Karpathy 的 autoresearch 搬进搜广推，我发现最难的不是自驱动，是交付对齐

GuoXun（百度）把 Karpathy 的 autoresearch 自驱动实验范式搬进搜广推，开源 AlgoPilot：离线棘轮跑得快，但 AUC 只是线上 CTR/GMV 的代理指标，作者补了「交付关」端到端仿真与「兑现率」台账，量化出同样是保留事件、交付价值能差 40 倍；自驱动 Agent + 交付对齐，正撞他的 Agent RL 与 infra 主线。注：推荐流标题称「用 o3」，正文未提 o3，实验用的是确定性 mock 引擎。

大纲

大纲（全文已通读；GuoXun，百度，专栏「通用Agent架构」，2026-11-14）

  • 起点：Karpathy 的 autoresearch
  • 630 行代码，单卡上让 Agent 自主跑 LLM 训练实验：改代码、训 5 分钟、看 val_bpb、保留或回滚，一夜约 100 次实验
  • 三件套：prepare.py（冻结实验装置）、train.py（唯一可改）、program.md（人写的组织代码）
  • 三条铁律：固定时间预算、单一指标 val_bpb、棘轮只进不退
  • 关键洞察：autoresearch 的「隐含幸运」
  • 离线指标 val_bpb 就是交付目标，离线与交付之间零距离
  • 搜广推没有这份幸运：离线 AUC 只是线上 CTR、GMV、留存、生态的代理指标
  • 中间隔着选择偏差、位置偏差、级联误差、代理指标过拟合
  • AlgoPilot：三道关体系（开源，github.com/guoxun/AlgoPilot）
  • 五文件：prepare.py、model.py（唯一可改）、judge.py、delivery.py、program.md
  • 关 1 离线棘轮：固定预算、单主指标 AUC、护栏（训练时长、logloss、数据指纹）一票否决
  • 关 2 交付关：400 会话 × 300 候选，模型自选 top-8 曝光，按真实因果 pCTR 产生点击；会话 CTR 不退化 + 曝光品类熵、冷启动点击率两护栏不破，才真正保留
  • 关 3 上线关：永远在人手里，是设计边界而非实现限制
  • 台账：每项实验记想法、补丁、指标、决策、原因；保留项加记「兑现率」＝离线增量 / 交付增量
  • 兑现率：同样是保留事件，价值差 40 倍
  • 特征交叉：AUC +0.021，CTR +0.064，兑现率 3.07
  • 激进学习率：兑现率 0.86
  • 多训一倍 epoch：兑现率 0.078
  • 护栏的胜利：双涨也会被拦
  • 某分支 AUC +0.0024、CTR +0.0103、兑现率 4.32，但曝光品类熵 0.68→0.16，被交付关拦下
  • 组织代码的自迭代（L5 前奏）
  • 三角色：Researcher、Engineer（LLM）、Reviewer（纯代码，护栏审查）
  • L4 并行：分叉点结算、最优合并；台账沉淀的教训蒸馏成 program.md 修改提案，三条结构红线 + 人工批准
  • 诚实的边界：合成 CTR 数据、mock 引擎非真智能、真实数据下离线-在线分歧会更大
