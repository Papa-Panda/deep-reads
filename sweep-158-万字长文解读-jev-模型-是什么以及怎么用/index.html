万字长文解读 Jev 模型：是什么以及怎么用

知乎专栏万字长文（谷粒，2026-09-21）。TypeSafe 的 Jev 把 LLM 的用法反过来：不生成文字，只对给定的 state 回答预先声明好的问题——是非（noul，返回为真概率）、选择（choice，带概率分布）、打分（score），一次前向并行出结果，延迟约 70–500 毫秒，定价为输入 0.042 美元/百万 token、输出免费。快的原因是砍掉自回归逐字解码、多个问题共享前缀与 KV，并用 RLCD 把输出概率校准到大体诚实。文章后半给出失效模式（没有思维链、顺序敏感、被无关选项干扰）、四种设计模式（推测式扇出、置信度门控、复合打分、分层分类）和生产路由：绝大多数判断走 Jev，不确定的才升级给大模型或人工。对他正对口：agent 系统里最高频的路由、校验、打分环节本质都是可枚举的判断题，Jev 是把「判断」从「生成」里拆出来单独定价的一层。注：知乎页面对自动抓取封闭，本条据浏览器通读全文后的结构与要点归纳，价格与延迟为文中转述的官方口径。

大纲

大纲（据知乎原文结构整理）

  • 问题设定：软件里大量调用 LLM 只为一个判断
  • 生成式模型是 System 2：慢、贵，输出还要再解析成程序能用的值
  • Jev 定位 System 1：一次前向直接给出类型化判断加置信度
  • Jev 是什么
  • TypeSafe AI 出品，创始人 Diogo Almeida（InstructGPT 作者之一）；名字取自经济学家 Jevons——判断变便宜，调用量反而暴涨
  • 三种原语：noul（是非题，返回命题为真的概率）、choice（选择题，返回每个选项的概率分布，最多 255 个）、score（在预设有序等级上打分）
  • 输入是 state（待判断的文本或 JSON）加一组预先声明的问题；一次读入、并行作答，不生成任何文字
  • 定价与延迟：输入 0.042 美元/百万 token、输出免费；端到端延迟约 70–500 毫秒
  • 为什么快：底层机制
  • 砍掉自回归逐字解码，输出空间被开发者给定的槽位锁死，一次前向算完所有选项的概率
  • 同一 state 上的多个问题共享前缀与 KV cache，读一遍材料答完所有题
  • RLCD（为校准决策做的强化学习）：目标是概率大体诚实——给出 90% 把握时统计上约对 90%
  • 实测（文中 20 行代码小实验加压测）
  • 输入从数百 token 涨到约 3 万 token，中位延迟只是温和上升
  • 约 100 个问题并发时延迟仍在 70–100 毫秒量级，并发再高才明显变慢
  • 失效模式
  • 没有思维链：需要多步推理的判断先天吃亏
  • 顺序敏感：选项排列顺序会影响结果
  • 会被无关选项干扰；正确选项不在集合里时，概率仍被迫在错误选项间分完
  • 用开源小模型自搭同类系统时，输出分数未经校准，不能直接当概率用
  • 四种设计模式
  • 推测式扇出：对同一 state 并行发多路判断，再汇总决策
  • 置信度门控：高置信自动执行，中置信交大模型复核，低置信转人工
  • 复合打分：把一个含糊问题拆成多个单因子判断，再加权成总分
  • 分层分类：先粗分大类，再逐层细化收窄
  • 生产架构
  • 路由分工：大部分决策走 Jev，不确定的升级给更大的生成模型或人工审核
  • 文中以每天 10 万次请求为例，估算这套路由相对全量调用大模型的成本与延迟优势
  • 什么时候用、什么时候不用
  • 答案空间可枚举、调用量大、延迟敏感：Jev 这类决策模型
  • 类别固定且有大量标注数据：传统分类器（如 BERT 系）更便宜可控
  • 需要推理、解释或生成内容：仍用生成式 LLM，Jev 是补位不是替代
