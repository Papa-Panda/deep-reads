推理 INFRA 方法论（5）：MoE 推理：Batch、DeepEP、DeepGEMM 与负载均衡

推理 INFRA 方法论系列第 5 章，以 Batch 为主线讲 MoE 推理的三块硬骨头：专家越切越碎如何让 GEMM 变小变碎，DeepEP、DeepGEMM、EPLB 各自解决通信、填充与负载偏斜，并用 Qwen3.5-397B-A17B-FP8 的 8 卡实测对照理论预算。值得他看的是它把 MoE 推理的系统问题从“调参”还原为 Roofline、通信建模与 tile 填充的定量分析，且逐项给出优化的收益天花板，正对推理 infra 这一优先方向。

大纲

大纲

  • 立意：以 Batch 为主线
  • 专家覆盖、通信量、tile 填充、负载偏斜四条线
  • 理论预算 + 端到端实测对照
  • 形状与稀疏度演变
  • dense FFN（Llama-70B）→ DeepSeek-V3（E=256，k=8+1，稀疏 5.5%）→ Qwen3.5（E=512，4.3%）→ DS-V4-Pro（E=384，3.1%，原生 FP4）
  • 趋势：专家数↑64 倍、单个专家缩小 14 倍、稀疏度 25%→3%
  • 后果：专家 GEMM 由大而密变小而碎，MoE 的系统问题皆源于此
  • Batch 的 Roofline 分析
  • B↑：算术强度与吞吐↑、每专家行数 M_e↑、all-to-all 字节 ∝B、KV 池需求 ∝B
  • 运行点 = min(B*， B_SLA， B_max_mem)
  • 专家命中率 C(B)=1−(1−k/E)^B，权重流量随之变化
  • 三个修复：DeepEP / DeepGEMM / EPLB 各自对应通信、填充、偏斜
  • 端到端实测（Qwen3.5-397B-A17B-FP8，8 卡 TP8）
  • Batch 1→256：解码 177→5626 tok/s，TPOT 5.6→45.5 ms
  • 30ms TPOT 上限下 B=64 通过、B=128 不通过
  • MTP-3：自然语言接受长度 3.07–3.11
  • DeepEP：通信量不减，但移出关键路径
  • dispatch/combine 字节量公式与去重目标卡数 C
  • 三招：FP8 + 去重降字节、IBGDA 降 α、hook + TBO 把加法变取 max
  • 实测：低延迟 dispatch 32–50μs，hook 仅遮住 20–27% 通信
  • 收益天花板 = 通信占步长时间的份额（40–60%）
  • DeepGEMM：静态 shape 装动态负载
  • 冲突：CUDA Graph 要求静态 shape vs 每步 masked_m[e] 都在变
  • 关键：内存静态、计算动态；masked_m 是地址固定、内容可变的 GPU 张量
  • FP8 深 K 两级累加：误差 25%→0.17%
  • BM 临界值也是 Roofline 点；实测 BM 16 比 128 快 3.8 倍
  • DeepEP 的 recv_count 就是 DeepGEMM 的 masked_m，零拷贝直通
  • EPLB：负载均衡的收益与天花板
  • 偏斜两源：统计涨落（修不了，只能加大 batch）vs 路由热点（可复制 + LPT 打包）
  • 收益换算：MoE 层加速 → 端到端加速，取决于可均衡份额 f
  • 算例：EP32 仅 1.10×；EP72 解码 2.54×；2 倍级收益需 EP64+、e≤4、重尾路由
