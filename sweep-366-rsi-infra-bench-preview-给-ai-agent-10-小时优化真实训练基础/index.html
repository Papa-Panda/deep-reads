RSI-Infra Bench Preview：给 AI Agent 10 小时优化真实训练基础设施

ydove1031（2026-11-19）介绍北大 RSI-Infra Bench Preview：给 Agent 每个任务 10 小时，在 1–4 张 Hopper 卡上优化 8 个真实训练负载（预训练/SFT/RL/OPD），按验证加速比 ln(S)/ln(S_best) 打分；Claude Opus 5.5 以 40.00 居首，3DGS 任务达 5.82×；轨迹分析显示手写 kernel 数量与得分相关性 +0.72，轮数多反而无益。正撞 Agent infra 与训练优化主线。

大纲

大纲（全文已通读；ydove1031，2026-11-19；16 赞 / 21 收藏）

  • 立论：测 Agent 优化真实训练 infra 的能力与速度
  • 每个模型每任务 10 小时墙钟预算，不是只看最终分数
  • 详情见博客与 GitHub（DAGroup-PKU/ResearchBoost-Agent）
  • 评测设计三原则
  • 固定 10 小时预算；真实训练负载；全程可验证反馈
  • 8 个任务：LLM 与多模态理解/生成，覆盖预训练、SFT、RL、OPD，含 GDN、YOCO 架构
  • 1–4 张 Hopper 卡；每模型每任务只跑一次
  • 计分方法
  • 终评按 参考 → Agent 实现 → 参考 顺序计时
  • 单任务分 = ln(S) / ln(S_best)，S 为验证加速比
  • 榜单（9 模型 × 8 任务）
  • Opus 5.5（Claude Code）40.00 居首；Sonnet 5.5 36.64；GPT-6.2 Astra 28.50
  • 最高单项：3DGS 任务 Opus 达 5.82x
  • 4 个模型构成得分–API 成本 Pareto 前沿（成本不含 GPU）
  • 轨迹分析（任务内 Spearman 相关）
  • 手写 kernel 数量 +0.72（覆盖 6 个任务）；优化类别覆盖 +0.60
  • 尝试→落地转化率 +0.50；工作日志轮数 −0.41（多轮不等于更好）
  • 三个案例（均为完整实现并终评）
  • 3DGS × Opus：5.82x，visibility-aware Lazy Adam + 融合训练流水线
  • R3 × Opus：2.41x，结构改动 + 手写 kernel，bitwise（N0）正确性要求
  • Slime GRPO × Sonnet：2.40x，跨 GPU 重分 GDN 计算，前向输出 bitwise 一致
  • 诊断报告：31 个主要优化机会，区分“未尝试”与“尝试未落地”
  • 日志中没有某想法 ≠ 模型缺乏相关知识
  • 展望：Preview 版，征求 infra 专家合作（新负载、正确性检查、计时方法、轨迹深挖）
