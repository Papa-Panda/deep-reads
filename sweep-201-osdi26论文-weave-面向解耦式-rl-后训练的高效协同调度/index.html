OSDI26论文--Weave:面向解耦式 RL 后训练的高效协同调度

知乎推荐流条目（想飞的石头，2026-08-30编辑，23赞、约29收藏）。OSDI'26 论文精讲：解耦式 RL 后训练把 rollout 放便宜的 H20 池、训练放 H800 池，但 on-policy 严格同步造成依赖气泡、两池轮流闲置，朴素解耦的成本反而高于共置 veRL。WEAVE（港科大+阿里，基于 ROLL 实现）用协同执行组加两级调度把一个任务的气泡用另一个任务的活跃阶段填满——组间按最坏情况保守放置守 SLO，组内用可证明最优的轮转加长尾迁移，状态驻留主机内存实现热启动。在 328×H20 + 328×H800 测试床上成本效率达 1.84×（对朴素解耦）与 1.38×（对共置 veRL），100% SLO 达成。对他正对口：这是 RL 后训练集群调度的一线系统论文，讲透解耦架构的成本账。注：已通读知乎原文，并核对了论文原文。

大纲

大纲（据原文通读整理）

  • 问题：解耦的代价是气泡
  • rollout 访存受限放便宜 H20 池、训练算力受限放 H800 池，硬件匹配本应省钱
  • 但 on-policy 严格同步让两池轮流闲置；朴素解耦 Solo-D 约 0.94k 美元/小时，反而贵于共置 veRL 的约 0.71k 美元/小时
  • AReaL、StreamRL、AsyncFlow 靠异步 off-policy 消气泡，代价是样本陈旧
  • 核心洞察：气泡互填
  • 一个任务的依赖气泡正好可被另一个任务的活跃阶段填满
  • 多个任务组成协同执行组，在两个资源池上紧密编织 rollout 与训练阶段
  • 两级调度
  • 组间：保守规划——按每条响应都跑满最大长度的最坏情况做放置，守 SLO（相对单独执行的减速容忍）与内存驻留约束
  • 组内：可证明最优的轮转调度；响应约 80% 完成时做长尾迁移，把拖尾请求挪到少数 GPU，释放大池给下一任务
  • 系统机制
  • 阶段中心控制模型把每个 RL 阶段暴露为一等可调度实体
  • 热启动：模型与优化器状态驻留在主机 DRAM，切换延迟较冷启动（最高 135 秒）大幅下降
  • 拓扑感知同步：权重只过一次慢速跨集群链路，再在集群内走 NVLink/InfiniBand 广播，同步速度数倍于 veRL
  • 评估（328×H20 + 328×H800 生产级测试床，基于 ROLL）
  • 成本效率 1.84× 对朴素解耦、1.38× 对共置 veRL，100% SLO 达成
  • 等成本下训练吞吐 1.82–1.99×；两周生产 trace 回放中气泡下降 24.4%（rollout 池）与 43.1%（训练池）
  • 调度质量距暴力搜索最优约 6% 以内；对负载漂移与单任务故障鲁棒
  • 适用边界
  • 适用于 PPO、GRPO、DAPO 等标准 on-policy 与仍保留气泡的单步 off-policy
  • 全异步 RL（AReaL、AsyncFlow）没有气泡可填，不在适用范围
