RL修炼第五弹：训推一致性

知乎推荐流专栏，RL 训练系列第五弹，讲训推一致性：RL 里 rollout 策略与 PPO 近端策略理论上应是同一权重下的同一分布，逐 token 概率应当对齐，缺口称为训推失配（TIM）——它不同于多 mini-batch 或异步更新带来的策略陈旧。值得他看的是这条把“同权重却算出不同概率”拆解到底层的分析：即使权重相同，vLLM/SGLang 这类推理引擎与 Megatron/FSDP 这类训练引擎也可能给出不同结果，大到一定程度会让名义上的 on-policy 训练实际变成无修正的 off-policy，危及训练稳定。注：本条大纲已据浏览器通读报告修正，此前“未读到原文细节”的标注作废。

大纲

大纲（据浏览器通读整理，概括转述）

  • 文章结构：先定义度量 → 为什么必须一致 → 成因分类 → 影响量级与崩溃情形 → 三层补救 → 总结
  • 概念：训推一致性
  • rollout 策略与 PPO 近端策略理论上是同一权重下的同一分布，逐 token 概率应相等
  • 缺口称为训推失配（TIM），区别于策略陈旧（多 mini-batch 或异步更新所致）
  • 为什么重要
  • PPO 的比率分母依赖近端策略概率，分母错了，更新方向就错
  • 失配大时，名义 on-policy 实际变成无修正 off-policy，训练可能失稳甚至崩溃
  • 成因：同权重、不同引擎也会算出不同概率
  • 浮点归约顺序：batch 构成、张量并行、split-KV 等
  • 精度与量化：BF16、量化 rollout
  • MoE 路由翻转；采样语义差异（top-k/top-p 重归一化）
  • token 管线变化：重切分、后处理；权重版本与同步问题
  • 量级参考
  • 文中给出的典型 K3 KL：稠密模型约 1e-5–1e-3，MoE 模型约 1e-3–1e-1
  • 三层补救
  • 根除：批不变/确定性算子追求比特级一致（如 SGLang 确定性推理、TBIK、slime 真 on-policy 模式、DeepSeek-V4 的算子做法）
  • 对齐敏感环节：FP16 或 FP32 LM head/router、R3 重放 MoE 路由、重放采样候选集、量化 rollout 校正、token-in/token-out、权重版本标记
  • 算法修正残差：TIS、MIS/veto、IcePop、词表剪枝
  • 实用建议
  • 始终监控训推 KL；MoE 默认开 R3；量化 rollout 务必校正
  • 不要只依赖 token 级 TIS，通常与序列级 MIS 或 veto 搭配
