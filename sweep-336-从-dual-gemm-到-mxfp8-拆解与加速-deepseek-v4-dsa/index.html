从 Dual GEMM 到 MXFP8：拆解与加速 DeepSeek V4 DSA

Dingirsu 拆解 DeepSeek V4 稀疏注意力 DSA 在 Blackwell 上的 BF16 kernel（Dual GEMM 如何把大 GEMM 拆成小块以喂饱 tensor core），再用 MXFP8 做到相对 FlashMLA 约 2 倍加速（prefill 2.03 倍、decode 2.05 至 2.22 倍），代价是 AIME 2025 掉 10 个点、GPQA 与 GSM8K 掉约 2 至 3.5 个点，作者把精度修复留给未来的 attention QAT。值得他看的是 kernel 级的逐周期 profiling 与 rank-1 量化 scale 分解，正撞稀疏注意力与量化主线。

大纲

大纲（全文已通读，Dingirsu，2026-11-07；开源代码 MXDSA）

  • DSA 是什么：DeepSeek V4 的每 token 稀疏注意力
  • 计算流与标准 attention 相同：QK GEMM、online softmax、rescale O、SV GEMM
  • 关键在 GEMM 如何组织；V4 Flash：64 头、head dim 512
  • BF16 DSA kernel 拆解：Dual GEMM
  • QK GEMM 用 tcgen05 的 mma ws 指令；M=64、N=64 时非 ws 模式只写 TMEM 一半列
  • 把逻辑 64×64×512 GEMM 拆成多个 64×128×128，Q/K 沿特征维切 8 个 64 宽子块，奇偶分开累加
  • 128 头用 2sm GEMM：两 SM 分担 K/V，SV 需重排 TiledMMA 让 KV 复用同一 SMEM
  • Profiling：为什么值得上 MXFP8
  • Prefill：QK/SV GEMM 约 512 周期，softmax 全程约 700 周期（实测约 800），GEMM 尚能盖住
  • MXFP8 后 GEMM 周期减半至 256，softmax 成瓶颈，须缩短 softmax
  • Decode：GEMM 与 softmax 串行，KV 占满放不下第三份，MXFP8 缩 KV 腾出重叠空间
  • MXFP8 算法设计
  • MXFP8 要求 M 不小于 128，64 头不满足：相邻 Q token 合并，Q 由 seqlen 行 64 头变一半行数 128 头
  • 两 token 共享 topk：取 Q 均值算 topk（LongBench 上精度损失不大，相邻 token topk 高度共享）
  • rank-1 scale 分解：scale 矩阵等于 token 因子与特征组因子外积，g0 固定为 1，解决 SV GEMM 的量化方向问题
  • MXFP8 DSA kernel 结构改动
  • 取消 permute、Q 直接放 SMEM 缩短 prologue；QK 与 SV GEMM 由不同 CTA 发出
  • 实验：B302 上相对 FlashMLA 约 2 倍加速
  • Prefill 峰值 2.03 倍（topk 3968：34.05ms 降到 16.82ms）；decode batch 64 峰值 2.05 倍，batch 128 峰值 2.22 倍
  • 精度代价：AIME 2025 96.67% 降到 86.67%（仅 30 题），GPQA 降 3.54 点，GSM8K 降 2.27 点
  • 结论：注意力量化天生敏感，修复留给未来的 attention QAT；V4.1 的 NVFP4 压缩 KV 无法直接与 MXFP8 做 MMA
