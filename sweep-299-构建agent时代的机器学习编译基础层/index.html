构建Agent时代的机器学习编译基础层

陈天奇（TVM 作者）在 tvm 专栏的编辑推荐长文：Agent 时代已能用 token 直接“蹬出”高性能算子与框架代码，编译器并未消失，而是要从单体黑盒变成模块化基础层——轻量稳定的核心 IR、“老实”的底层模块、插件式动态扩展、Python/Rust/C++ 混编，并推出 TVM-TIRx 作为这一基础层。值得他看的是它直接回答了 Agent infra 时代编译器以何种形态存在的问题，正对 ML 编译底层这一优先方向，且出自一线作者。注：推荐流卡片标题与正文标题不一致，已按正文页标题为准。

大纲

大纲

  • 引子：Agent 元年，编译器的旧问题与新问题
  • 传统 ML 编译：图优化、分块、SIMT 跨硬件
  • Agent 已能直接生成算子、核函数乃至框架代码（KernelAgent、CUDA Agent、CAKE、TIRx Harness 等）
  • 追问：编译器会不会被自动化掉？（HazyResearch “Retire the Abstractions”之问）
  • 还需要编译器吗：分析与验证，而非“编译”
  • 不能无条件信任 Agent 输出，需要验证；也不想让 Agent 在低级错误上浪费时间
  • 两大刚需：程序分析（访存、线程同步、数值、快速反馈）与程序验证（形式化证明、人机协同检查）
  • 结论：仍需编译基础设施 + 轻量稳定的核心 IR，可扩展新算子
  • 面向 Agent 的编译器基础层如何设计
  • 语言不必统一：Python 快速原型，Rust/C++ 要效率与强类型反馈；TVM-FFI 作 ABI，模块级混编
  • 让 Agent 迭代更快：整编译器重编译太慢；一切皆插件，动态离树扩展，pip 安装基础层后只迭代所需部分
  • 代码维护分层：基础层守住轻量、稳定、“老实”的部分；上层与 harness 交给 Agent 快速迭代
  • 展望：结构化、可扩展的组合边界
  • 过紧的抽象会封顶 Agent 的能力上限
  • TVM-TIRx 是朝这个方向的基础设施
