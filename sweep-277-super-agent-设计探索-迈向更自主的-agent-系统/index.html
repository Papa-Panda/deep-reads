Super-agent 设计探索：迈向更自主的 Agent 系统

DeepSeek 关于更自主 Agent 系统的设计探索：当单任务不再需要逐步督导，瓶颈从模型能力转向人的注意力与会话管理；由此提出持续在线、不绑定单次会话的 Super-agent，可跨渠道带上下文、多任务并行、感知环境并主动行动。值得他看的是它把 Agent 设计还原成系统工程问题：常驻协调层与并行执行层如何分工、事件如何驱动、计算与状态如何分离，以及一层独立的监控回路如何兜底。注：据浏览器通读该文整理，概括转述。

大纲

大纲（据浏览器通读该文整理，概括转述）

  • 核心论点
  • 瓶颈转移：从模型能力转向人的注意力与会话管理
  • Super-agent：持续在线、不绑定单次手动会话、跨渠道带上下文、多任务并行、主动感知环境
  • 定性：不是新理论，而是把成熟的系统工程思路用到 Agent 设计上
  • 一、起点问题：会话制的四处掣肘
  • 用户要在多个会话间切换，单会话会被长操作阻塞
  • 多任务上下文容易缠绕，本地 Agent 随设备离线而中断
  • 目标形态：持续、高效、主动、可持久
  • 二、双层架构：常驻协调与并行执行分开
  • Router 层常驻：跨渠道连续性、全局协调与记忆
  • Worker 会话隔离执行单任务，通过 Router 回报而不直接对用户回复
  • 连续性与吞吐量由此解耦；重负载下 Router 批量处理是扩缩机制
  • 三、事件驱动：不等用户打字，响应环境事件
  • 两级过滤：快而确定的规则先行，慢而语义的模型判断在后
  • 按订阅路由：同一线索的后续事件直达相关 Worker
  • 上下文组织：行内与溢出分流、凭 ID 与引用图链式回想
  • 推测行动：用户确认前先准备草稿或修复方案
  • 四、人机交互与部署分离
  • 全双工异步：长工具调用不阻塞新输入；按渠道调整输出密度
  • 计算无状态上云、会话状态另存、重型执行环境留在原地经轻量守护进程接入
  • 由此可换设备续跑、断网后恢复
  • 五、Watchdog 与实验、开放问题
  • 独立外部控制回路：定期消息驱动，监控 infra 故障与模型级失误（循环、目标漂移）
  • 初步实验：完成更快更稳，但缓存 token 成本更高，请求延迟随触发率与批量微升
  • 未解：单 Router 之上的扩缩与长期记忆、隐藏会话下的人为干预、跨 Agent 的上下文边界、安全与隐私
