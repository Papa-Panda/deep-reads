【10-08】agentic 方式合成 / 清洗训练数据 (SFT・mid-training・RL)

知乎推荐流专栏（登录浏览器通读核验：作者 Lei Tian，2026-10-07 发布，49 赞同、77 收藏）。速读 7 篇 agentic 训练数据论文：SPADE 用提示遗憾差驱动环境自生成、Agent Error Dataset 把 5 万条失败诊断变成主资产、WorkForge 用真实工作区做可验证环境、ToolLoop 与 Data Turnstile 用闭环回炉代替生成再过滤、ToolRACER 补失败场景、Spotify 跑通合成数据加自改进的线上闭环。值得他看的是这条统一判断：Agent 后训练的数据管线本身已变成可验证、可回炉的闭环系统，失败轨迹与环境真实性是两个最实在的杠杆。

大纲（据登录浏览器通读整理）

  • 条目信息
  • 知乎专栏「Agentic视角下的数据链路」速读，作者 Lei Tian（北京邮电大学电子科学与技术博士），2026-10-07 发布，49 赞同、77 收藏
  • 覆盖 7 篇论文，每篇分 Highlight 与实验 finding 两小节，文末有总结
  • 趋势总括：单轮生成再过滤已经过时
  • 主流变成多阶段生成-验证-精修或多角色闭环，因为生成成本高、只过滤不划算
  • RL 侧出现真正可用的自博弈环境自生成方法
  • 产业界同期上线合成数据加自改进闭环的案例
  • 失败样本首次被规模化开采成主数据资产
  • SPADE：自博弈自适应合成可执行环境
  • 同一 LLM 分饰环境设计师与推理 Agent：设计师生成带 reset/step 接口的可执行环境代码
  • 设计师奖励不是通过率，而是 Agent 有提示与无提示的奖励差（遗憾 gap），把环境钉在能力边界上
  • 设计师须以预训练语料文档为锚，否则会自嗨式出题；另有环境记忆做增量演化
  • 效果：Qwen3-30B-A3B 八项 held-out 均值 50.2→58.3，ACEBench-Agent 62.0→75.9，BFCL v4 多轮 49.0→54.7；收益随规模增大
  • Agent Error Dataset：五万条错误诊断对
  • 首次把失败样本当主资产：错误-诊断配对用于失败分析与错误感知后训练
  • 诊断 SFT 后 Qwen3-8B 与教师标注的精确步骤一致率 47.19%→63.56%，高于文中列出的前沿模型参考值
  • 定位研究：带诊断的续写 31.3%，高于通用反思 26.0% 与纯重跑 18.6%
  • 警示：只做动作级事后修复训练在不同环境符号相反（WebShop-lite +6.67pp，TextQuest -8.33pp），不是免费午餐
  • WorkForge：长程工作 Agent 的可验证环境规模化
  • 瓶颈不在模型而在环境：真实工作区与真实工作流，LLM 合成的工作区与真实差距达数量级
  • 直接从真实资源建工作区，从真实专家工作流派生任务、解法与程序加语义双验证器，产出 1.67 万个可验证环境、40 个专业领域、60 种文件类型
  • 真实工作区文件数 5.4 倍、平均大小约 13 倍；效果：Qwen3.5-35B-A3B GDPval 45.5→73.6，27B 稠密版 GDPval 82.4，超过约 15 倍参数的 397B 基座
  • ToolLoop：工具调用数据的闭环合成
  • 针对生成再过滤三缺陷：单次采样难挑最优工具、静态过滤救不回错误、全程无反馈信号
  • 5281 个 API 聚成 26 组，逆向生成查询、正向生成调用，每阶段配验证器，出错带原因回炉而非整条丢弃
  • 效果：11K 样本的 ToolLoop-4B 在 BFCL 上 82.14%→86.40%，超过 60K 样本的 APIGen 与 55K 样本的 ToolMind
  • 最反直觉消融：去掉反馈的版本跌到 79.97%，低于未训练基座——无约束原始合成数据会污染模型
  • Data Turnstile：小模型工具调用数据的角色 DAG
  • 同一痛点在小模型侧：直接用 xLAM/Glaive 等开放数据 SFT 会把 0.6B 的 BFCL 打到 55.1%，低于基座
  • 把多轮工具交互拆成角色 DAG（查询、推理、调用、执行结果、回复各为节点），各角色独立生成、独立验证、带错反馈重试，避免单次合成的级联错误
  • 效果：0.6B BFCL 75.9%，τ²-bench 电信域 pass^1 从 3.5 升至 23.0；但多轮任务关掉 CoT 会塌 11–22pp，CoT 在多轮里不可省
  • ToolRACER：失败场景三分法
  • 现有评测偏重合作成功轨迹，忽略不合作用户、含糊请求、不可满足意图等真实失败场景
  • 三模拟器生成 Happy、Unhappy、Impossible 三类轨迹，失败轨迹回炉重生成，救回 65.4% 的初始失败轨迹，终得 5.6K 多轮对话、约 66% 为易失败场景
  • 效果与干扰：τ²-bench 提升且与 APIGen-MT 可叠加；但只训 Impossible 虽把 BFCL 无关检测推到 95.50%，却拖累 τ²-bench 零售分——不同失败类型会互相干扰，不能简单拼接
  • Spotify：产业界端到端案例
  • 多轮对话推荐 Agent 冷启动：无真实用户交互，先用合成对话做评测替身，再用自改进闭环分流可靠性失败与能力缺口
  • 合成对话四维人工质检均 ≥90%，自改进后 pass@1 相对已手工优化过的提示再 +8%
  • 两周约 1500 万用户 A/B：收听时长 +14%，WAU +5%，跳过率 -5%；但 7 轮对话相对 2 轮 pass@1 掉 11.9pp，长对话仍难
  • 对他的启示
  • 做 Agent 后训练时，数据管线本身要当成可验证、可回炉的闭环系统来设计，而不是先大量生成再筛
  • 失败轨迹、真实工作区、环境自适应三条线，分别对应数据资产、环境真实性、训练课程三个杠杆
