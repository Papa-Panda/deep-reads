论文解读：AI 就是编译器——让 LLM 直接写 PTX，绕开整个编译器后端

讲论文 "AI as a Compiler"：LLM Agent（TAIC）直接把 Triton 内核翻译成 PTX，绕开整个编译器后端，在 L40S/H100/B200 上相对自调优 Triton 做到 0.83x–3.34x，FlashAttention 1.37x、BitDelta 3.34x；作者还用无 GPU 的 SASS 级复现验证了 wgmma n=64→256 等关键机制，并指出验证才是真正的瓶颈。值得他看的是它把 Agent infra、编译器后端与 GPU 指令级优化连成一条线，且批判性评估很克制——收益只集中在能重组计算与数据搬运的算子上。

大纲

大纲

  • 核心主张：AI lowering
  • 删掉整个编译器后端，让大模型把 Triton 内核直接译成 PTX
  • 性能不降，部分算子反超 Triton 自身编译器
  • 新范式设想：新芯片靠「生成 + 验证」快速带起来
  • 为什么选 Triton 到 PTX
  • PyTorch 会混入图级优化，CUDA 暴露过多底层选择
  • Triton 固定计算与接口，指令选择/线程映射/数据搬运/同步/调度全留给后端
  • Triton→PTX 的距离，正好就是编译器后端的价值
  • 系统：TAIC 生成，TCENV 判定
  • TAIC：LLM + 三项通用技能（读 NCU 指标、查 PTX ISA 文档、高层 GPU 优化原则）
  • TCENV：抽象掉与 lowering 无关的配置，组装/启动/检查/画像
  • 正确性定义：固定契约（c, I, h），数值等价 ≈ε 而非逐位相等
  • 防奖励作弊：参考实现严格按官方教程最佳实践，并先在目标 GPU 上自调优
  • 迭代循环：诊断瓶颈 → 规划 → 子 Agent 并行出补丁 → 同契约评估 → 达标者成下一轮种子
  • 实验结果（GPT-6 Astra，PTX ISA 8.7，Triton 3.6.0，L40S/H100/B200）
  • 12 个常见核：0.83x–3.34x，收益极不均匀
  • 元素级/RMSNorm/RoPE 近 1.0x；卷积 2D 最稳定 1.17–2.23x
  • GEMM FP16：H100 仅 0.83x（输）；GEMM FP8：H100 1.61x
  • 10 个已发表核：BitDelta 3.34x、FlashAttention 1.37x、FlashSinkhorn 1.55x
  • 成本：每次搜索约 $5–15 API 费，编译时间换成账单
  • 附录 A：最值钱的三处优化
  • 归约：用 Tensor Core 做行求和，替代 shuffle + 共享内存归约
  • 卷积：复用重叠 3×3 窗口输入，消除冗余 gather
  • H100 FP8 GEMM：wgmma n=64→256，显式双缓冲 + 转置 stmatrix epilogue
  • 作者的 SASS 级复现（无 GPU，只用编译前端 + 汇编器）
  • 证实 Triton 的 wgmma n 等于分块 N，不探索指令 n 上限
  • 手写 PTX：m64n256k32 通过汇编并反汇编为真实 SASS，m64n512k32 失败
  • Tensor Core 归约的精度代价：FP8 下最大相对误差约 3.3×10⁻³
  • Blackwell TMEM 通路：tcgen05.ld/st 等指令真实存在，tcgen05.mma 六种写法全失败
  • 批判性评估
  • 打败的是 Triton，不是 CUDA/CUTLASS
  • 验证是真正瓶颈：可证明子集下 GEMM 1.03x→0.24x，Volta 可信基从 42k 增至 60k 行代码仍不完备
  • 精度代价未被当作权衡讨论；泛化证据有限；"AI 编译器"严格说并未取代 IR
