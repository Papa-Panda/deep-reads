面向 Agent 时代的 「AI Infra」 到底该怎么做？

知乎推荐流问答，作者卢冕为范式智能 AI Infra 负责人（HKUST 博士，团队在做大模型推理基础设施开源项目 ModelSphere）。他谈 Agent 时代底层 Infra 必须变的三个方向：负载越来越动态，静态配额与固定规则不再够用；Agent 长上下文、多轮调用使推理服务稳定性更关键，中断后应能续跑而非重算；模型与硬件迭代太快，性能调优应交给持续自动化的 Tuning Agent 闭环。值得他看的是这条来自一线推理 Infra 负责人的实践判断：长期稳定高效的运行比峰值跑分更重要。

大纲

大纲（据浏览器通读整理，概括转述）

  • 引子
  • Agent 产品（编程、操作电脑、自主任务）普及后，底层 AI Infra 要跟着变
  • 作者背景：范式智能 AI Infra 负责人，团队在做 ModelSphere 推理基础设施
  • 一、负载越来越动态
  • Agent 请求模式、上下文长度、token 量、时延需求差异大，同一 Agent 的实时负载也在变
  • 固定规则的资源管理与固定 RPM/TPM 限流不再贴合
  • 方向：按 TTFT、生成速度等实时服务质量信号调并发，按真实负载与服务质量动态扩缩 GPU
  • 二、推理服务稳定性更关键
  • Agent 长上下文、多轮调用、长生成，中途失败会浪费昂贵重算并破坏体验
  • 方向：不追求绝对不出错的引擎，而是中断后迁移到健康实例续跑
  • 三、性能调优要自动化、持续化
  • 新模型、新 GPU、新推理框架来得太快，针对某一负载调好的配置未必一直最优
  • 方向：Tuning Agent 闭环——分析真实业务负载、生成测试负载、搜索配置组合、评估吞吐/时延/资源占用、验证后上线
  • 总结
  • 最重要的三个方向：动态资源管理、更可靠的推理服务、少人工干预的持续性能优化
  • 生产环境里长期稳定高效运行比峰值性能更重要
