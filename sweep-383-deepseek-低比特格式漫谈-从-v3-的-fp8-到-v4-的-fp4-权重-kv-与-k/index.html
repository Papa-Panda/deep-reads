DeepSeek 低比特格式漫谈：从 V3 的 FP8 到 V4 的 FP4，权重、KV 与 kernel

大纲

1. 两条贯穿全文的式子：有效位宽与 decode 字节账

  • 有效位宽 b_eff = 元素位宽 + scale 位宽 / 分组大小：分组越细误差越小，scale 开销越大
  • 8bit 时 scale 格式无所谓，4bit 时 MXFP4 开销 5.9%、NVFP4 达 11.1%，scale 格式成了关键选择
  • decode 步时间 T ≈ (权重字节 + B·L·KV字节) / 带宽：每步读一次权重和全 batch 的 KV，瓶颈是字节数不是算力
  • V3 算例：B=128 时交叉长度 L* 约 73K（BF16 KV）→ 128K（FP8 KV）；上下文长到 1M 后，焦点必然从权重转向 KV

2. V3：671B 规模 FP8 训练的格式

  • 全张量只用 E4M3，细粒度 scale 补动态范围；相对 BF16 基线损失误差 <0.25%
  • 激活按 1×128、权重按 128×128 分组，在线算 amax；反向 Wgrad 需把激活重标为 128×1
  • FP8 只进三个 GEMM（前向、Dgrad、Wgrad），其余模块与优化器态保持高精度；反向缓存激活与 MoE dispatch 也走 FP8

3. V3 的 kernel 与 V3.1：把 scale 留在 tensor core 外面，再对齐硬件

  • Hopper FP8 WGMMA 累加仅约 14bit 有效精度，K=4096 时相对误差近 2%，不可接受
  • 每 128 个 K 元把部分和提到 CUDA core 乘 scale、进 FP32 累加器；128 恰好等于 scale 分组长度，乘 scale 与提精度一举两得
  • 双 warpgroup ping-pong 让 tensor core 不空闲；这套 kernel 后来开源为 DeepGEMM
  • V3.1 把 scale 换成 UE8M0（2 的幂）：省空间、无新舍入误差、tensor core 可在 MMA 内乘 scale；代价是最多丢一个 binade，E4M3 有约 18 个 binade 可忽略，E2M1 只有约 3.6 个就很要命
  • Blackwell 内置 block-scaled MMA，Hopper 的“回 CUDA core”不再必要；但 OCP MX 规范与 Blackwell 都早于 V3 报告，是独立殊途同归

4. KV：从 MLA 到 FP8 cache 再到稀疏注意力

  • MLA 每 token 每层 1152B（BF16），相对 MHA 约 70 倍压缩；V3.2 的 FP8 KV（FlashMLA）降到 656B
  • RoPE 64 维暂不量化：它承载位置信息，误差会直接扭曲 attention 分布；V4.1-Flash 才把它也量化
  • DSA：轻量 indexer 先给全部历史 token 打分，只对 top-2048 做精确 BF16 注意力；选 token（低精度 O(L)）与算注意力（高精度 O(k)）分开
  • 稀疏化后 KV 位宽不再决定“每步读多少”，而决定 HBM 能装多少序列、indexer 的 O(L) 读多大——V4 把 indexer QK 量化到 FP4 正为此

5. V4 与 V4.1-Flash：FP4 分治——权重与 KV 的不同答案

  • 权重走 MXFP4 + QAT：FP32 master → MXFP4 → 无损反量化回 FP8，复用整套 FP8 GEMM；收益几乎全在 HBM 容量与读带宽
  • KV 走 E4M3 scale + 更细分组（每 16 通道）：KV 是推理时在线生成的激活，训练无法补偿误差，格式本身必须更精细
  • V4.1-Flash 再加跨层复用（仅 4/40 层存主 KV）与序列压缩，1M 上下文 KV 降到 V3.2 的约 1/4；降位宽只是其中一部分

6. 收尾：格式跟着硬件走

  • 训练侧思路是少发明新 kernel：FP8 GEMM 写好，FP4 只是前面多一步；推理侧每代都有新 KV 格式与 attention kernel，因为推理对字节数更敏感
  • 8bit 时设计空间小，E4M3 + 足够细的分组就够；4bit 时 scale 格式、分组、QAT、哪些维不量化都显著影响精度
  • 统一原则：能训练补偿误差的地方格式可以粗，只能在线量化的地方格式必须细
