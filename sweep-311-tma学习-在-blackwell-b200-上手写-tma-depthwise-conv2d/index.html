TMA学习：在 Blackwell B200 上手写 TMA Depthwise Conv2D

在 B200 上手写 TMA Depthwise Conv2D 的实战记录：从 naive 实现的性能下限，到共享内存复用、TMA 异步搬运、producer/consumer 流水线与 n_stage 取舍，实测 n_stage=2 追平 cuDNN、n_stage=4 反而更慢。值得他看的是它把 TMA 从概念讲到可跑的代码与实测曲线，且对 n_stage=4 变慢的第二点原因明确标为未验证的推测，正对 CUDA/GPU 底层主线。

大纲

大纲

  • 第 0 章：TMA 是什么
  • Hopper 引入、Blackwell 沿用的专用硬件，负责全局内存与共享内存之间的数据搬运
  • 三大好处：硬件处理边界（描述符预声明 shape/stride/越界策略，自动补零）
  • 单线程下发：一条 cp.async.bulk.tensor 搬整个 tile，其余线程留给计算
  • 异步 + mbarrier 通知，可搭多级 ring buffer 流水线
  • 第 1 章：Depthwise Conv 基础
  • 通道完全解耦：每通道独立用自己的 R×S 核卷积，无跨通道归约
  • PyTorch 用 F.conv2d(groups=C) 作等价实现，作为全部 kernel 的正确性基线
  • 第 2 章：v0 naive 实现——性能下限
  • 每线程沿 C 处理 8 个连续输出（float4，8 个 fp16），3×3 展开直接读全局内存
  • 无共享内存、无 TMA、无线程协作：每个输出独立读自己的 R×S 窗口
  • 优化切入点：相邻输出窗口 2/3 重叠，一个输入元素最多被 9 个输出复用
  • 第 3 章：共享内存优化
  • 输入 tile 先搬进 SMEM 一次：全局读从 BlockP×BlockQ×BlockC×R×S 降为 (BlockP+R-1)×(BlockQ+S-1)×BlockC
  • CTA 分工：一个 CTA 固定 (n, p_block, c_block)，沿 Q 逐 tile 推进
  • producer warp 搬数据、consumer warps 做计算；ring buffer 让搬运与计算重叠
  • n_stage 不是越大越好：算快于搬时加深可防计算单元饿死；算慢于搬时双缓冲已够，多加只占 SMEM 降占用率
  • 第 4 章：B200 实测
  • 环境：B200、CUDA 13.0/12.9、PyTorch 2.9.1、cuDNN 9.10.2
  • v0 随规模线性上升，完全受 HBM 带宽限制；ws n_stage=2 大幅快于 v0，大致追平甚至略胜 cuDNN
  • n_stage=4 反而更慢：SMEM 占用拉低 occupancy；作者第二点解释（B200 HBM 太快、计算慢于搬运）明确标为未验证的推测

流程图

graph TD A[Depthwise Conv：通道独立 3x3 卷积] --> B[v0 naive：每线程 8 通道 float4 直读全局内存] B --> C[瓶颈：相邻输出窗口 2/3 重叠，重复读 HBM] C --> D[共享内存：输入 tile 只搬一次] D --> E[TMA：硬件搬运 + 边界自动补零 + 单线程下发] E --> F[producer/consumer 分工 + mbarrier] F --> G[ring buffer：搬 tile i+1 的同时算 tile i] G --> H[n_stage 取舍：算快于搬则加深，算慢于搬则双缓冲够用] H --> I[B200 实测：n_stage=2 追平 cuDNN，n_stage=4 因占用率下降反而更慢]
