如何看待网友发布的30系及40系显卡的GPU算力解锁工具gpu-unlock？

知乎热榜问题（问题页经登录浏览器通读核验：58 人关注、43,638 次浏览、16 个回答）。开源工具 gpu-unlock（Zagitta）及 Ada 分叉声称解除英伟达对消费卡 Tensor Core 的指令发射限速：3090 Ti 的 BF16 吞吐 87.5→157.4 TFLOPS（+80%），4090 的 FP16/BF16 发射率约翻倍。但高赞回答给出了关键限定：只解锁 FP16/BF16 MMA + FP32 累加这一条路径，而现代 AI 负载多已转 int8/fp8/int4；LLM 推理瓶颈在显存带宽不在算力。机制据答主拆解涉及安全启动固件漏洞与驱动加载前注入，断电即恢复、漏洞大概率被修补。值得看的是限速本身：同芯片消费卡半速、专业卡全速的市场分割样本。

大纲

大纲（据问题页通读与公开报道交叉核验整理）

  • 条目信息
  • 知乎热榜问题；问题页核验：58 人关注、43,638 次浏览、16 个回答、好问题 1
  • 工具：GitHub 项目 gpu-unlock（作者 Zagitta，30 系）与分叉 gpu-unlock-ada（2026-10-24，40 系，当时仅支持 4090、4070 Ti Super、4060 Ti 16GB 等部分型号）
  • 被锁的是什么：一条指令路径的发射率
  • FP16/BF16 矩阵乘 + FP32 累加在 GeForce 上被限为半速，同核心的 Quadro/专业卡全速
  • 高赞答主 Edison Chen 指出：被解锁的只有这一条 MMA 路径；他原以为 50 系已全速，自测后改口称 50 系同样有限速迹象
  • 工具原理（据高赞答主拆解）
  • 传承自 CMP 矿卡破解：工具编译为 Linux 内核模块、放入 initramfs，在官方驱动加载之前运行
  • 借 GPU 安全启动固件漏洞取得受保护寄存器的写权限，改掉速率寄存器，再触发 PCIe 复位；随后正常驱动以为显卡已正常初始化而加载
  • 不改驱动、不刷 vBIOS；断电后恢复原状；推论是固件漏洞大概率会被后续驱动/固件修补
  • 实测数字（问题页与媒体一致）
  • RTX 4090：FP16→FP32 165.6→331.6 TFLOPS，BF16→FP32 165.5→330.6 TFLOPS，约翻倍
  • RTX 3090 Ti（450W，稠密 8192³ GEMM、FP32 累加、五次采样中位数）：BF16 87.5→157.4（+80%），TF32 约 +94%
  • 真实负载的落差（高赞回答的共识）
  • LLM 推理的 Attention 是显存带宽瓶颈，不是算力瓶颈，翻倍数字只是纯矩阵/指令基准
  • llama.cpp / LM Studio 常用 q4 量化、根本不用 FP16，无收益；vLLM 能用但其用户很少用游戏卡
  • 现代负载优先 int8/fp8/int4/fp4，FP16/BF16/TF32 的适用面在收窄；少数真受益场景：老式 BF16 图像生成（如 Flux/SDXL）可能 +50–60%，改显存的 FP16 视频模型（如 Wan2.2 5B）较挑模型
  • 模型越大、越带宽受限，增益越缩水
  • 风险与判读
  • Windows 路径每次冷启动都要重载模块 + 复位 PCIe，单卡黑屏风险高，答主明确劝谨慎
  • 支持范围限于具体型号与平台组合，属实验性工具；收益只落在计算受限、且恰好走 FP16/BF16+FP32 累加的负载上
  • 真正的看点：消费卡算力被寄存器限速这一事实本身，是观察英伟达产品分层与定价权的底层样本
