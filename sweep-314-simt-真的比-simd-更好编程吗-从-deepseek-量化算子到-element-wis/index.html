SIMT 真的比 SIMD 更好编程吗？从 DeepSeek 量化算子到 Element-wise for/if

以 DeepSeek TileKernels 量化算子为试验场，在 Ascend 950 上实测对比 SIMD 与 SIMT：连续规约与简单位运算两者接近，Transpose/Gather/二维规约 SIMT 更自然；FP4 纯 SIMT 软模拟慢约 90 倍、只把最后 Cast 移回 SIMD 则差距缩到 1.26 倍；PTO 虚拟指令集把 MXFP8→BF16 反量化从 144μs 降到 113μs。值得他看的是它把“SIMD 难写”拆成执行模型与接口层次两个问题，并给出 Element-wise for/if + PTO + 超标量 NPU 的完整路线图，正对量化与 GPU/NPU 底层主线。注：文中两张图表为图片，未逐数核验。

大纲

  • 立论：SIMD 难写是接口问题还是执行模型问题
  • 常见说法：NPU 难编因为 SIMD，CUDA 好编因为 SIMT 可按标量思考
  • 反驳：CPU 程序员用 AVX/NEON/SVE 十余年没觉得 SIMD 不可编；高性能 CUDA 也要 Warp Shuffle、Vote、MMA 与同步
  • 试验场：DeepSeek 开源 TileKernels 量化算子，Ascend 950 支持 SIMD/SIMT 混编，可同算法双路对比
  • 为什么选量化算子
  • 数学极简，却几乎碰遍向量处理器的麻烦数据组织操作；FP8/FP4/MXFP8/MXFP4 与多种 Scale 布局
  • FP8 分组量化：每组取最大绝对值定 Scale，E4M3 下 s = a_max/448，q = FP8(x/s)
  • E8M0 Scale 只保留指数：s_f = 2^{ceil(log2 s)}，可从 FP32 指数位直接算，还能省一次真除法；两个 E8M0 Scale 可打包进一个 16-bit
  • 核心操作归纳：Reduce、Broadcast、Cast、Shift、Pack、Interleave、Transpose
  • 固定宽度 SIMD 寄存器为何让类型转换复杂
  • Ascend 950 物理 SIMD 寄存器固定 256 Byte，与数据类型无关；同 256 个元素，BF16 占 512B、转 FP32 变 1024B，物理寄存器数被迫变
  • vcvt 的 PART_EVEN/PART_ODD/PART_P0–P3 与其间的 vintlv/vdintlv 都是为此还债
  • PTO 关键设计：虚拟寄存器逻辑容量随类型变、元素数与逻辑位置不变，Lowering 负责物理拆分重排
  • SIMD 究竟比 SIMT 难写在哪里（七组算法组合实测）
  • 连续数据规约：两者已接近，PTO 代码量可逼近 SIMT
  • Broadcast 与 Interleave：SIMT 略优（如下标即语义）；PTO 需知道分布模式的存在
  • Transpose 与二维规约：SIMT 优势明显（换下标 vs 重算 Lane 索引 + vgather）；32x32 整块规约同理
  • Element-wise for/if：Tile 内每个元素有自己的索引与条件
  • 编译器把逐元素描述重聚为 Tile 指令，如反量化 Broadcast 识别分组共享关系转 Broadcast Load + 向量乘
  • Element-wise if 用 Mask 表达：分支有效集为 P&C 与 P&!C；Mask 语义须精确（非活跃元不是任意清零），尾块 27/32 元素需 Padding 或 Mask
  • Cell Array：每 Group 共享 Scale、每 Tile 共享基址，每元素保留独立数据/索引/Predicate
  • FP4 为什么让 SIMT 慢了 90 倍
  • 原生 FP4 E2M1 转换指令只在 SIMD 路径，SIMT 只能整数位运算软模拟，CA 模型测得纯 SIMT 软模拟 VF 周期约 90 倍
  • 只把最后一次 Cast 移回 SIMD 执行，差距缩到约 1.26 倍
  • 教训：编程模型给表达自由，但专用硬件能力未在各执行模式平等暴露；ISA 设计要整体看待转换、Scale、Pack、Mask、向量与矩阵计算
  • PTO 虚拟指令集带来多少性能收益
  • 同算法同 Shape 下 SIMT 周期数通常为 SIMD 的 1.2–10 倍（FP4 软模拟约 90 倍为例外）
  • MXFP8→BF16 反量化：手写 ASC/CCE VF 144μs → PTO Lowering 后 113μs；VADD/Vmul 不变，VINTLV 从 20 降到 8，局部耗时降约 21.5%
  • 意义在依赖链与流水线 Bubble，不只在指令数；乱序执行消不掉真实依赖、加不了带宽
  • SIMT 能否自动编译成 SIMD？Agent 时代编程模型反而更重要
  • 规则连续计算易向量化，转置/Broadcast/Gather 需从标量下标恢复多维布局；TileLang 的 Shape/存储层级/Tile 边界给了编译器比 C/C++ 更丰富的信息
  • Agent 能批量生成 Intrinsic，但维护、定位回归、理解数值错误的成本上升；优化规则应沉进 PTO 与编译器 Pass，可复用、可随 ISA 演进
  • 结语：好架构应让程序员永远按算法自然的方式描述数据，编译器与硬件负责组织、执行与调度
