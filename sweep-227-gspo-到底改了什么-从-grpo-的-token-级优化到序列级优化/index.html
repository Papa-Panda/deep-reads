GSPO 到底改了什么？从 GRPO 的 token 级优化到序列级优化

知乎推荐流专栏（作者「心灵的灯」，2026-10-23 07:26 发布于北京；读时 2 赞同、5 收藏、0 评论。已通读原文的更正版——本轮早先曾以未读原文兜底写入）。一篇纯公式与机制层面的 GSPO 拆解（全文无实验数据）：先并列 GRPO 与 GSPO 两个目标函数，指出差别只在『优化粒度』——GRPO 的重要性权重与 clip 都在 token 级、优势是 Â_{i,t}；GSPO 把优势写成整条序列的 Â_i，比率 s_i(θ) 是整条序列似然比的 1/|y_i| 次方（长度归一化），clip 也在序列级。随后逐节论证：token 级比率单样本估计方差大、且与序列级奖励错位；负优势时 token clip 拦不住过大的比率（文中用 10^-6→0.001 得比率 1000 的示例说明），波动累积可拖崩 MoE；序列级单位对单个 token 的路由变化不敏感，故 MoE 训练不再需要 Routing Replay。本质区别一节最值得记：GRPO 逐 token 给梯度调权重，GSPO 只整句统一缩放、不改变句内 token 的相对变化。正对他的 RL 配方主线——看 GRPO 系变体，先盯优化单位与奖励单位是否对齐、以及梯度是否被逐 token 加权。

  • 二、为什么 token 粒度不行
  • 高方差：重要性采样靠多样本纠偏，单样本时修正有限、方差不可避免，逐 token 算比率尤其抖
  • 错位：奖励通常是序列级的，优化却在 token 级；token 级奖励理论可行但难落地
  • 三、序列似然比的推导
  • 序列概率＝条件 token 概率之积 ⇒ 序列比率＝token 比率之积 ⇒ 取 1/|y_i| 次方并用 log/exp 化乘为加，得到 s_i(θ) 的 exp 形式
  • 四、长度归一化降方差
  • 统一不同长度序列的比率数值范围，避免长序列比率被连乘放大/缩小，使不同长度回复可同尺度比较
  • 五、Clip 粒度：从 token 到序列（关键节）
  • GRPO 的不对称：A>0 时比率有效范围 0~1+ε；A<0 时是 1−ε~+∞——负优势时 clip 只拦过小、拦不住过大，比率取 min 后仍保留裁剪前的大值
  • 文中唯一数字示例（说明性、非实验）：旧策略某 token 概率 10^-6、新策略 0.001，比率即达 1000
  • 后果：波动随训练与序列变长累积，可最终拖崩 MoE 模型
  • GSPO：整体偏离策略的整条样本直接整条裁剪，与序列级奖励完全对齐，避免 token 级 clip 的噪声与偏差
  • 六、消除 Routing Replay 依赖
  • MoE 病灶：梯度更新后专家激活模式改变（同一批样本从激活专家 1、2 变成 1、3），同 token 换专家则计算结果大变，比率剧烈震荡、频繁触发 clip，被 clip 的 token 无梯度、留下的带噪声
  • 传统解 Routing Replay：记录旧策略采样时激活的专家，更新时强制同路由
  • GSPO 以序列为单位、对单 token 波动不敏感，故不需要 Routing Replay
  • 七、本质区别：是否对 token 梯度加权
  • GRPO：逐 token 用各自重要性权重调梯度（逐 token 调权重）
  • GSPO：只把整句的比率统一缩放，不改变句内 token 之间的相对变化（整句统一缩放）——文中称这是其更稳、更适合长序列与 MoE 的根源
  • 八、一张表总结（七行对照）
  • 重要性权重粒度、clip 粒度、与奖励粒度对齐（弱 vs 强）、长度归一化（逐 token 平均 vs 序列似然比 1/|y_i| 归一化）、方差（高 vs 低）、Routing Replay（通常需要 vs 不需要）、token 梯度加权（是 vs 否）
  • 九、一句话总结
  • GRPO 在 token 级做重要性采样与 clip：噪声大、与序列奖励错位、MoE 依赖 Routing Replay；GSPO 把权重与 clip 抬到序列级、用长度归一化的序列似然比优化：降方差、对齐奖励、去掉 Routing Replay
