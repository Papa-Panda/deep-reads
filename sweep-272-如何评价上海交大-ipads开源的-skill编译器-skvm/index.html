如何评价上海交大 IPADS开源的 Skill编译器 SkVM？

知乎回答（作者 tomsheep）评析上交 IPADS 开源的 SkVM：把 Skill 从可移植的提示词文本，重新理解为需要在不同模型与 Agent 框架上适配的程序，用编译思路提升其可靠性。值得他看的是这条把 Agent infra 的关键痛点——同一 Skill 换模型、换框架、换环境就失灵——拆成可度量、可补偿、可并行化的工程问题；文中实验数字为回答所称，未独立核验。

大纲

大纲（据回答通读整理，概括转述）

  • 核心主张
  • Skill 不应只看作一段可移植的提示词文本，而应看作要在目标平台上运行的程序
  • 多数 Skill 结构相对固定、参数变化，因此适合做编译式准备与运行时优化
  • 一、问题：Skill 生态为何参差
  • 名义上是 Markdown 文档、看似可移植，实际是提示词的一部分
  • 三类失配：模型能力假设不成立；同一模型在不同框架下表现不同（系统提示、工具、上下文组装不同）；用户机器缺少假设的包、命令行工具、服务或配置
  • 二、思路：把 Skill 当高级代码
  • 模型与框架相当于不同的 CPU / 操作系统，SkVM 是中间的编译层
  • 难点：大模型是概率黑箱、没有确定指令集，所以这种编译只能是经验性的，而非形式化精确的
  • 三、核心设计
  • Profiling：把复杂 Skill 拆为 26 个原子能力并分级，用基准套件测出目标模型加框架的能力画像并缓存复用
  • AOT 编译：抽取 Skill 的能力需求并与画像对比，差距小则把指令写得更明确、示例更丰富，差距大则换等价实现路径；再抽取依赖并生成幂等环境安装脚本，事前修好缺失工具；最后从离散步骤建依赖 DAG，暴露可并行部分
  • JIT 优化：重复执行后，把结构固定、参数变化的模板固化为可直接执行的代码；只有系统性、与 Skill 相关的重复失败才触发动态重编译
  • 四、回答所称的实验效果
  • 原生 Skill 不可靠，SkVM 后平均任务完成率、回归率、token 用量与并行加速均有改善（数字为回答所称）
  • JIT 固化在合适的模板化任务上加速最显著
  • 五、边界与启示
  • 更适合结构化、工具密集、流程化的 Skill，高度开放、依赖模型原生创造力的工作受益不明
  • 对普通 Skill 写作也有启发：流程清晰、依赖明确、模板可抽取、任务可拆为可验证、可并行、可复用的单元
