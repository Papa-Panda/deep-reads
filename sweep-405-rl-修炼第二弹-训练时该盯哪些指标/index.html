RL 修炼第二弹 · 训练时该盯哪些指标

大海无量（2026-10-15）以 LoongSage 代码库为例，讲清 RL 训练该盯哪些指标：RL loss 本身不是健康信号，要看 reward/优势、KL 估计器、熵与训推一致性等一组行为指标，给出公式、阈值与熵崩溃、奖励 hacking 等故障诊断流程。后训练 RL 实操手册。

2026-11-27

原文链接：https://zhuanlan.zhihu.com/p/2094100433065329717

大纲

1. 前提：RL loss 不是健康指标

  • SFT 里 loss 下降有信息量；RL 的 loss 是优势加权、clip 后的策略梯度替代目标，抖动是常态
  • 要盯的是一组行为指标，各有公式、代码路径与判读标准

2. 奖励与优势：方向对不对

  • rollout/reward_mean + rollout/response_length_mean（答案变长常意味着推理步数增加）
  • rollout/all_correct_ratio 与 all_wrong_ratio：GRPO 组内归一化下全对/全错组优势为 0
  • train/adv_zero_ratio 高 = 采样算力被浪费，应调题目难度或组大小

3. KL：k1 / k2 / k3 三种估计器

  • r = log(π_ref / π_θ)；k1 = -r（无偏高方差，可为负），k2 = r²/2（有偏低方差），k3 = e^r - r - 1（无偏低方差，恒非负，默认）
  • use_unbiased_kl 时按重要性比 π_θ/π_old 加权（DeepSeek-V3.2 的做法）
  • 关键是系数 ref_kl.coef 而非估计器选择；KL 缓升正常，陡升是警告

4. 熵：探索是否还在

  • H = -Σ p log p，logsumexp 稳定计算；以 bonus 进 loss：rl_loss = pg_loss - entropy_coef × entropy_loss
  • 缓降正常，断崖式下跌 = 熵崩溃：模型停止探索、奖励停滞，调高 entropy_coef 或用 clip-higher
  • 熵近零还继续训 = 在少数路径上过拟合奖励缺陷

5. 训推一致性：is_approx_k3_kl

  • 采样用 SGLang、训练用 Megatron，同一权重算出的 logprob 有细微偏差
  • train/is_approx_k3_kl 用 k3 公式度量 train 侧 old_logprob 与 rollout 侧 rollout_logprob 的差距，健康值在 1e-4 量级且稳定
  • 配套看 is_logprob_abs_diff、is_clip_ratio、is_nan_ratio；MoE、FP8、异步训练会放大偏差
  • 框架用 IS 修正（π_old/π_rollout 加权）与 M2PO / OPSM 做离策略保护

6. 更新幅度与诊断流程

  • train/approx_kl（相对采样策略走了多远，区别于 ref KL）与 train/clip_ratio（被 clip 的 token 占比，百分之几到 10%+ 健康，过高说明步子太大）
  • 诊断顺序：reward_mean 定方向 → ref KL + 熵看漂移/崩溃 → is_approx_k3_kl + clip_ratio 看稳定性
  • Q&A：奖励涨但 KL 涨、熵崩溃 = 奖励 hacking；loss 抖但奖励稳升、KL 可控、熵未崩溃通常无碍
