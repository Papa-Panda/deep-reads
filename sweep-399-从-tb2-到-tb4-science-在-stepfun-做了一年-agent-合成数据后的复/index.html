从 TB2 到 TB4 / Science：在 StepFun 做了一年 Agent 合成数据后的复盘

StepFun 的 Yongchi Zhao 复盘一年 Terminal-Bench 任务合成：上半年 Agent Scale 靠规模与多样性把终端 Agent 能力从 0 做到 1，下半年进入 TB4/TBS 深水区，提出“真实+有效难度”的好任务标准、L1/L2/L3 合成策略与三条提质路径，并以 Anthropic S-1 数据成本论证系统性数据资产是与算力并列的另一条鸿沟。Jun 做后训练数据与 Agent 环境可直接对照；注意这是反思性长文，部分数字引自他人工作。

大纲

1. 背景：作者一年做 Terminal-Bench 任务合成

  • StepFun 一年：上半年 TB2，下半年 TB4 / Terminal-Bench Science（TBS）
  • 上半年是 Agent Scale 时期：搭多样化可执行环境、规模与多样性优先，模型终端 Agent 能力从 0 到 1
  • 下半年任务变难：好任务的两条北极星——真实（Realism）与有效难度（Effective Difficulty）

2. 为什么 Agent 时代要大规模环境

  • 聊天 SFT 只需少量样本：LIMA 1000 例即可，因对话本就是预训练语料的延续，少量样本只做格式对齐
  • Agent 多轮探索数据在预训练中是分布外的：教程、成品代码多，但“探索→跑命令→修错→测试”的状态演化过程很少被记录
  • 结论：Agent 行为要从头学，必须大规模可执行环境训练

3. SWE 与 TB2 的规模化路径不同

  • SWE 有天然金矿：开源仓库的真实功能、历史依赖与测试套件；三种形态：PR→任务、基于仓库的功能开发、仓库级黑盒任务
  • 数字：SWE-Universe 从 5.2 万仓库扫出 80.7 万可验证环境；Nemotron-Terminal 用 31,661 条 SWE 轨迹把 Qwen3-8B 的 TB2.0 从 2.47% 提到 7.02%，胜过 5 倍量的数学轨迹
  • TB2 长尾分散：89 个任务跨 16 类，75.4% 标签只出现一次；环境轻（Dockerfile 中位 10 行）；交互中位 10 轮
  • 合成三步教训：自由想象→快速同质化；多维短语种子→缓解表面重复但信息密度低；高信息密度真实素材→决定合成任务天花板；CLI-Universe-6K 以约 1.2% 数据量胜过 49 万条全量
  • 泛化三层 L1/L2/L3：以 L2 为核心最稳；退回 L1 只宜调试，追 L1 指标是“蜜糖毒药”

4. 深水区：TB4 / TBS 与“好任务”的定义

  • TB3.0 首批 74 任务引入多容器、GPU 与专业产品；TB4.0 66 任务；TBS 70 任务由 376 位研究者的 920 份提案三审仅 7.6% 通过
  • 好任务两维：真实专业对齐（对应真实工作场景的真实需求，不靠堆琐碎细节压低通过率）+ 足够难（任务本身正确无歧义的前提下，当前模型不能稳定高通过率）
  • 传统合成任务多是“清晰合同下的短闭环执行”；真正难住模型的是三类真实工作流：未知损伤机制的数据取证与假设检验、跨模块强耦合系统的约束权衡、随操作演化的在线动态反馈环

5. 瓶颈：模型会解题，不会出题

  • SOTA 模型“出题”能力远落后于“解题”：能协作证明黎曼猜想，却提不出黎曼猜想级的新问题
  • 三条提质路径与边界：高密度细节输入（专家注入先验，Mercor / Scale AI 路线）；小领域专用流程（可批量但换域难复用）；任务渐进深化 Deepen（门槛低但演化方向不可控，易脱离真实任务）；附带技巧：去掉隐含解题提示可低成本提难度

6. 终局：专家仍不可替代，数据资产是壁垒

  • Polanyi 悖论与 File Drawer 问题：专家隐性知识与“死胡同”负样本不在公开语料里
  • IdeaTaste：模型研究品味仅达人类社群的 26%（引用匹配）/ 18%（具体想法）；TasteVal：问题给定后模型实验迭代效率达人类专家 2.3 倍——人机分工边界清晰
  • Anthropic S-1 第 235 页：把 post-training 任务体系写为最持久的科学壁垒；2025 年第三方数据质检成本同比 +1.65 亿美元，2026 前三季度 +7.57 亿美元
  • 结论：数据与环境工程没有捷径；中美差距不只算力，还有先发积累的、与各领域顶级专家精细对齐的系统性数据与环境资产
