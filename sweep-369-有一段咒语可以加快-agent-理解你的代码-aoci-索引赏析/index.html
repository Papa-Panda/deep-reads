有一段咒语可以加快 Agent 理解你的代码！AOCI 索引赏析～

飞天闪客（2026-11-18，5:51）讲 AOCI 索引：把每个文件压成一条固定维度的字母编码记录（职责/关联/接口/补充），整项目索引一次读进 Agent 上下文，免去盲目翻文件烧 context；官方对照实验相关文件召回率 57.2%→74.8%，50 万行代码压成约 20 万 token 索引，靠文件哈希增量更新。Agent infra 里代码认知压缩的新思路，结尾还留了“维度是否最优”的开放问题。注：视频无简介，数字来自视频旁白与转录。

大纲

问题：大项目塞不进上下文

  • 小项目可整体塞进 Agent 上下文，大项目不行
  • Vue3 约 160 万 token；K8s 约 7000 万 token——1M 上下文一次最多读约 1/70
  • 现状 workaround：先让 AI 通读项目写一份 README，下次先读 README——等于手动做了一次索引工程

AOCI 的思路：为 Agent 而写的压缩索引

  • README 是给人看的自然语言；能否把同样信息压成专供 Agent 读的摘要？
  • AOCI：代码认知压缩新范式
  • 每个文件压成一条记录，固定维度 + 统一字母编码
  • 例：UserService.java: F:users | R:user | A:get | S:id
  • 四栏：负责什么、改它要盯谁、对外暴露什么接口、补充信息
  • 全项目记录合起来就是一份索引，可一次读进上下文
  • 比喻：像一张简化关系表——改代码就更新它的记录；一文件一条记录

实操演示：5 万行新闻聚合站

  • 步骤 1：经 MCP 安装 AOCI Code（官方配置现已自动写好，交给 Agent 执行）
  • 步骤 2：建索引——模型按 AOCI 规则把每个文件压成一条记录，需耗时
  • 产出：项目内索引文件 + 可视化整站结构的网页（入口层、元信息、核心索引）+ 一份面向 Agent 的项目总述文档
  • 演示任务：加“删除新闻”功能——Agent 凭完整索引直接定位修改点，改真实文件后功能跑通；视频称 Agent 对系统整体把握约 99%（UP 自认小演示代表性有限）

官方对照实验

  • 4 个仓库 93 个真实 issue，SWE-benchmark 式测试：相关文件召回率 57.2%→74.8%
  • 未见过的仓库：修复率 66.7%→约 82%（该数字转录不清，仅供参考）
  • 规模收益：50 万行代码 → 约 20 万 token 索引；70 万行 → 约 30 万 token，占 1M 上下文的 30%，余 70% 给对话
  • 保鲜：按文件哈希增量更新，只重建改过的文件，不用全量重扫

开放问题与评论区质疑

  • 索引终究还是一份文档：为什么不直接让 AI 写自己的 README？AOCI 的维度与格式是否最优，尚未定论
  • UP 的追问：如果它真是更优解，大模型会不会自然而然学到这种结构总结？
  • 评论质疑 1（冷鸟社区）：快速迭代项目里索引易过期，增量更新是否够用
  • 评论质疑 2（ousannwangmm，178 赞）：怕刚跑起来就被大模型厂商内化进工具链，又得迁移，不如等厂商更新
  • 评论追问（弹幕）：AI 拆 spec 的任务粒度仍是人类规模，这部分优化还没见过
