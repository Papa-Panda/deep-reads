vLLM Agentic 推理｜面向 Agent 负载的推理优化

vLLM 维护者从 Agentic 工作负载出发，讲清多轮推理-工具调用循环如何改变推理瓶颈，并给出 prefill/decode 分离、KV 共享与工具调用一级优化的整套打法。值得他看的是它把 Agent 推理从单次聊天扩展成系统工程问题，正对 Agent infra 与推理优化的兴趣。

大纲

大纲

  • 一、Agentic 工作负载是什么
  • 不再是一次问答：推理—工具调用—再推理的多轮循环
  • 编程 Agent 常有数十轮，上下文不断累积，多 Sub-agent 并行
  • 特征：token 量大且波动大、长尾与上下文相关 token 占比高、工具调用轮次主导延迟
  • 二、怎么评估 Agentic 推理性能
  • AgentX 数据集与示例任务
  • 指标：延迟、TTFT、吞吐、P99/P999、单位 token 成本
  • 三、vLLM 优化总览
  • 系统层优化与引擎层优化分工
  • 四、引擎层三大优化
  • Prefill/decode 分离与弹性 EPD：两者独立扩缩容
  • KV 缓存共享：跨轮次、跨 Sub-agent 的前缀与 KV 复用，含全局前缀缓存与 KV 传输
  • 工具调用与结构化输出：一级引擎能力，增量解析、并行与异步执行、语法缓存
  • 五、完整 Agentic 技术栈
  • 多智能体框架、多轮对话管理、Agent 框架、Agent 服务部署、开发框架
  • 六、结论
  • 优化必须跨层协同：引擎、KV 系统、调度、工具调用、Agent 框架一起做
