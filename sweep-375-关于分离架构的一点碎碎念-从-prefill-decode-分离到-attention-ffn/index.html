关于分离架构的一点碎碎念——从 Prefill/Decode 分离到 Attention/FFN 分离，重新理解大模型推理的性能

美团 mlsys 实习生 QIU Chengyu（2026-11-20，19 赞）从一年分离式推理实践出发：MFU、利用率、峰值吞吐都是局部指标，真正该比的是同预算同 SLO 下的整机可服务吞吐；P/D 分离与 AFD 分离的收益要扣掉「承载能力税」与通信等待——Qwen3-235B 仿真里 FFN 局部 MFU 涨 3 倍，整机吞吐反而只剩 70.7%。推理优化的一线实测与度量框架，值得慢读。

大纲

1. 什么才算更好的推理系统

  • MFU、利用率、峰值吞吐都是局部指标：GPU 忙不等于服务了更多用户
  • 局部 MFU 与部署级 MFU 口径不同：前者只算 GEMM 窗口，后者含通信与等待
  • 吞吐不看延迟会作弊：放大 batch、容忍排队就能刷高峰值

2. 从吞吐到 SLO

  • TTFT（首 token）与 TPOT（每输出 token）刻画在线体验的不同阶段
  • Goodput 与 SLO 可行吞吐：在给定延迟达标率下，系统能服务多少请求
  • 目标函数：资源预算内，最大化满足 SLO 的服务吞吐

3. P/D 分离：让不同阶段各满足自己的 SLO

  • Prefill 算密、Decode 访存重；同卡部署互相干扰（长 Prefill 饿死 Decode）
  • 分离后各池可独立选硬件、并行策略与调度，但 KV 传输与排队成本仍在
  • 对照路线：Sarathi-Serve 的 Chunked Prefill，不分离也能缓解干扰

4. AFD 分离：Attention 与 FFN 的资源错配

  • Attention 要大 KV 状态，FFN 要大 batch；MoE 下专家 token 往往太少
  • 潜在收益：Attention 卡腾出专家权重显存装更多请求；FFN 可聚合多路 token
  • 代价概念：「承载能力税」——划给 FFN 池的卡不再直接承载请求

5. 实测：局部效率涨 ≠ 整机吞吐涨

  • Qwen3-235B 仿真：FFN 局部 MFU 27.9%→84.3%，整机吞吐却只有基线的 70.7%
  • LongCat 910C 实测：吞吐 +82% 的同时 Decode 周期恶化约 37%
  • 分母陷阱：多加 25% 的卡，总吞吐 +5.4%，单卡吞吐反而 -15.7%

线上效果与扩展性

  • 一周 A/B vs Generator–Evaluator：人均 GMV +2.63%，广告主价值 +2.06%，复购率 +2.03%，重排 + 混排端到端延迟 −13%
  • 奖励模型越大判别越强；decoder 越大订单 / GMV 增益越高；采样组 8→128 三目标皆升、边际递减

6. 三层度量框架

  • 模块效率层：利用率、局部/部署 MFU、HBM 带宽、通信开销
  • 用户体验层：TTFT、TPOT、TBT 尾延迟、SLO 达标率、完成率
  • 整机容量层：Requests/s、Output Tokens/s、SLO 可行吞吐、Tokens/s/$、Tokens/s/W

流程图
