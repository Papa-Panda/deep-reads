LoRA 一作、OpenAI o1 核心成员的新工作：首次公开 397B 模型的 Agent RL 训练配方

LoRA 一作、OpenAI o1 核心成员 Edward Hu 加入 Mercor 后与 SkyRL 团队联合发布：Qwen3.5-397B-A17B 在 APEX-Agents（480 个长程知识工作任务）上 Pass@1 从 16.11% 提到 27.29%。最震撼的结论是只修 Harness（PDF 解析、工具返回 None、沙箱超时）就让未训练模型平均奖励从 22.74% 升到 28.69%，涨幅相当于一个 epoch 的训练。公开 TITO token 对齐、Fully Async RL 的 KV Cache 并发上限、Prompt Mean+DPPO+Context Nudge 组合等工程细节。正中他 Agentic RL Infra 主线。（未读到原文细节：大纲按浏览器任务通读摘要重构）

大纲

大纲

  • 背景：谁在做、做什么
  • Edward Hu：LoRA 一作、OpenAI o1 核心成员，加入 Mercor 后与 SkyRL 团队合作
  • 模型 Qwen3.5-397B-A17B；任务集 APEX-Agents（法务/咨询/投行 480 个长程知识工作任务）
  • 结果：Pass@1 从 16.11% 提升到 27.29%
  • 核心结论：只修 Harness 约等于一个 epoch 的训练
  • 修 PDF 解析、工具返回 None、沙箱超时等问题后，未训练模型平均奖励 22.74% 升至 28.69%
  • 工程哲学：Agent RL 成败更多取决于环境、Harness、Verifier 和数据，而非 RL 算法本身
  • 关键工程细节
  • TITO（Token-in-Token-out）：推理与训练 token 完全一致，避免隐蔽 off-policy
  • Fully Async RL：KV Cache 并发上限计算
  • 算法组合：Prompt Mean（按任务而非 token 聚合 loss，单项 +3.9 点）+ DPPO + Context Nudge
  • 实施顺序：先 32 个任务 overfitting run，再做大训练
  • 与之前工作的关系
  • 呼应 MiMo 拆解："修环境比调算法更重要"；对照 SDPO：算法侧 dense signal vs 工程侧 harness/verifier
  • 迁移
  • 做 Agent RL infra 先做 harness 可靠性审计（工具返回、沙箱超时、解析），再谈算法
  • TITO 思想可迁移：任何"推理-训练"两套 token 化路径的系统都要做一致性校验
