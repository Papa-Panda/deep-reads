为什么我越来越确信，未来的AI Harness不会只有一种形态？

知乎推荐流条目（浅月落，2026-10-15 发布；热度很低，0 赞、2 收藏、约 208 阅读）。作者复盘自研轻量 Agent 框架 SIAH 的实践后提出一个判断：Harness 的形态应由任务的复杂度与不确定性决定，而不是追求单一通用框架——简单任务用单循环 ReAct，复杂任务用先规划后执行，多视角任务用多 Agent 协作，高风险任务保留 Human-in-the-loop；Skill 也应分临时经验、领域方法论、组织资产三层沉淀。对他的价值在 Agent infra/harness 这条主线：这是一篇把 harness 多样性讲成选型原则的一线实践随笔。注：全文为框架与观点论述，无 benchmark 与成本数据，深度在结构而非实测。

大纲

大纲（据原文通读整理）

  • 核心判断
  • Harness 不会收敛成单一通用形态；形态应随任务的复杂度与不确定性选型
  • 出发点是作者自研轻量 Agent 框架 SIAH 的实践复盘
  • 任务先拆三维
  • 目标是否清晰、路径是否确定、结果是否可验证
  • 三维组合决定该用哪种控制结构，而不是让一个框架硬套所有任务
  • 四种形态与适用面
  • 单循环 ReAct：简单、路径短的任务
  • Plan-and-Execute：步骤多、需要先规划的复杂任务
  • Multi-Agent 协作：需要多视角分工的任务
  • Human-in-the-loop：高风险、不可逆的任务
  • Skill 沉淀分三层
  • 临时经验：一次性的上下文技巧
  • 领域方法论：可复用的做事套路
  • 组织资产：团队级沉淀、可治理的能力库
  • 边界与落点
  • 全文为架构随笔，无 benchmark、无成本与延迟数据
  • 可迁移的结论：先判任务结构，再选 harness 形态与 Skill 层级
