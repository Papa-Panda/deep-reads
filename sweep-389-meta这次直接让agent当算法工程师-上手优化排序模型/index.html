Meta这次直接让Agent当算法工程师，上手优化排序模型

杨沐白解读 Meta 论文《MLE Agents》（arXiv:2611.23910）：Claude Opus 4.8 驱动的 Agent 在 31 天、131 轮里对日请求 10 亿+的搜索排序模型 Nullstate 做了 1097 组 64 卡训练实验，采纳 325 项改动，加权 NE 0.6611→0.6388，上线 A/B 搜索会话 +0.23%；代价是约 36 万 GPU 小时与渲染延迟护栏回归。Agent 当算法工程师的工业级实证，附目标错配、黑名单与人只管方向的完整复盘。

原文链接：https://zhuanlan.zhihu.com/p/2108284527625889167

大纲

1. 三笔账：成绩、代价与护栏

  • 31 天、131 轮、1097 组实验、325 项采纳，加权 NE 0.6611→0.6388，线上搜索会话 +0.23%
  • 代价约 36 万 GPU 小时；渲染延迟护栏回归
  • 论文把三笔账写在同一页上

2. 改的是什么：Nullstate 排序模型

  • 多任务排序模型，Transformer 骨干，给搜索框联想词条排序，日请求 10 亿+
  • 每组候选都是一次 64 卡、median 3.54 小时的真实训练
  • 研究问题：LLM 能否做工业级算法工程师，而非刷 benchmark

3. v1.0 的三处败因与 v2.0 的改法

  • 目标错配：Click AUPRC 偏爱易点击的直达结果，离线涨、线上不动；改加权 NE 0.3×click + 0.7×下游
  • 上下文过载：全量历史致约三分之一输出格式错误；改结构化上下文——“What Didn't Work”黑名单 + 严格格式契约 + 防陈旧规则
  • 串行太慢：每轮 7 并行候选 + 1 方差探针；并行提吞吐不提单次速度

4. 失败也要记账：黑名单机制

  • 失败方向带实测代价入黑名单：ADAM-epsilon 改动 NE +6.2%、同方差不确定性加权 +4.5%、DB-MTL 平衡 +1.8%
  • 黑名单缓解但不能根除探索坍缩；自我纠错不一致（一次二次门控改动 18 次跟进后才回滚）
  • 格式错误率 33.8%→0.8%是唯一干净的单变量对比

5. 人只管方向，Agent 带来外部机制

  • 人经同一上下文通道间歇干预：seeds 文件插想法、黑名单写失败方向、目标失准时重校准；典型：优化器调参连败 8 次后人把方向转到架构搜索
  • 研究阶段检索代码库与外部文献（FRNet、MaskNet、FiLM），引入新架构：融合自注意力投影 MLP + 4 层 SE-DHEN、双向稠密/稀疏交叉注意力、独立内容 embedding Transformer
  • 最大边际贡献：去掉 content_downstream 负标签平滑（−0.0041）、自注意力输出加可学习 sigmoid 门（−0.0024）；边际贡献不可加总

6. 平台期与上线：算力不是万能

  • 最优模型远在结束前已找到，同空间继续加算力无用；要扩假设空间——新研究阶段、新模型面、多 Agent 团队
  • 一周 A/B：搜索会话 +0.23%（95% CI ±0.15%，Fieller 法），下游参与与留存正向；但渲染延迟护栏回归
  • 只认纯质量目标的 Agent 不会自己把 trade-off 摆上台面；结论：MLE Agent 不取代 ML 工程师，而是把角色从假设执行者变为研究总监
