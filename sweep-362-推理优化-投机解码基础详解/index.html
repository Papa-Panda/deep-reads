【推理优化】投机解码基础详解

Twinkle（2026-11-17）把投机解码从头讲透：解码慢在访存而非算力（单 token 算力利用率不到 1%），小模型猜 k 个候选、大模型一次前向并行验证，按 min(1, p/q) 投机采样接受、拒则按 norm(max(0, p−q)) 重采样，全接受再得一个 bonus token；无损证明、EAGLE 3.1x 实测、k 取 3–8 与 α 熔断线都给了具体数字。正撞推理优化与 KV Cache 主线。注：文中部分公式为图片，未逐字读到。

大纲

大纲（全文已通读；Twinkle，2026-11-17；7 赞 / 15 收藏；文中部分公式为图片，未逐字读到）

  • 立论：不改变输出分布前提下，小模型猜、大模型验，加速自回归生成
  • 为什么解码慢
  • 自回归：每 token 一次完整前向，20–200 tokens/s，100 token 要 1–5 秒
  • 瓶颈是访存：H100 约 3.35TB/s，70B FP16 约 140GB，每 token 要读一遍全部权重；单 token 算力利用率不到 1%
  • KV Cache：Llama-3-70B 每 token 3.2MB，1000 token 3.2GB；MLA 可把 KV 压 93%（3.2MB→0.2MB）
  • Batch 32–64 利用率提到 70–90%，但不缩短单用户延迟；prefill 算力 bound、decode 访存 bound，PD 分离是背景
  • 核心机制：草稿 + 验证
  • 草稿模型：同系小模型（如 Llama 3.2-1B 配 70B）、Medusa 头、EAGLE、Eagle-2 动态树、Prompt Lookup
  • 验证：目标模型一次前向并行算出全部 k 个位置的分布（同 prefill 的并行模式）
  • 投机采样：按 min(1, p_target/q_draft) 接受；首次拒绝处丢弃后续并按 norm(max(0, p-q)) 重采样；全接受多得一个 bonus token
  • 树验证：一次前向验整棵候选树，提高至少一分支存活的概率
  • 无损证明：两情形求和恰为 p(x)，输出分布与目标模型单独解码完全一致
  • 收益与实测
  • 草稿成本约目标的 5–10% 延迟、1–10% 参数；期望每轮 token 数 (1-α^{k+1})/(1-α)
  • 典型 2–3x，乐观 3–5x；EAGLE 在 Llama 2-70B 上 1.6–2.3x、Llama2-Chat 70B 上 3.1x；Medusa 在 7B 上 2.18–2.8x
  • 工程经验：k 最优 3–8、上限 10；α 低于 0.6–0.7 不值得开，低于 40% 熔断关闭；k 应动态调
  • 适用与局限
  • 适合：长输出、小 batch、低延迟单用户、代码/结构化/模板化等高接受率任务
  • 不适合：大 batch、短输出、高熵创意写作、长上下文 KV 主导场景；草稿太弱或太大都吃掉收益
  • 工程难点：草稿选型与对齐、树验证的 KV 管理、与 temperature/top-p 的兼容、与 batching/PD 分离的配合
  • 未来方向
  • 自适应草稿长度与动态树；EAGLE-2/3 等预测隐状态的草稿头；检索式草稿（Look-M/REST）；融合验证 kernel 与 PD 分离、连续批处理等系统协同
