为什么 AI 时代值得重新讨论 OS：从 Linux Kernel 到 GPU 执行栈的系统重构

王多鱼-加油（2026-04-06，409 赞 / 626 收藏）从第一性原理讲 OS 的本质是资源抽象：Linux 靠进程/虚拟内存/文件等抽象赢了 CPU 时代，而 AI 把系统重心移到 GPU 张量程序——FlashAttention、Triton/CuTe、vLLM 的 PagedAttention 正在长出新的执行栈与内存/调度子系统；所谓 AI OS 不是取代 Linux 的新内核，而是其上的一层层新系统层。AI Infra 的系统视角长文，值得慢读。

大纲

1. OS 的本质：抽象决定成败

  • Linux 的伟大不在功能清单，而在选对了 CPU 时代的资源抽象
  • 进程/线程：资源归属、隔离与容错边界；虚拟内存：把物理字节变成可组织的策略对象
  • 文件/Socket：持久化与通信的统一接口；驱动与系统调用：把硬件细节藏进内核语义

2. AI 把系统重心移出内核

  • 传统热路径：线程拿 CPU 时间、碰虚拟内存、调系统调用
  • LLM 训练与推理的胜负手：计算图下沉、算子融合、tile 尺寸、HBM/共享内存/寄存器间的数据搬运、流间同步、多卡集合通信与计算重叠、KV 缓存分配与请求调度
  • 真正重要的一等对象变成张量、布局、图、核函数、流、KV 缓存、请求、会话、上下文

3. GPU 已有自己的执行栈

  • 驱动：上下文、地址空间映射、命令提交，是硬件资源进入系统秩序的第一站
  • CUDA/HIP 运行时：流、事件、分配器、核函数启动、图执行、异步拷贝与同步——是 GPU 时代的 POSIX
  • 栈的形态：驱动 → 运行时 → 编译器 → 核函数 DSL → 服务/运行时系统 → 分布式运行时

4. 编译器正在成为系统组件

  • MLIR/Triton/CuTe 里融合、分块与布局不是局部优化，而是资源组织
  • tile 选择决定寄存器/共享内存占用、bank 冲突、occupancy 与通信重叠；融合决定中间结果是否落 HBM；布局决定访存模式，进而决定核函数代码与同步
  • 编译器与运行时边界模糊：编译器预先定下运行时要面对的资源形状

5. FlashAttention、Triton 与 vLLM：新的系统层

  • FlashAttention 的启示：瓶颈常是跨内存层级的数据搬运而非 FLOPs，核函数设计即内存系统设计
  • Triton/CuTe：把并行结构、布局与数据搬运以恰当形式暴露出来，如同当年的页、inode、socket、epoll
  • vLLM 的新矛盾：同时处理数百个长度/阶段/SLA 各异的请求，最稀缺的是 HBM 尤其是 KV 缓存；PagedAttention 是真正的页式缓存管理，系统要调度 token 生成顺序、批次合并与驻留策略

6. 什么是 AI OS

  • 不是取代 Linux 的单体新内核，而是在 Linux 之上的新系统层
  • Linux 仍管通用隔离、设备、网络、文件系统、安全与基础资源控制
  • 其上：GPU 驱动 + 运行时 + 编译器 + 通信运行时构成新「执行内核」；再上：服务系统、会话运行时、内存运行时；顶层：Agent、工作流、工具与策略层
  • 真正的问题：谁先把这些新一等对象抽象清楚，谁先把驱动、运行时、编译器、核函数、内存、调度与请求语义组织成稳定系统
