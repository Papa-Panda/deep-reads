更快更省的 RL 权重同步传输

实习作者做的 RL 权重同步中间件 ShardFly：零冗余发送计划（算一次、每步复用）+ GPU 发起网络（NCCL device API 绕开 CPU）+ 传输中量化（BF16→FP8→FP4），256 张 H20 上 Qwen3-30B-A3B 同步从 2953.6ms 降到 373.9ms（7.9x），端到端训练 20.4 分钟→3.5 分钟。值得他看的是它正撞 RL 训练 Infra 主线，把“同步耗时 3 倍于训练步”的瓶颈打成可忽略项，且有论文（arXiv:2611.00646）与开源代码可对照。注：文中 TL;DR（3.59–11.02x）与表格最大值（11.07x）有小出入；FP4 对下游精度的影响尚未充分验证，仅在 H20 上测过。

大纲

大纲（全文已通读）

  • 瓶颈：RL 训练每步都要把权重从训练集群同步到推理（rollout）集群
  • 30B 模型、256 张 H20 上，同步一次约 8 秒，是训练步其他开销的 3 倍多
  • 目标：零冗余权重传输中间件——横向扩展、传输时间不随模型变大、总带宽随集群规模涨
  • 调研（第 1 周）：三套现有系统
  • Awex（蚂蚁开源）：按两侧并行与内存布局预先算好零冗余发送计划，每步复用
  • TensorHub（字节）：ROS 抽象，推理节点可同时从多个节点拉权重，P2P 式利用节点间闲置带宽
  • Mooncake TE：RDMA 传输后端，TensorHub 的引擎
  • 设计：控制面 + 数据面
  • 控制面学 Awex：发送计划算一次、反复复用；并行策略变了才重算
  • 数据面学 TensorHub 的流水线/P2P：每片权重只发一次
  • 发送计划覆盖 TP/DP/EP/PP/混合/分片张量并行六种切分
  • 8 步流水线：按推理侧并行切分权重 → 算每片归属 → 建计划 → 下发计划 → 推理侧备好接收缓冲 → 点对点发送 → 组装成本地布局 → 发完成信号
  • 实现（第 3 周）：两处关键优化
  • GPU 发起网络：基线是 CPU 编排的单通道 NCCL，CPU 与 host 拷贝卡在关键路径上；改用 NCCL device API（ncclDevSend/Recv、ncclGroupStart/End、cuda::barrier、grid 同步），kernel 每步启动一次、全程不回 host
  • 传输中量化：发送前 BF16→FP8→FP4，接收后反量化回 BF16；FP4 理论误差比 FP8 大约 10%，实测经 FP8 反量化后仅大 0.3%，字节数再减半
  • 评测（第 4 周）：256 张 H20，NVLink + RDMA，对比 veRL 的 NCCL 同步
  • Qwen3-30B-A3B：373.9ms vs 2953.6ms，7.90x；Qwen3-32B 3.64x；Qwen3-235B-A22B 10.34x；GLM-4.5-Air 10.99x；Kimi-K2-Thinking 11.07x
  • 端到端（Qwen3-30B-A3B，100 步）：20.4 分钟 → 3.5 分钟，5.8x
  • 扩到 512 节点：同步时间 373.9ms → 411.2ms，基本不涨
  • 结论与局限
  • 权重同步不再是 RL 训练的主导成本；论文 arXiv:2611.00646，代码 ShardFly（github.com/PACTHEMAN123/ShardFly）
  • 局限：反量化 kernel 尚未与后续计算融合；FP4 目前只用于权重；仅在 H20 上验证；FP4 对下游任务精度的影响未充分验证；文中 TL;DR（3.59–11.02x）与表格最大值（11.07x）有小出入
