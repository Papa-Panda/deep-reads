如何看待anthropic取消git？

知乎推荐流条目（21 个回答、约 19.7 万浏览）。所谓「取消 git」是 Anthropic 把自家 monorepo 从 Git 迁到自研的 Scion：AI Agent 把日合并量四个月内从约 2500 推到 3 万以上、主干历史涨到约 100GB、CI 每天约 2500 万次 checkout，Git 的分布式离线设计成了瓶颈。实质内容集中在第 5 高赞的 Kevin 回答（34 赞，唯一引用 Anthropic 官方博文《Redesigning source control at Anthropic》）：Scion 仿 Google Piper 与 Meta Sapling，服务端承担历史与合并、数据存 Spanner 与对象存储、无 packfile、分层缓存命中率 99% 以上，号称比 Git 镜像系统省 200 倍 CPU/内存、CI 省下 25% 算力。高赞前四条多是质疑与玩笑，需跳读。对他的价值在 Agent 时代的开发基础设施：当客户端几乎全是常在线的 Agent 时，基础设施要按 Agent 的规模重做——这正是 harness/infra 线的一手案例。

大纲

大纲（据问题页与高赞回答整理）

  • 事件本体
  • Anthropic 五个月内把内部 monorepo 从 Git 全量迁到自研系统 Scion
  • 触发量级：日合并约 2500（2026 年 5 月）→ 3 万以上（9 月）；主干历史约 100GB，压缩工作副本超 25GB
  • 为什么 Git 先撑不住
  • 实际用法是中心化单权威副本，但客户端几乎全是常在线的 Agent 与任务，Git 的离线/分布式设计成为扩展瓶颈
  • CI 每天约 2500 万次 checkout，朴素做法相当于每天 600PB 级流量；partial clone、稀疏检出、数百个内部镜像都顶不住
  • Scion 的设计（仿 Piper / Sapling）
  • 服务端做重活：历史、blame、提交、合并、变基都在服务端，客户端按需取数、只留有界缓存
  • 数据存 Spanner 与对象存储，不存在完整物化的仓库副本，没有 packfile、没有仓库维护
  • 一切皆 API：CI 可直接向服务端要 diff，免 checkout；检出走节点守护进程 → 区域缓存 → 权威服务端的分层缓存，各层命中率 99% 以上
  • 声称的效果与组织变化
  • 比 Git 镜像系统省约 200 倍 CPU/内存，检出从分钟级降到秒级，CI 省下约 25% 算力
  • 7 人团队五个月建成 Scion 及配套评审系统；全局锁合并队列改为合并后、部署前自动测试，由 Claude 修冲突
  • 争议与边界
  • 高赞前四条多为质疑：Linux/Chromium/AOSP 都用 Git、拆子仓库更合理、数字算法可疑——但都没读官方原文
  • 原文自承：Scion 不是通用 Git 替代，只对超大 monorepo 成立，且深度依赖自家评审/搜索/CI，难以移植
