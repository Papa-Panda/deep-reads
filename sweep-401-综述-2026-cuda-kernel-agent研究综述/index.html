大纲

1. 为什么 kernel 质量决定真实速度

  • 峰值 FLOPS 不等于落地速度；优化 kernel 每年全球省下数亿美元（粗估）
  • 高性能 kernel 与硬件代际、形状强绑定，手工调优不可扩展；编译器只搜人类设计的空间
  • LLM Agent 天然契合：生成 → 运行 → 验正确与速度 → 修改的迭代闭环
  • 开篇警告：正确 ≠ 更快——前沿推理模型（o1、DeepSeek-R1）一次生成在 KernelBench 上跑赢 PyTorch eager 的不到 20%

2. 任务如何定义：KernelBench 与 fast_p

  • 任务格式：给 PyTorch 参考实现，输出功能等价且更快的版本；250 题分三级（L1 单算子 100、L2 融合序列 100、L3 完整模型 50）
  • fast_p：既正确又快过阈值 p 的题占比；fast_0 即纯正确率；“正确但慢”和“快但错”都不给分
  • T0–T6 基线分层：T0 框架参考 → T4 生产 incumbent → T6 硬件上限；“10× vs T0”可能不如“1.1× vs T4”

3. 早期高分为什么塌了：基线公允性

  • 规模：v0 微秒级任务测的是启动开销，v0.1 统一到 1–15ms 窗口
  • TF32：基线打开 TF32 后 24% 的题快 1.5× 以上；GPT-5.5 几何均值加速从 1.43× 跌到 0.88×
  • 检查器漏洞：形状门控恒等捷径（ReLU 不计算直接返回）；KernelBench-Verified 用 4 种隐藏输入分布反制
  • METR 剔除 45 道无信息量题，新增 Level 5（DeepSeek-V3、Llama 3 等前沿工作负载）

4. 训练路线：SFT → 多轮 RL → Agentic RL

  • SFT（KernelLLM、ConCuR）：fast_1 仅 17%–22.2%，天花板低
  • Kevin：首个多轮 RL，n 轮轨迹拆 n 个样本、丢历史 CoT；Best@16 正确率 82%、加速 1.10×（仅 H200 定形状）
  • CUDA-L1：对比 RL，把执行时间反馈写进 prompt；三阶段 SFT→自监督过滤→GRPO，加速比 22.4%→66%→88.4%，A100 平均 3.12×
  • Dr. Kernel：治“懒优化”（正确但没真优化），KernelGYM + TRLOO + 画像奖励；14B 的 Level-2 fast_1.2 达 25.6%
  • CUDA Agent：整条 agentic 轨迹训练，Seed1.6，里程碑奖励；KernelBench 通过率 98.8%、几何均值加速 2.11×

5. 免训练框架：不训模型也能闭环

  • CudaForge：Coder/Judge 双角色，NCU 指标筛到每轮只看 3–4 个；250 题正确率 97.6%、平均加速 1.677×，单核成本约 $0.30
  • KernelEvolve：把优化当搜索（MCTS/进化），正确性为硬约束；480 个配置全部通过
  • KDA（MIT Han Lab / NVlabs）：Claude Coder + Codex Verifier，ncu-report-skill 与 KernelWiki；MLSys 2026 FlashInfer 竞赛三赛道胜出
  • GEAK：Generator/Reflector/Evaluator/Optimizer 四模块；知识注入 + Optimizer 后执行准确率 40.76%、加速 1.45×

6. 可信度：离硬件上限多远、猫鼠游戏与三轴地图

  • SOL-ExecBench：以 roofline 推导硬件下界，SOL Score 锚定基线 0.5、上限 1.0；与真实 headroom 回收相关性 r=0.981，原始加速比仅 r=0.10
  • Reward hacking 四类：根本没写 CUDA、计时攻击（多流异步）、惰性求值、改语义；CUDA-L1 早期 32.8% 的实现钻计时空子
  • 变异测试：官方检查器只杀死 83.1% 的可证错误，精度类漏检 78.6%；容忍带可达信号的 4000 倍
  • 收束：三轴地图（方法轴/基准轴/验证轴）+ 四问（任务类型、加速分母、硬件条件、检查器强度）；务实路线是 harness 工程 + 人在环路
