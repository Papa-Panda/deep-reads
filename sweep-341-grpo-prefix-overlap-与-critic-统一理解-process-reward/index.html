GRPO、Prefix Overlap 与 Critic：统一理解 Process Reward、Gradient Noise 与 Long-Horizon RL

haotian 把 ICML 2026《GRPO is Secretly a Process Reward Model》与 Scale Labs《To Critic or Not to Critic》两篇工作统一进一个框架：GRPO 靠同组 rollout 的共享前缀隐式得到蒙特卡洛过程奖励，Critic 则靠函数近似在无重叠处给出低方差 credit；小批量时 Critic 占优、大批量时 GRPO 追平，长 horizon 的 Agent RL 里二者都弱，作者主张 Critic 找节点、主动分支验证的混合路线。值得他看的是它把 GRPO/PPO 的取舍从经验之争变成可算的交叉批量公式与五条可检验假设，正撞 RL 配方与 Agent RL 主线。（作者 haotian，清华信通硕士；编辑于 2026-11-10）

大纲

大纲（全文已通读；haotian，清华大学信息与通信工程硕士；编辑于 2026-11-10；全文 25 节）

  • 核心问题：GRPO 与 PPO 到底谁更好，取决于什么
  • 两篇 2026 年工作放进同一框架
    • ICML 2026《GRPO is Secretly a Process Reward Model》：GRPO 只有轨迹级结果奖励，但同组 rollout 共享精确前缀时，其更新可严格改写成带蒙特卡洛过程奖励的目标
    • Scale Labs《To Critic or Not to Critic: GRPO vs PPO》：显式 Critic 主要降低策略梯度噪声，但不完美 Critic 的自举会引入方向偏差
  • 统一图景：GRPO = 无学习 Critic + 组内基线 + 精确前缀重叠诱导的隐式蒙特卡洛过程结构；PPO = 学习 Critic + GAE/自举 + 显式状态相关 credit 分配
  • 关键不在“有没有过程奖励”，而在蒙特卡洛过程信号 vs 学习/自举 Critic 信号
  • GRPO 为什么是隐式过程奖励模型
  • 组内优势 A_i = (R_i − R̄)/σ_R，token 级策略梯度对整条轨迹共享同一优势
  • 共享前缀是关键：同一前缀的轨迹在该 token 处梯度方向相同，贡献可合并为 N_s·A(s)·h，其中 N_s 为经过该前缀的轨迹数，V̂(s) 为经过前缀 s 的轨迹平均结果奖励
  • 二值奖励下 V̂(s) ≈ P(成功 | s)：GRPO 从不显式训练价值函数，但同组前缀树诱导出蒙特卡洛过程价值
  • 澄清：过程奖励 ≠ 进步奖励；GRPO 隐式给出 V̂(s_t) ≈ E[R | s_t]，真正的进步奖励是 V(s_{t+1}) − V(s_t)
  • 前缀重叠低时会发生什么
  • N_s 远大于 1 时 V̂(s) 是真正的蒙特卡洛平均过程奖励；N_s = 1 时退化为轨迹级结果信号
  • 严谨性提醒：不能简单说“低重叠 ⇒ GRPO 梯度方差一定更高”——隐式 PRM 是对原更新的重新解释，不是额外方差缩减估计量
  • 局部梯度信噪比：ν_s ∝ 1/N_s，后代越多、局部梯度信噪比越好（局部共享梯度近似，非全局证明）
  • Scale Labs 的 Critic vs No Critic 框架
  • 两个量刻画优势估计量：梯度对齐度 c（方向偏差）与梯度噪声尺度 ν；批量 B 下 E[cos] ≈ c / √(1 + ν/B)
  • 小批量（B ≪ ν）：噪声主导，PPO 的价值网络 + GAE 给出更细的状态相关 credit，ν_PPO < ν_GRPO，PPO 常胜（数学小批量、终端 Agent 在 B=128 时 PPO 明显领先）
  • 大批量：B→∞ 时对齐度成天花板；GRPO 避开 Critic 自举偏差，可追平甚至超过重自举 PPO（数学 B=1024 超过重自举 PPO；终端 Agent 在 B=2048 追平轻自举 PPO；horizon 越长/任务越复杂，交叉批量越大）
  • Critic 的本质：用偏差换方差；重自举 PPO 噪声低但对齐度可能低，轻自举 PPO 居中
  • 把前缀重叠与 Critic 统一起来
  • GRPO 的隐式过程奖励 V̂_MC(s) 像非参数蒙特卡洛 Critic，但只能在实际存在精确共享前缀的位置做平均
  • 学习 Critic V_φ(s) 可对 N_s=1 甚至从未重复的状态给出预测——这是真正的结构差异
  • 长 horizon 任务：深度 t 增加时 N_t 从 8 → 5 → 2 → 1 递减，深层隐式过程信号坍缩回轨迹级信号，Critic 仍可输出价值
  • Agent RL 更严重：工具调用一不同，环境观测立即分叉，后续上下文几乎必然分叉，N_t 快速趋向 1；GRPO 的隐式 PRM 主要存在于轨迹早期，而关键错误决策可能在深处
  • 交叉批量公式：B* = (c_P²ν_G − c_G²ν_P)/(c_G² − c_P²)；重叠越差的任务，GRPO 需要越大的批量才能匹配 Critic 版 PPO
  • 重要区别：批量 B ≠ 前缀后代数 N_s；盲目增大全局批量不等于增大局部过程样本量（B=2048 时深层状态仍可 N_s=1）
  • 三条路线与混合方案
  • 路线 A 纯 GRPO、增大全局 B：简单、无 Critic 偏差；但 rollout 贵、长 horizon 噪声高、深层 N_s 未必增加
  • 路线 B PPO/学习 Critic：小批量样本高效、无需精确重叠、长 horizon 尤其有价值；代价是 Critic 计算、误差与自举偏差
  • 路线 C 选择性树/分支采样：在重要状态主动提高 N_s，保留蒙特卡洛信号、少自举偏差、给真实局部反事实信息；代价是额外 rollout 与分支状态选择
  • 主动分支优于盲目增大 B：在状态 s_t 处主动分支（a_1, a_2, a_3 各自 rollout），直接控制 N_{s_t,a} = K_a
  • Critic 与主动分支可结合：Critic 回答哪些状态值得分支、哪些动作对结果最敏感、哪里样本太少、哪里梯度影响最大
  • 分支分配目标：U(s) ∝ [梯度重要性 × Critic 不确定性 × 可纠正性 / rollout 成本] × (1/N_s)，把有限分支预算投给 U 最高的节点
  • 最有前景的是混合：Critic 负责找节点（不确定/可纠正/高影响状态）→ 主动分支验证 → 蒙特卡洛分支 credit 做策略更新
  • 推荐监控的实验指标与可检验假设
  • 指标：前缀后代数 N_{i,t} 及其随 t 的曲线；共享过程比例 EPR；梯度噪声尺度 ν 及其与 N_t/EPR 的相关性；horizon 对比；每任务交叉批量 B*；Critic 误差/对齐度
  • 假设 H1–H5：前缀重叠越低、GRPO 局部梯度信噪比越差；长 horizon 的主要困难之一是深层状态 N_s→1；低重叠任务中 PPO/Critic 的小批量优势更明显；低重叠 ⇒ 交叉批量 B* 更大；同等 rollout 预算下，有针对性的分支优于盲目增大独立组大小
  • 最终统一结论：GRPO 用采样获得局部信息，PPO 用函数近似获得局部信息；前者低偏差、高方差潜力，后者低方差、高偏差潜力
