当 Agentic RL 训练，遇到长上下文压缩

喔喔喔（2026-11-22）从 RL 前缀一致性出发，讲清 Agentic RL 长轨迹触发上下文压缩后为何不能再把整条轨迹拼成一个训练样本：按压缩边界切分、优势广播到各段、摘要生成本身也要进 loss（CompactionRL 实测 +2.3pp），并给出 Gateway 采集轨迹树的工程实现。Agent RL 训练与上下文压缩的硬核工程拆解。

2026-11-26

原文链接：https://zhuanlan.zhihu.com/p/2107938229118842397

大纲

1. 背景：长任务逼出上下文压缩

  • Agent 任务常需数百轮，每轮追加模型推理、工具返回与报错日志，1M 上下文也不够
  • 工程做法：接近预算时把早期交互摘要成 summary，保留系统提示、任务描述与最近若干轮原文，继续执行
  • 核心问题：压缩替换了前缀，轨迹不再是连续序列，训练必须正视压缩

2. 为什么无压缩时“整条轨迹当一个样本”是成立的

  • 一条轨迹 = 一个训练样本，一次前向 + loss mask（模型生成部分为 1，其余为 0），一个 reward 训多轮决策
  • 前提是前缀一致性：Agent 上下文只追加不改写，因果注意力下 m3 看到的仍是推理时的真实前缀
  • RL 的关键要求：训练前缀必须与推理时前缀逐 token 相同

3. 压缩如何破坏前缀一致性

  • 压缩后 p1..x4 被改写成新的起点 p1'，后续采样的前缀与原始轨迹无法对齐
  • 结论：含压缩的轨迹在概率意义上断成两段，不能硬拼成一条训练序列

4. 主流方法：三个问题

  • 奖励分配：优势广播（ReSum-GRPO，整条 rollout 的优势分给各段）；ContextPilot（按片段重采样、片段奖励取均值再标准化）；CompactionRL（PPO + GAE，按后段可训 token 数折扣前段优势）
  • 损失聚合：各段在各自真实前缀下分别算 logprob 与概率比 ρ，进入 GRPO clip 目标；batch 总损失按 rollout 平均 vs 按有效 token 平均，权重不同
  • 摘要本身训不训：只当输入 vs 计入 loss；CompactionRL 实测：训摘要生成，SWE-bench Verified 200 题 Pass@1 64.5% → 66.8%（GLM-4.5-Air），+2.3pp

5. 工程实现：Gateway 采集完整轨迹树

  • Agent 与 vLLM 之间加 Gateway，每次调用按 TITO（Token-In / Token-Out）记录 token ID 与采样 logprob，挂到 rollout_id 下的轨迹树
  • 前缀匹配：匹配则只追加新尾巴；失配（压缩后的首个请求带 p1'）则开新分支
  • rollout 结束：每条根到叶路径展开成一个训练段（同 rollout_id + batch_id，含完整 token 序列、loss_mask、logprob），分别入队；也可用于 SFT
  • 训练：按 batch_id 取 rollout，按 rollout_id 分组算优势；每段在其真实前缀下重算 logprob → 概率比 → clip 损失 → 聚合更新

6. 结论与设计建议

  • 按压缩边界切分，不硬拼；摘要生成本身应进 loss；优势方案与损失聚合方式都是设计决策
  • 段内须完整保存 prompt、工具返回与摘要，保证训练与推理前缀一致
