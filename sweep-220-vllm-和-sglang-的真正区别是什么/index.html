vLLM 和 SGLang 的真正区别是什么？

知乎推荐流条目（149 人关注、约 8.3 万浏览、16 个回答；已通读问题页与默认排序前 5 个高赞回答）。提问先纠偏：vLLM 并非只有 PagedAttention、从不复用前缀，它有块级链式哈希前缀缓存；真正的老差异在 KV 复用粒度——vLLM 整块复用（默认块 16 token、末块不可用），SGLang 基数树可按 page 1 精确匹配并在部分命中时分裂节点。前 5 个高赞回答的共识是两家已大幅收敛、互相借鉴：feed 推荐答案 BBuf（101 赞）认为框架层差异将尽、性能领先只是时点问题、开源框架没有护城河，真正风险是 Agent 时代的代码可维护性；最高赞 WingEdge777（348 赞）认为粒度差对长上下文首 token 时延影响很小、主要经调度放大，并明确 2026 年生产环境选 vLLM（多模态更稳、Day-0 支持快）。另一高赞给出的命中率与单请求 +17% 等数字均为单篇声称、无基准出处，慢读时需打折看。

大纲

大纲（据问题页通读整理：问题描述 + 默认排序前 5 个高赞回答）

  • 条目信息
  • 149 人关注、约 8.3 万浏览、16 个回答；话题含 AI infra / 大模型推理 / vLLM / SGLang
  • 提问前提：质疑「SGLang 靠前缀树复用、vLLM 只会重算」的流行说法；提问者读过 nano-vllm（链式哈希缓存）与 mini-sglang（前缀树）后问差距是否其实很小
  • 老差异：KV 复用粒度（WingEdge777，348 赞，最高赞）
  • vLLM：块级链式哈希，整块命中才复用，默认块 16 token；末块因需末 token 的 logits 只能缓存 n-1 个 token
  • SGLang：基数树，默认 page 1，可精确匹配至 n-1，部分命中时分裂节点；更优雅，但分裂、驱逐与分级缓存的维护成本更高
  • 粒度差的实际影响：长上下文下几个 token 对首 token 时延几乎无感（双方同为显存带宽受限），更大的影响在调度——多一次独立 prefill 会打断 decode
  • 经典对照与它的简化（大龄爱码士，38 赞）
  • PagedAttention 管显存如何分配，RadixAttention 管缓存如何复用（树加 LRU、调度优先长前缀请求）
  • 其「vLLM 用完即弃、共享前缀全重算」的说法被其他高赞与提问本身纠正：vLLM 有前缀缓存，只是粒度粗
  • 其碎片浪费下降、场景命中率与单请求 +17% 等数字均为单篇声称、无基准出处
  • 共识：已经收敛
  • BBuf（101 赞，feed 推荐答案）：上下层调度与内核趋同，性能领先互相轮换、非技术鸿沟，开源框架没有护城河；真正风险是逐模型改造若无人把关，约半年代码即不可读，Agent 自动清理达不到其标准；此答案未展开 Radix 细节，也未给选型划分
  • Starduster（32 赞）：真正的差异是社区与生态——能触达的人、贡献的公司、谁来审合并你的修复；2025 年后功能差基本消失，自研引擎难点在模型与特性组合爆炸和逐版修 bug；两家问题区都被 AI 生成噪声淹没
  • Luminol（22 赞）：差异主要是设计哲学——vLLM 偏重、偏系统与稳定，SGLang 偏轻、偏运行时原生；前缀缓存、分块 prefill、PD 分离、投机解码、结构化输出均已互相借鉴
  • 选型分歧（2026 口径）
  • WingEdge777：生产选 vLLM——已去掉 Ray、多模态/VLM 更稳（SGLang 多模态曾有显存泄漏与精度不一致）、Day-0 模型支持快、bug 少；nano/mini 小实验两者皆可
  • 其余三位基本中立：选型看社区可达性与可维护性，而不是能力差
