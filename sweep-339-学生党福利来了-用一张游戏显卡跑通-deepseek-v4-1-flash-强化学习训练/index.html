大纲

大纲（全文已通读，remaper，2026-11-13；作者自述尝鲜意义大于实际、未经严格测试）

  • 目标：一张 24GB RTX 4090 跑通 DeepSeek V4.1-Flash 的完整 GRPO 循环
  • 原模型 476GB（路由专家 276GB + engram 查找表 189GB），正常需多机多卡
  • 成果：SGLang rollout 权重占 19.46GB，Megatron 训练峰值显存 9.8GB；每步 64 条轨迹，LoRA 合并后 SGLang 热换 0.5s；约 15–20 分钟/步；16 道固定 GSM8K 题奖励 0.72→0.83（10 步内）
  • 四招
  • 只答数、不推理：每步前向 10–13s（专家按需从磁盘读），每多一个 token 就多一次前向；提示词追加只答最终数字、关闭思考模式、每条轨迹最多 6 个 token；只留 ≤200 字符的 GSM8K 题（7473 道留 3166 道）；奖励严格到 0/1（去空格逗号后须为单个数字且等于答案）；回复平均 2.6 个 token
  • 剪枝专家：每层 384 个路由专家、每 token 激活 6 个；按训练提示词统计各层路由频率，每层只留 Top 64 并剪掉对应 gate 行（FP4 权重顺带反量化）；架构不变（超链接、压缩稀疏注意力、engram 全保留）；剪后 checkpoint 94GB
  • 磁盘当显存：专家留在文件里（SGLANG_FILE_EXPERTS），每层显存只留 6 个专家槽位，按 safetensors 字节偏移按需读（主机内存不存副本，靠 OS page cache 缓存热点）；engram 表也在文件里，每次前向并行 pread 所需行并在 GPU 上反量化
  • 流式训练：meta 设备上建完整 Megatron 模型（不占显存），只分配一个 4.84GiB 显存池、各层以视图共享，用 hook 在前向/反向时逐层从磁盘加载权重；可训练部分是最后 4 层 dense 模块的 LoRA（r=16，449 万参数），Adam 状态可忽略
  • 两个坑
  • FP8 静默吃掉 LoRA 更新：LoRA 合并进 FP8 serving checkpoint 后，SGLang 只重载 48 个变化张量；奖励上升但训练/推理 log-prob 发散。四向 log-prob 对比锁定是重量化：LoRA 增量仅为权重的 0.6%–1.2%，而 E4M3 相邻可表示值差约 12.5%，大部分增量被舍入丢掉。解法：每层 LoRA 前向加不可微残差修正 residual = (dequant(quant(W+BA)) − (W+BA)).detach()，前向用量化权重、梯度直通 LoRA；训练/推理 log-prob 差从 0.178 降到 0.022。教训：推理用低精度权重时，LoRA 合并可能悄悄丢掉大部分更新
  • V4.1 算子在 4090 上跑不起来：FlashMLA 切便携路径；TileLang indexer 与稀疏 MLA 核按 SM89 的 99KiB 共享内存重排（block_N=64、2 stages）；无 MXFP4 核时 FP4 专家反量化成 FP8，MoE runner 块尺寸改 128×128
  • 复现与边界
  • 代码在 LoongSage coda/custom/dsv41_4090/（reward.py、patch.py），全靠 monkey-patching、零侵入框架；建议磁盘 ≥600GB；作者机器内存很大（page cache 用到数百 GB），小内存机器速度未测；不是全参 RL（最后 4 层 LoRA + 剪掉 5/6 专家）；任务极小（GSM8K 只答数、≤6 token、16 道固定题），证明的是完整循环能跑且训练推理一致，不是训出了更强的 DeepSeek；路由统计脚本尚未进仓库
