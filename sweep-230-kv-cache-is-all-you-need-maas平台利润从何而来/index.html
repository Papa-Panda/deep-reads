KV Cache is all you need——MaaS平台利润从何而来？

知乎推荐流专栏（作者沈墨，2026-10-20 发布于广东；读时 31 赞同、33 收藏、3 评论。已通读原文）。作者先修正自己 4 月旧文的两处错误——忽略了 Blackwell/Rubin 的代际效率、漏算了 KV Cache 命中收入——再用一个自设模型算账：单机月成本 10 万元、满载输入 36000 tok/s、无缓存时月营收约 17.9 万元；命中率 80% 时命中收入新增约 20 万元/月，总营收约 37.8 万元；90% 的现实情景下命中收入约 35.9 万元，超过其余全部收入两倍。结论是 MaaS 利润的大头藏在 KV Cache 命中率里，Coding Agent 的竞争本质也是命中率。注意：作者明说细算数字是现编的、只有计算框架可参考，评论区有人质疑重复计费、作者已回应——当成本模型框架读，别当实测数据。

大纲（据原文通读整理）

  • 条目信息
  • 知乎推荐流专栏，作者沈墨（深圳湾区码农），2026-10-20 发布于广东；读时 31 赞同、33 收藏、3 评论
  • 全文无小标题，结构为：纠错 → 降本清单 → 无缓存基准模型 → 加缓存三档情景 → 保留意见与评论交锋
  • 起点：修正旧文两处错误
  • 忽略 Blackwell/Rubin 代际：B300/Rubin 的推理效率远高于 Hopper 代
  • 漏算 KV Cache 命中收入：作者 5 月得出的核心判断——优化性能、提负载、拉长高负载时段，都不如提高命中率
  • 正统降本手段（命中率之外）
  • infra 性能优化、提高实例负载、夜间折扣拉长工作时段、浸没液冷降 PUE、算电协同与绿电、补贴
  • 基准模型（作者自设参数，非实测）
  • 单机月运营成本 10 万元；满载输入 36000 tok/s、输出 8600 tok/s；定价：未命中输入 8 元、命中 2 元、输出 28 元（每百万 token）
  • 无缓存：日等效满载 8 小时、输入输出比 7:1，月营收约 17.9 万元，打七折仍有约 2.5 万元利润
  • 加上 KV Cache 的三档情景
  • 命中率 80%：命中 token 按 1/(1−0.8) 放大，命中收入新增约 20 万元/月，总营收约 37.8 万元
  • 命中率 99%（思想实验）：命中收入近 400 万元/月；作者自注 DeepSeek 也只有约 96%，且命中并非零成本
  • 命中率 90%（现实情景，含额外内存/NVMe 与研发成本、TPS 降 10%）：总营收约 52 万元/月，命中收入约 35.9 万元、超其余收入两倍
  • 保留与争议
  • 定价取 GLM 5.2/5.3 口径、GPU 按年初 H200 价格五年摊销；能否真跑到该 TPS 与命中率取决于 infra 与运营能力
  • 评论区质疑输入 token 已包含命中部分、存在重复计费；作者回应其『输入』指实际参与 prefill 计算的 token
