从 verl 与 slime 最近两个月的更新，看 RL 基础设施的演进，以及 DeepSeek V4.1 Flash 的支持现状

讲 verl 与 slime 近两个月更新的对照复盘：两大 RL 框架正收敛为“连续流训练系统”——异步调度、版本窗口、量化/路由一致性、token 级轨迹语义、权重快速切换与跨故障恢复成为标准组件；并分层核查了 DeepSeek V4.1 Flash 的支持现状，指出推理已支持但主线尚无稳定可验证的完整 RL 训练方案。值得他看的是它把 RL infra 的演进从功能清单还原为“控住偏差/故障成本与有效策略更新”的系统设计问题，且对 Miles 分叉报告的未核实点做了明确标注，正对后训练主线。

大纲

  • 立论：verl 与 slime 的共同方向
  • 同时控住两类成本：可控的偏差/故障成本 与 有效策略更新
  • 样本→训练的边界从“生成”移到“策略版本控制”
  • 训练从静态批系统走向带故障恢复的连续流系统
    1. 版本对齐：五个共同问题
  • verl v0.9.1（2026-09-20）与 slime v0.4.0（2026-10-09）
  • 异步调度、数据新鲜度、训练一致性/量化、数据 token 语义、权重/缓存切换
    1. 异步调度与数据新鲜度
  • verl 异步 rollout（vLLM colocated 模式，长序列多轮场景 3–5×）
  • slime 动态采样；陈旧度量：off-policy 版本漂移、stale step、stale sample rate
  • 解法：混合调度 + 版本窗口
    1. 训练/采样一致性作为系统接口
  • NVFP4 量化对齐；MoE R2 路由回放
  • Score Centering：verl 标准化 advantage，slime 标准化 reward（baseline + 样本标准差，GAE λ=0.9），最终都落在标准化的 advantage 上——跨框架结果不可直接比
  • top-p 回放保证采样一致性
    1. Agent 训练的数据 token 语义
  • verl Continuous Token：agent 回合边界、token 级 loss、 标 episode 结束、多轮训练
  • slime 流式 rollout：token 流、episode 截断、loss masking
    1. 权重/缓存/版本切换
  • 分片增量同步、磁盘增量更新、PipelineRL 的 KV-cache flush
    1. 跨故障持久化
  • slime straw 框架：跨故障持久化、回滚、恢复服务；verl Q4 路线图
    1. DeepSeek V4.1 Flash 分层判断
  • 身份：V4.1-Flash vs V4-Flash、初始版 vs 1017 版
  • 架构：Causal Encoder-Decoder、跨层共享压缩 KV、分层稀疏索引、mHC、Engram、视觉能力
  • 支持现状：vLLM/SGLang 推理已支持；verl 主线有方向但无稳定可验证的完整 RL recipe；slime 主线证据不足；Miles 分叉报告（16×GB300 DAPO 多步 RL）但多处未核实
    1. 启示：五个方向与三类建议
  • 调度、数值、轨迹、更新、恢复；给研究者、贡献者、用户的分别建议；三个待观察结果
