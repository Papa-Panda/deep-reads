FP8 预训练与中训练的 Train Loss 系统性比 BF16 高 5%该怎么办？

知乎提问：FP8 预训练/中训练的 Train Loss 为何系统性比 BF16 高 5%？主答（附 114 篇文献）把 5% 差距拆成前向容量损失、反向梯度漂移、主权重停滞三项，用六大机制（块缩放取整、FP22 累加、SwiGLU 爆炸等）逐一定位并给出五步诊断法与 <0.25% 验收线；第二答补了公平对照清单与 A–F 消融方案。值得他看的是它把 FP8 训练的精度账从经验之谈变成可复现的诊断流程，正撞训练优化主线。注：5% 指 loss 差距而非数学推理能力下降 5%（推荐流标题有误，页面实际标题已采用）。

大纲（全文已通读；问题页 2 个回答，2026-11-12；注：页面实际标题与推荐流标题不同，5% 指 loss 差距而非数学推理能力下降 5%）

  • 核心现象：FP8 预训练/中训练 Train Loss 系统性比 BF16 高约 5%
  • 训练不崩：无 NaN、梯度范数无尖峰、吞吐 +30% 以上
  • 但 train/val loss 系统性高约 5%（ΔL ≈ +0.12 nats）；按 Chinchilla 换算约浪费 35–45% 算力与 token
  • 澄清：loss 2.00→2.10 对应 PPL 高约 10.5%，不是能力下降 5%；合格线是相对 loss 差距 <0.25%
  • 差距的统一分解：三项正交来源
  • ΔL_rep：前向有效容量损失
  • 反向一阶梯度收缩 / 有偏漂移
  • ΔL_stall：主权重与优化器二阶矩停滞下限
  • 六大机制（按 loss 曲线“指纹”诊断）
    1. MXFP8 块缩放向下取整饱和：OCP 公式 floor(log2(amax/448))，峰值被钳在 448；改 ceil；另有延迟缩放失配与敏感层误量化
    1. Hopper Tensor Core FP8 累加仅约 14 位（“FP22”）：单次 K=4096 GEMM 最大相对误差约 2%；per-tensor 离群值淹没（1000 量级 vs [-5,5]，SQNR 掉 >15 dB）；解法：激活 1×128 / 权重 128×128 在线缩放 + 每 128 元 FP32 提升部分和
    1. 前向/反向转置双重量化：Dgrad 误用 128×128 块量化（DeepSeek-V3 附录 B.2：16B MoE 约 300B token 处退化发散）；MoE“反量化-转置-再量化”（FP8-Flow-MoE，12 次 cast → 2 次）
    1. SwiGLU 二次对齐爆炸（约 200B token 后）：输入 30 变成约 900 离群值；Smooth-SwiGLU、TWEO（Top-1 激活 10410 → <20）、Muon + Single-Scale RMSNorm
    1. FP8 Attention Stale-Delta 破坏 Softmax 零行和不变量（Delta-Matching，每行残差 1.1e-2–4.7e-2）；因果/文档边界块缩放泄漏（FLAMIA）
    1. 主权重 / Adam v_t 在 LR 退火期停滞：BF16 ULP 7.8e-3、FP8 ULP 0.125，小于 ½ ULP 的更新归零；ECO、COAT、随机舍入 + 周期性优化器状态重置
  • 合格标杆：DeepSeek-V3、InfiR2（Qwen2.5-1.5B/7B 中训 160B 数学/代码 token）、NVIDIA Blackwell MXFP8（8B、15T token）；连 NVFP4/MXFP4 也只做到 0.2–0.9% 差距
  • 诊断与验收：五步正交二分法（0 步前向探针 >0.5% 即前向问题；Fprop/Dgrad/Wgrad 500 步消融；硬件累加器/块大小检查；SwiGLU/Attention/通信检查；主权重/优化器停滞检查）；验收：相对 loss 误差 <0.25% 且斜率平、梯度余弦 >0.99、范数比 [0.98, 1.02]、中位 |ΣdS| <1e-4、停滞率 <5%；长尾事实探针：0.5% loss 差距下稀有事实需 1.32–1.52 倍曝光
  • 回答 2 的实用补充：先别调 LR，先查量化策略/缩放/反向梯度精度；公平对照清单（同初始化、数据顺序、AdamW、全局 batch、高精度 loss 计算）；消融 A–F（优先 C：FP8 前向 + BF16 反向 GEMM；D：Current Scaling）；性价比按“达到同等验证质量的时间”算，不按原始吞吐（示例：1.5× 吞吐、1.2× token → 有效加速 1.25×）
