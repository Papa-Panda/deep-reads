Loop / Graph Engineering

澄清三个易混概念：Loop 是运行时控制结构，Graph 是控制流的显式表示，Engineering 是让循环可靠的整套系统；覆盖状态、条件边、终止预算、恢复、幂等、人工介入、Trace 与评估，附状态机代码骨架、六类常见误区与是否需要 Graph 的五问自测。

大纲

三个概念的区分

  • Loop：运行时控制结构，while、重试、反思循环都是 loop
  • Graph：控制流的显式表示，节点与边把流程画出来
  • Engineering：让循环在生产环境可靠的整套系统
  • 混淆三者是大多数 Agent 故障的根源

核心机制

  • 状态：循环每次迭代携带什么记忆，状态放哪里
  • 条件边：满足什么条件走哪条边，判断逻辑归谁
  • 终止预算：最大步数、时间上限、token 上限，三者缺一不可
  • 恢复：失败后从哪里继续，重放还是续跑
  • 幂等：重试安全的设计，同一节点跑两次结果不变
  • 人工介入：什么情况下升级给人，升级时带什么上下文

可观测性与评估

  • Trace：每一步的输入输出留痕，可回放
  • 评估：循环是否收敛、是否发散、成本多少

状态机代码骨架

  • 最小可运行的状态机示例：状态定义、转移函数、预算检查
  • 代码为示意，无后端

六类常见误区

  • 把 Graph 当银弹：图只是表示法，不解决可靠性
  • 循环无预算：无限反思烧掉所有 token
  • 状态到处泄漏：隐式状态导致不可复现
  • 条件边写死：环境一变就走错分支
  • 无人工兜底：关键决策无人把关
  • 只测 happy path：异常路径从没跑过

五问自测

  • 五个问题判断你的任务是否真的需要 Graph，还是普通 loop 就够

流程图
