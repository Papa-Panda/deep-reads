Pi-Agent源码解析四_上下文压缩Compaction

以 pi v0.83.0 源码为据，讲 Agent harness 的上下文压缩 Compaction：何时触发、如何把当前路径切成三段、摘要如何生成、又如何只追加一条 compaction 节点回填 Session 树。值得他看的是它把长会话上下文管理拆成触发、切点合法性、分段 turn 处理与滚动摘要四个可复用的机制，正对 Agent infra/harness 这一优先方向。

大纲

大纲

  • 问题：上下文只增不减
  • Session 树每次落一条消息，请求前沿叶回溯成上下文
  • 大工具输出（如大文件回读）最容易把上下文推向窗口上限
  • 触发：harness 只给手动入口，时机归 host
  • compact() 仅 idle 可调用，压缩中拒绝 prompt/skill 调用
  • 阈值：当前 token 数超过窗口减 reserveTokens（默认 16384）
  • 估算：以最后有效 assistant 消息的 provider usage 为准，其后按字符粗估
  • 切分：prepareCompaction 是纯函数，不调模型
  • 边界：只处理上次压缩之后的部分，旧摘要作 previousSummary 滚动更新
  • 切点：从尾向前累积到 keepRecentTokens（默认 20000）附近，toolResult 永不能作切点
  • 分段 turn：切在 assistant 消息上即为 split turn，需另给一段 turn 前缀摘要
  • 三段：待摘要历史、turn 前缀、原文保留尾巴 retainedTail
  • 产物：摘要 + 文件清单 + 保留尾巴
  • 历史摘要与 turn 前缀摘要分两次调用，格式固定（目标、约束、进展、决策、下一步）
  • 文件清单直接取自 toolCall 参数，不靠模型总结，不会丢
  • hook 可取消或接管：session_before_compact
  • 回填：只追加一个节点，不删旧节点
  • 新 compaction 节点挂在当前叶下，叶指针前移
  • 下次 buildContext 回溯到该节点即停，读摘要 + 保留尾巴 + 新问题
  • 再压缩时只读“上次摘要 + 此后内容”，摘要滚动前进
