RL 修炼第一弹： 一个 step 都有什么

大海无量把一个 RL 训练 step 拆成采样—打分—算优势—前向—更新五步，讲清四种 logprob 的分工、重要性采样 ratio 的来历、GRPO 用组均分省掉 critic 的代价，以及 off-policy 拿稳定性换吞吐的权衡；后训练 RL 的入门实战手记。

原文链接：https://zhuanlan.zhihu.com/p/2093781927924863303

大纲

1. 一个 step = 五步走，转圈循环

  • RL 与 SFT 的根本差别：数据是模型自己现产现销的，“自产自销”是 RL 一切麻烦的根源
  • 五步：采样 Rollout → 打分 Reward → 算优势 Advantage → 前向 Forward → 更新 Train，权重同步后采下一批

2. 四种 logprob：采样 1 份，训练侧 3 份

  • logprob 是唯一可求导、可推高推低的量
  • rollout_logprob（推理引擎采样时）、old_logprob（训练前向重算，概率比的分母）、ref_logprob（冻结参考模型，算 KL 防漂移）、new_logprob（每次更新重算，概率比的分子）
  • 为什么重算 old：采样与训练是两个引擎，算出的概率对不上

3. 重要性采样：旧数据为什么还能训新模型

  • ratio = π_new / π_old = exp(new_logprob − old_logprob)，新模型更喜欢的 token 权重更大
  • 比值过大要 clip；这也是 off-policy 数据可复用的数学依据

4. GRPO 为什么不要 critic

  • PPO 的 Critic 与主模型一样大，又耗显存又耗算力
  • GRPO 用同题一组答案的均分做基线，优势 = 比组内平均高多少，省掉整个价值网络
  • 代价：每题要采够多答案，组均值才准

5. 一题多采不是浪费

  • 两个原因：组内基线需要多个答案；单样本噪声大，采样 8/16 个取平均才可信
  • 组大小是超参：太小基线不准，太大浪费采样时间

6. 常见疑问：RL vs SFT、on/off-policy

  • SFT 是“抄答案”，RL 是“对答案”：没有标准答案，只告诉好不好
  • 严格 on-policy 干净但浪费；实战偏 off-policy 一点，采样训练并行、复用略旧数据，吞吐大涨，代价是稳定性

流程图

graph TD A[一个 RL step：模型自己答题，自产自销] --> B[① 采样 Rollout：一批题，每题答多次] B --> C[② 打分 Reward：每个答案给个分] C --> D[③ 算优势 Advantage：比同题组内平均高多少] D --> E[④ 前向 Forward：重算 old/ref/new 三种 logprob] E --> F[⑤ 更新 Train：优势推高好答案概率，改参数] F --> G[权重同步：新模型送回采样，采下一批] G --> B D --> H[GRPO：组均分做基线，省掉 Critic] E --> I[重要性采样 ratio = exp(new_logprob - old_logprob)] I --> J[旧数据可复用，但比值过大要 clip] F --> K[偏 off-policy：用稳定性换吞吐]
