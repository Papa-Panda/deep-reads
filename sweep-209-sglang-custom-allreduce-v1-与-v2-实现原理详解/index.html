SGLang Custom AllReduce v1 与 v2 实现原理详解

知乎推荐流条目（作者 BBuf，编辑于 2026-07-27，56 赞、87 收藏）。源码级拆解 SGLang 自研 Custom AllReduce：TP 下每层两次 all-reduce、decode 单条消息仅约 16KB，瓶颈是固定开销而非带宽，NCCL 的环形多步与协议选择太重。v1（源自 vLLM）用 IPC 共享缓冲区 + Signal 双相计数 barrier，含 1stage 全读归约与 2stage 分片两档；v2 是 SGLang 自研重写（存算分离、阈值改实测调优表），新增 1shot_push 用数据本身的 +0.0 位模式作到达哨兵、彻底去掉跨卡 barrier，并有 NVLS 交换机硬件归约与 PDL 重叠。正对他的推理优化与 CUDA 底层主线。注：已通读原文（更正：本条初版摘要的作者/日期/赞藏数与一处 bug 说法有误，已按原文核实修正）。

大纲

大纲（据原文通读整理，已核实修正）

  • 问题：小消息、高频次的固定开销
  • TP 下每层至少两次 all-reduce，层数乘起来每步数百次；decode 消息极小（bs=1、hidden 8192、bf16 约 16KB）
  • NCCL 为大消息设计：环形需 2(ws-1) 步、协议选择与 proxy 逻辑、CUDA graph 下参数块成本，累积到毫秒级
  • 前提收窄：单机全 NVLink P2P、world_size ≤ 8、消息不超过 workspace 上限；先经 cudaIpcOpenMemHandle 交换地址
  • v1（移植自 vLLM）：共享缓冲 + 计数 barrier
  • 每 rank 预置 Signal 同步区、转运缓冲与预注册输入缓冲，图模式用 RankData 指针表延迟注册
  • 同步：Signal 的 self/peer 双相计数器，peer_counter 两相交替防覆盖；entry 只需到达语义（volatile），exit 需 release/acquire 内存序保证数据可见
  • 两档 kernel：1stage 每卡读全部副本本地归约（流量 ws×N，省一轮同步）；2stage 为 reduce-scatter + all-gather（流量约 2×N，多一次带 fence 的同步）；按 ws 与 512KB/256KB 阈值硬编码切换，上限 8MB、超出回退 NCCL
  • v2（SGLang 自研重写）：存算分离与分级算法
  • 存储由 Python 侧对称内存 workspace 统一持有，C++ kernel 成纯函数；JIT 按 (dtype, ws, PDL) 编译，阈值全变 Python 侧可调数据
  • 1shot_push（v2 新增）：发送方把数据写进所有 rank 的 push 槽，接收方轮询本地槽；以 +0.0 位模式为「空槽」哨兵（真 +0.0 先改写为数值等价的 -0.0），无跨卡 barrier，延迟下限是一次 NVLink 写加一次轮询命中
  • 1shot_pull 与 2shot_pull：128B Semaphore 同步；2shot 第二阶段把归约结果原地写回所有 workspace，all-gather 融进写回
  • NVLS multicast 变体：交换机做 ld_reduce 硬件归约；PDL 让后继 kernel 与前任尾部重叠
  • 选算法靠 per-(架构, ws) 实测调优表分 graph/eager 双轨；workspace 默认 16MB 上限，长尾大消息交回 symm-mem/NCCL
  • 正确性契约
  • 两代都固定按 rank 0..ws-1 顺序累加、指针不按距离重排，保证跨 rank 位一致，避免 ULP 差异逐层放大导致采样分叉
