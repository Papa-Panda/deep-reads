LLM的MoE架构的“动态路由”为什么能训练出来？

知乎推荐流条目（白露未晞me，2026-10-15发布，53赞、71收藏；问题9475浏览、7个回答）。用第一性原理加可运行代码回答一个关键问题：MoE 的 argmax 路由不可微，路由器为什么还能被训练出来。核心推导是梯度仍经保留的 softmax 概率回流、且分母含全部专家使未选中专家也收到梯度；再用重要性损失与 Top-1 负载均衡损失解决专家塌缩。对他正对口：MoE 稀疏化、路由梯度与均衡损失的机制讲透，正是后训练与大模型架构的基本功。注：已通读该回答全文要点。

大纲

大纲（据知乎推荐回答整理）

  • 问题设定
  • token 表示与专家函数、路由器 logits 与 softmax 概率如何定义
  • 动态路由的疑问：选择是离散的，为什么还能学
  • 软路由的梯度
  • 输出是专家输出的加权和
  • 每个专家 logit 的梯度取决于它的输出比混合平均好多少
  • 硬路由 Top-1 为什么也可训
  • 选中专家固定的一段区域内，梯度经保留的 softmax 概率回流
  • softmax 分母包含全部专家，未选中专家的 logit 也收到梯度，下一轮前向可自然改派
  • 负载不均衡与均衡损失
  • 软路由易把概率质量集中到少数专家，Top-1 易使 token 计数失衡
  • 用路由概率的变异与 token 占比构造均衡损失并求梯度
  • 总目标与代码
  • 任务损失加均衡损失后反向传播，附 PyTorch 的 MoE 模块与均衡损失实现，实践中无需手推梯度
