推理优化：把 MoE 的 dispatch 与 combine 搬进交换机（INC-MoE）

华为 INC-MoE 论文精讲：把 MoE 推理的 dispatch/combine 搬进交换机，利用网内 AllGather 收重、ReduceScatter 发重的互补让两者同时在飞，OLMoE-1B-7B 上 TTFT 最高降 33%；正撞推理优化与通信主线，作者的七条自我批判（模拟交换机、只有 prefill、未开源）同样值得看。

大纲

大纲（全文已通读；Arthur，芯片公司 AI Infra 工程师，2026-10-29；精讲华为 INC-MoE 论文 arXiv:2610.36339）

  • 问题：MoE 推理的通信瓶颈
  • 每层 dispatch + combine 都在关键路径上，跨节点带宽远低于节点内
  • vLLM 默认路径三段串行：AllGather → 专家计算 → ReduceScatter
  • 环形集合通信天生对称：单条已占满双向链路，重叠 AG 与 RS 省不了时间
  • 刻意取舍：用 AG/RS 代替 all-to-all，只多传约 9%，换来与路由无关的规整通信模式
  • 关键洞察 1：网内 AG 收重、网内 RS 发重，可以同时跑
  • 网内 AG：每 rank 只发 S/N，收 (N-1)/N·S；网内 RS：发 (N-1)/N·S，只收 S/N
  • 各自单独跑与环形一样快；并发时每方向只传 S 字节，理论节省 (N-2)/(2(N-1))：N=4 时 33.3%，N=8 时 42.9%，趋近 50%
  • 前提 N≥3；N=2 时无增益，只适合多节点 scale-out
  • 关键洞察 2：只卸载不够，AG 与 RS 必须同时在飞
  • 同层内 AG 与 RS 严格依赖：分 band + 融合成一个 persistent kernel，三类 thread-block（gather / compute / reduce）各司其职
  • 稳态三 band 齐飞：gather 发 j+1 的 AG、compute 算 j 的 FFN、reduce 做 j-1 的 RS
  • 工程要点：bit-exact 的 band 边界、按 Tmax 填充的布局、单调递增计数器 + epoch 的完成信号、每 band 一次跨 rank barrier、空 band 也要走全流程、尾部协助
  • 实现：消息语义、零拷贝、epilogue 融合
  • 消息而非内存语义：交换机做 multicast 与 reduction，端点不需知道对端显存布局
  • AG 用 rooted multicast，RS 用 rooted reduction（到达→规约→转发三级流水线）
  • FFN epilogue 融合进 RS 发送缓冲：SwiGLU 在寄存器里算完，down 投影直接按路由权重累加进 Z
  • 零拷贝输出：结果以 tensor view 交给 serving engine；可直接接入 vLLM
  • 实验：TTFT 降 20.2%–33.1%
  • 测试台：4 卡 EP + 1 卡模拟交换机，400 Gbps 共享链路；OLMoE-1B-7B，prefill only
  • 集合通信层面：网内有效带宽 163–172 Gbps，比环形高 25.6%–31.8%
  • 端到端 TTFT：24K tokens/卡降 20.2%，126K 降 33.1%；单卡吞吐 +25.3%–49.5%；逐 token 余弦相似度 1.0
  • 作者自己的七条批判
  • 交换机是单卡模拟的，含仿真伪影；基线只有 vLLM 默认路径，未与 DeepEP / FlashMoE 等实测对比
  • 只有 prefill，无 decode 数据；AG/RS 冗余随 N 增大；依赖现有网络没有的交换机能力；层间无流水线；未开源
  • 可迁移的结论
  • 判断重叠是否有用的判据：单跑时是否已对称占满双向链路
  • 用规整性换可卸载性：多传 9% 换来交换机可识别、可复制、可规约的固定模式
  • 三个工程坑：band 边界算术必须全 rank 一致、空 band 走全流程、跨 rank 同步点要少而粗
