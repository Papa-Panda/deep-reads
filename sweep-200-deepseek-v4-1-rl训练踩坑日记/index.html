DeepSeek v4.1 RL训练踩坑日记

知乎推荐流条目（sallon88，2026-10-13发布，380赞、485收藏）。一线 bring-up 实录：在百度百舸自研 LoongSage 框架（Megatron 训练 + SGLang rollout 共置）里把 DeepSeek V4.1 Flash 的 Agentic RL 跑通——环境 r2e gym + mini-swe-agent、24k response、训推一致性保持在 1e-4 量级。坑几乎全在未文档化的工程细节：权重格式转换要手写、跨机部署撞上两个 DP-attention 隐藏 bug、路由器不感知 DP 让多轮轨迹的 KV cache 大量重算、dummy 快速启动静默丢掉 engram；作者点名最大的瓶颈是主机内存而非显存——R3 专家回放按 960B/token 预留、与 CPU 优化器叠加，把 6 节点 H20（每节点 2T 内存）打到 host OOM，最后靠 chunked offload 把优化器主机峰值从 18N 降到 12N。对他是同构的一手故障账本：Agent RL 训练环路里最先爆掉的往往不是模型，而是主机内存与路由粒度这类账。注：原文未给 RL 算法名与奖励设计。

大纲

大纲（据原文通读整理）

  • 任务与终态
  • LoongSage（百度百舸自研）已支持 V4 的 Agentic 训练、SGLang 有 4.1 的 day-0 支持，看似开箱即用，实际每一步都是未文档化的坑
  • 终态：r2e gym + mini-swe-agent，24k response，训推一致性 1e-4 量级，全参 bf16 训练（fp32 lmhead）
  • 权重格式转换
  • 训推统一 bf16、多模态剥成纯文本模型；无官方/社区脚本，自行手写转换
  • 三处 config 清理：删 quantization_config、删 vision_config 并把 text_config 上提一层、删不参与训练的 mtp/dspark
  • 跨机部署与两个 DP-attention 隐藏 bug
  • 单机 8 卡光权重就占 130G+ 显存，被迫跨 2 节点：ep=16、tp 上限 8（某投影权重切不动）、dp=2；pp 会破坏 router replay 而弃用
  • bug 1：健康检查直接打挂服务——DP attention 要求 prefill token 数是 attention tp 的整数倍，探活请求几乎永不满足（修复已提上游 PR）
  • bug 2：关掉 decode CUDA graph 调试时 decode 永久假死——idle batch 从未被插入
  • KV cache 重算
  • 框架路由器不感知多 DP，同一轨迹后续轮次落到不同 DP 上，KV 无法复用、大量重算
  • 修法：用 SGLang 的指定 DP 能力，把粘性路由从引擎粒度下沉到 DP 粒度
  • 快速启动丢 engram
  • dummy 加载跳过读权重再从 Megatron 同步，把小时级启动压下来；但权重同步不带 engram（冻结参数、存主机内存），被静默丢掉，靠给 SGLang 打补丁单独加载
  • engram 主机布局默认 shared 跨机失效，须显式改 private 分片模式
  • 主机内存瓶颈（作者点名的最大瓶颈）
  • R3 专家回放按 token 预留主机内存：960B/token；每卡留 20G KV 就意味着 160G 主机内存，KV 池开大 8 倍放大
  • CPU 优化器 + engram 双份 + R3 叠加：能跑 V4 的 6 节点 H20（2T/节点）跑 V4.1 必死于优化器更新阶段
  • 修法：Megatron 的 chunked_optimizer_state_offload（当时仅 dev 分支），主机峰值 18N→12N（4N 主权重+4N 主梯度+8N 动量+2N pinned）；另配 pinned_max_cached_size 避免 2 的幂取整浪费（需 11G 实分 16G）
  • KV 侧同时用 max_total_tokens 显式封顶
  • 混合精度续训失败
  • chunked offload + fp32 lmhead 时旧 checkpoint 无法加载续训，优化器未正确处理混合精度状态对齐；临时 monkey-patch 绕过
  • 附录：step 0–30 的 SWE 训练指标
  • reward_mean 约 0.86→0.93（step 7 附近曾跌到约 0.77）；entropy 约 0.49→0.39；timing/step 约 3500→1970；KL（is_approx_k3）约 0.0008–0.00097
  • 原文未给：RL 算法名、奖励设计、总步数、tokens/s 吞吐
