内存还会跌吗？KV Cache砍掉99%，单卡吞吐飙6倍，港科大、CMU联手岩山科技开源新模型

知乎推荐流条目（量子位，2026-10-20 发布，原文已通读）。岩芯矩阵（岩山科技）与港科大、CMU 等联合开源 EdgeRock-4B：不用全量 KV，而是循环状态存大意、1024 token 局部窗口存近处、打分筛选的记忆岩锚库存远处关键细节，把每序列 attention KV 固定在 72 MiB（256K 时较源模型 Qwen3.5-4B 降 99.1%），单张 Hopper 80GB 可 512 路 32K+32K 并发、12,124 tok/s，为源模型 6.42 倍；关掉岩锚的消融里长上下文问答从 94.1% 跌到 0.4%。对他有用：上下文压缩路线从逐 token 瘦身转向固定状态加选择性锚点的一手架构样本。注：数字均为厂商技术报告自报（无 arXiv 编号），按待独立复现处理。

大纲（据原文通读整理）

  • 条目信息
  • 量子位（允中），发布于 2026-10-20 19:40；读时 12 赞、20 收藏
  • 对象：岩芯矩阵（岩山科技）与港科大、CMU 等联合开源的 EdgeRock-4B；权重与推理代码在 GitHub / Hugging Face 的 rockmatrix-ai/EdgeRock，技术报告为厂商 PDF，文中未给 arXiv 编号
  • 问题：推理越长为什么越贵
  • 标准注意力每生成一个 token 就新增一份 KV：源模型 Qwen3.5-4B 每 token 约 32 KiB，单序列 64K 时约 2 GiB、256K 时约 8 GiB
  • 路线一是逐 token 瘦身（MLA 压缩、KV 量化、TurboQuant 一类）：单份变小，总量仍随长度增长
  • 路线二是 有界状态模型（循环、状态空间、滑窗）：内存固定，但远处细节容易丢，后面要用时找不回
  • 方法：记忆岩锚 Rock Memory Anchors
  • 历史拆成三件固定的事：循环状态记大意，局部窗口留最近 1024 个 token，锚库存被选中的旧细节
  • 写入要竞争：每个 token 先生成一条候选记录并打分，每攒满 256 条就和库里已有的比，只留总分最高的 1024 条；4 个 KV 组各比各的
  • 锚记录一旦入选就不再改，且带着原来的位置，滑出局部窗口后仍能被直接读到
  • 改造路径：从 Qwen3.5-4B 分阶段转换、不从头预训练；保留 24 层 Gated DeltaNet，8 层全注意力换成滑窗注意力加独立的岩锚模块
  • 结果：内存、吞吐与成本（厂商自报）
  • 每序列 attention KV 固定 72 MiB，与 4K 到 256K 的长度无关，256K 时较源模型降 99.1%；连全部历史状态共 97.76 MiB
  • 单卡 Hopper 80GB、32K 输入加 32K 输出：512 路并发跑出 12,124 输出 tok/s，是源模型（最大 batch 64、1,889 tok/s）的 6.42 倍；整卡峰值显存 61.26 GiB
  • 按 GPU 时长折算，4K 输入时单 token 成本约为源模型的 24.9%，32K 输入时约 15.6%；且每请求内存事先可知，利于容量规划和 Agent 长历史
  • 能力保持与证据强度
  • 对源模型：AIME pass@1 保留 96.3%，MATH-500 保留 97.5%，29 项文本基准里 8 项反超
  • 关键消融：推理时关掉全部 8 个岩锚模块，长上下文问答准确率从 94.1%（964/1024）跌到 0.4%（4/1024），说明锚库是能力来源而非摆设
  • 边界：以上数字全部来自厂商技术报告，暂无同行评审与独立复现；文中还点了机器人与边缘部署（数小时运行、历史状态可预先算清）作为落点
