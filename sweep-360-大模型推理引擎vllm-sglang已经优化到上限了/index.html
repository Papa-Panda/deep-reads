大模型推理引擎vllm、sglang已经优化到上限了？

不归牛顿管的熊猫（2026-11-17）论证：固定模型、硬件与负载时推理引擎确有上限（8B BF16 在 H100 上约 200 tokens/s），但注意力压缩、MoE、Agent 长上下文、硬件换代与优化目标迁移不断把上限往前推；附 DeepSeek V4 CSA/HCA、Kimi K3.1 KDA 与 SGLang HiCache 的具体数字。正撞推理优化与 KV Cache 主线。

大纲

大纲（全文已通读；不归牛顿管的熊猫，2026-11-17；31 赞）

  • 立论：上限问题不能把引擎与模型、硬件拆开谈
  • 固定三者，上限存在且部分场景已接近；三者每年都在变，上限一直前移
  • 结论：离天花板还很远；唯一的终点是出现整类更强的新模型
  • 固定条件下的上限：Decode 的 roofline 可算
  • 8B BF16 约 16GB 权重 / H100 SXM 约 3.35TB/s / batch=1 → 约 200 tokens/s
  • 超过上限只能说明模型算错了；Llama+H100+普通聊天组合确实优化空间不大，但该组合正在过时
  • 模型变，引擎也要变
  • 注意力：MHA→GQA→MLA，KV Cache 一路缩小；DeepSeek V4 的 CSA（4 token 压 1 条 + lightning indexer 稀疏选 top-k）与 HCA（128 token 压 1 条 + 全量稠密）；各留 128 token 未压缩滑窗；Qwen4 同向演进
  • Kimi K3.1 KDA 门控线性注意力：每请求只维护固定大小循环状态；其余 24 层为门控 MLA，每层加 indexer 只看最相关的 2048 token
  • 缓存形态变复杂：多压缩比 KV + 滑窗 KV + indexer key + 线性注意力循环状态；PagedAttention 与 prefix cache 需重设计；循环状态每 token 被覆写，不能任意截断复用，需在特定位置另存状态
  • MoE：Kimi K3.1 Pro 2.8T 总参数 / 104B 激活 / 896 路由专家 / 每 token 选 16 + 2 共享专家；路由专家权重直接存 MXFP4；新问题：专家跨卡放置、token 路由 all-to-all、专家负载不均、分组 GEMM 配低精度权重、latent MoE
  • 负载形态：o1/R1 起推理模型先出上万 token 思考链，负载由 Prefill 主导转 Decode 主导；上下文 1M token；KV Cache 随输入输出膨胀，内存管理/调度/投机解码收益都要重估
  • Agent：多轮对话 + 反复工具调用 + 长共享系统提示 → prefix cache 关键，但 GPU 显存装不下；SGLang HiCache 三级缓存：HBM L1 / CPU 内存 L2 / 外部存储 L3（Mooncake、3FS），可跨实例共享；4×H200 上 DeepSeek-V4-Flash 多轮对话，Mooncake 作 L3 后有效输入吞吐 9.4K→145.5K tokens/s，命中率近 98%；KV Cache 从显存管理问题变成存储系统问题
  • 多模态：视觉编码器算力特征与 LLM 完全不同；视频输入视觉 token 量大；编码器与 LLM 如何拆分部署、视觉 token 如何压缩缓存，仍待探索
  • 硬件变，最优解也在变
  • Hopper：FP8、TMA、warp specialization；FlashAttention-3 大量用新特性；A100 最优核到 H100 未必最优
  • Blackwell：NVFP4 等新特性，工作要重做一遍；GB200 NVL72：72 卡同一 NVLink 域，改变专家并行规模与 P/D 资源分配、模型切分方式
  • 国产芯片（昇腾等）：架构/算子生态/互连都不同，引擎要从头做大量工作才能接近硬件上限
  • 新硬件刚出时软件与理论峰值差距大，引擎的工作就是一点点弥合差距；快弥合完时下一代硬件又来了
  • 优化目标本身也在变
  • 吞吐（每卡每秒 token）→ TTFT/TPOT 与 goodput（延迟约束下的有效吞吐；DistServe、Splitwise 的 P/D 分离由此而来）→ 每百万 token 成本、集群能耗与利用率、多租户多模型混合部署效率
  • 目标函数一变，最优解跟着变；旧目标下接近上限的系统，在新目标下可能还差得远
  • 类比：数据库与编译器
  • 几十年还在优化，不是因为前人做得差，而是硬件（磁盘→SSD/NVMe、单核→多核→云分布）与负载（OLTP→OLAP、流处理、向量检索）一直在变
  • 推理引擎夹在模型与硬件之间、直面业务负载，同样永远没有“做完”的一天；方向才刚开始，寿命与大模型本身相当
  • 作者认定的边界
  • 只有整类新模型在能力/成本/范式上全面超越并整体替换大模型应用场景与生态时，围绕 Transformer/KV Cache/自回归解码的优化体系才会成为历史
  • 即便如此，新模型仍需高效跑在硬件上，会出现新一类推理引擎；今天积累的经验大多可复用：访存瓶颈分析、调度、存算权衡、软件追赶硬件
