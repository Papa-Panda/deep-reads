AgentCore + Codex 构建生产级 Agent 的原理与实践

阿里中间件团队详解 Codex + AgentCore-Runloop 如何构建生产级 Agent：三层架构、Runloop 三阶段执行、Skills、工具、存储、身份与可观测性全链路拆解，并附部署实操与延迟实测。Agent infra 与 harness 的系统级实战拆解，值得慢读。

2026-11-19

原文链接：https://zhuanlan.zhihu.com/p/2102101438616946256

大纲

核心思路

  • Codex Skills 是知识层，AgentCore 是引擎
  • Codex CLI（Node.js，Apache-2.0）模型无关，MCP 式工具与 Skills 协议与 AgentCore-Runloop 兼容
  • 默认模型 Qwen3，也支持 Kimi K2、glm-4.6

三层总体架构

  • 交互层：SSE 流式输出
  • AgentCore-Runloop + AgentCore Tools（Codex 兼容）
  • Agent 层：Nacos 注册与动态路由（工具、存储、身份、可观测）

Runloop 内部执行

  • Input：系统提示词 + Skills + 历史 + 上下文，工具用 zod 严格定义，多模态输入
  • Reasoning：模型调用、多轮工具调用、Skills 加载、工具编排、Guardrails
  • Output：SSE 流式输出，会话历史存入 session store，指标上报
  • 三个特点：多模态工具调用、流式输出、多维可观测

工具与 Skills

  • 内置工具：bash、apply_patch（支持 100MB 以上大文件）、web search 等
  • 远程 MCP Server（SSE/stdio）可动态配置注册
  • Skills 遵循 Codex Skills 标准，内置 skill-creator、pdf、pptx、remotion 等，社区 Skills 可一键安装

存储：三层皆在 PostgreSQL

  • Session store：会话历史自动保存
  • 长期记忆：pgvector 向量记忆
  • 知识库：PostgreSQL + pgvector，文档索引与 RAG 检索

身份与安全、可观测

  • 三类身份：AgentIdentityManager、MCP Auth、Skill Auth；Docker 沙箱网络隔离
  • OpenTelemetry 指标、TraceId 链路追踪、TTFT 与延迟等模型指标；AgentCore Evals（LLM-as-judge）

动手部署与实测

  • 依赖：Node.js 20+、Docker、PostgreSQL、Nacos、AgentCore CLI
  • 源码 agentcore-runloop 与 agentcore-chat，pnpm build，Docker/K8s 部署
  • 实测：TTFT 约 1.7 秒，P95 约 1.95 秒，网关约 0.18 秒（20 样本，2 核 8G）
