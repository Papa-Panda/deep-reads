再探 CUDA Graph：核心机制、多图复用以及 Dual AR 模型的统一覆盖优化

Chayenne Zhao 在 SGLang-Omni 为 Fish Audio S2-Pro（PR #153）把 Slow AR（Qwen3-4B）与 Fast AR（9 步码本循环）统一进一张 CUDA Graph 的实战复盘：从捕获/实例化/回放机制与五条约束出发，讲清指针稳定、内存池共享、延迟捕获与持久 buffer 的工程实现；实测 eager 55.6 → 仅图 88 → 全编译 126 tok/s。值得他看的是它把 CUDA Graph 从提速技巧还原为静态化优化的设计哲学，且反直觉的结论是图优化真正 payoff 在微秒级小算子的快头、而非毫秒级大 GEMM 的慢头，正对 CUDA/推理优化主线。

大纲

大纲（全文已通读）

  • 立论：CUDA Graph 本质是静态化优化
  • 把动态的 kernel 启动序列固化成静态 DAG，一次 cudaGraphLaunch 替代逐个启动
  • 推理常用、训练少用：推理 kernel 序列高度重复、无优化器步骤；训练有动态 shape、梯度同步与优化器状态更新，破坏静态假设
  • 背景：作者在 SGLang-Omni 为 Fish Audio S2-Pro TTS 模型加 CUDA Graph 支持（PR #153），并结合 torch.compile 实测
  • 第一章：核心机制
  • 三步：捕获 cudaStreamBeginCapture 录成 DAG 节点 → 实例化 cudaGraphInstantiate 做依赖分析与合法性检查 → 回放 cudaGraphLaunch 单次 CPU 调用整图执行
  • 五条约束（皆由机制导出）：指针稳定性、禁止动态内存分配、禁止 host-device 同步、静态控制流、图录制后不可自动更新
  • 推论：batch size 须固定在图里，不同 batch size 要不同图
  • PyTorch 封装：torch.cuda.CUDAGraph 只是驱动 API 的包装；标准用法是静态输入输出张量 + copy_ + replay
  • 内存池：图即 cache，空间换时间；单图占用约等于捕获期峰值内存（高水位），不是全部中间张量之和
  • 多图共享：12 个 batch size 各持一份高水位即 12 倍显存；torch.cuda.graph(pool=...) 让多图共用一个池，SGLang CudaGraphRunner 即用此法
  • 第二章：S2-Pro Dual AR 架构
  • 5B 参数 TTS 模型：给定参考语音与目标文本，生成同音色语音；每步产 10 个码本 token
  • Slow AR（4B，基于 Qwen3-4B）：沿时间轴自回归，每步预测第 1 个 RVQ 码本的语义 token；单步毫秒级
  • Fast AR（约 400M，4 层 Transformer）：以 Slow AR 隐状态为条件，沿码本深度轴 9 步生成剩余 9 个码本 token；单步微秒级，但 9 步循环积累大量小 kernel 启动
  • 多码本融合 MCF：10 个码本 token 聚合成连续向量，作为 Slow AR 下一步输入
  • 关键同构：4B 时间轴 + 4 层深度轴的非对称设计，与标准自回归 LLM 结构同构，可继承连续批处理、分页 KV、CUDA Graph 回放、RadixAttention 前缀缓存
  • 两种 KV cache 可共存于一张图
  • Slow head 用分页 KV：请求创建时分配、随序列增长、块表间接寻址、RadixAttention 复用
  • Fast head 用静态 KV：初始化一次预分配、固定长度（码本步数固定为 10）、直接索引、每步后 zero_ 原地清零复用
  • 各自独立管理状态、所有 kernel 录进同一 DAG，是后文一图覆盖两个 AR forward 的事实依据
  • 设计决策：PR #153 的一图统一
  • 之前：图只覆盖 Slow head，Fast head 在图外逐请求 eager 执行
  • 反直觉结论：Slow head 大 GEMM（mm 8×2560×6144）毫秒级，省启动开销收益小；Fast head 微秒级小算子，启动开销占大头，图优化真正 payoff 在此
  • 曾考虑的双图方案被否：两图之间仍有 CPU 调度开销（取结果、启下一图、写回）
  • 定案：一张图内录 Slow AR + 采样 + Fast AR，_decode_codebooks 从图外后处理改为 forward 内的一步
  • 第三章：工程实现
  • 延迟捕获：初始化先禁图，待 ModelWorker 初始化、BF16 修正、静态 KV 预分配、setup_vq_decode 挂载完成（_vq_ready 置真）后，才 init_device_graphs 捕获完整 forward；早捕获会静默缺失 VQ 组合与码本解码且永不自动更新
  • Buffer 分配：setup_vq_decode 内 torch.zeros 一次性分配 _vq_codes、_vq_mask、_output_codes、_output_semantic_ids、_semantic_bias，之后只原地修改
  • Persistent buffer：图外写值、图内读地址；update_vq_buffers（图前 copy）→ forward 图回放 → build_outputs（图后读结果）；input_pos 用 register_buffer + fill，不用新建张量
  • Greedy 解码：top-k/top-p 采样改 torch.argmax，因 multinomial 涉随机状态与动态 shape、与图不兼容；TTS 场景下贪心质量损失可接受
  • 实测数据（稳态，不含 vocoder）
  • Eager 55.6 tok/s → 仅图 88（+58.3%）→ 部分编译（仅快头）121 → 全模型编译 126 tok/s（2.27 倍）
  • 未回答：统一一图 vs 双图的直接对比数、torch.compile 增益是否来自融合快头小算子；torch.compile 四种 mode 与 inductor CUDAGraph Trees 的冲突留作后文
