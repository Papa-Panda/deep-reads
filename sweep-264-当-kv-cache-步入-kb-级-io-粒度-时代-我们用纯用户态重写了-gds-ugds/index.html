当 KV Cache 步入 KB 级 IO 粒度 时代，我们用纯用户态重写了 GDS：uGDS 开源，吞吐提升 2.63 倍

讲推理瓶颈如何从算力转向 KV Cache 在存储层之间的搬运：单 token KV 已缩到 KB 级，历史缓存值得放进 NVMe，但现有 GPU 到 SSD 路径对细粒度访问不友好。作者给出纯用户态方案 uGDS，并附 arXiv 报告与开源链接。值得他看的是这条与推理缓存、LMCache 落地直接相关的存储层分析；注意 2.63 倍是异步/批量、计算掩盖传输场景下的峰值，并非所有传输都快这么多。

大纲

大纲

  • 瓶颈转移
  • 推理不再只受算力约束，显存与存储层之间的数据搬运成为关键
  • 单 token KV 从数百 KB 缩到 KB 级，长上下文的历史缓存变得碎片化
  • 为什么放 SSD
  • 会话级缓存规模可达 TB/PB，NVMe 成本上更适合做持久缓存层
  • 亚 GB 级历史缓存理论上可在 1 秒内量级载入
  • 现有路径的短板
  • GDS 走文件系统与内核切换，细粒度读写带宽低、延迟高
  • 旧的用户态方案难维护，GPU 发起式方案则占用宝贵的 GPU 算力
  • uGDS 的做法
  • 控制面放用户态：NVMe 命令组装、doorbell 与完成队列轮询由 CPU 做
  • 内核驱动只负责初始化，数据直通 GPU 显存与 SSD，不经过主机内存
  • 三条路径分工：冷启动、热控制与数据路径分离
  • 队列按功能切分，同步与批量互不干扰；支持同步轮询、批量、GPU 流异步与中断四种模式
  • 效果与边界
  • 小 IO 场景优于 GDS，大 IO 下两者趋近带宽上限
  • 异步/批量端到端场景下 TTFT 降至约 37%，KV 吞吐峰值约 2.63 倍
  • 代价是目前需独占裸盘，适合自带块分配池的缓存系统
  • 未来方向
  • SSD 既做高速交换空间，也做持久缓存
  • 更高层 AI 存储语义、条带化 SSD 与远程分布式存储
