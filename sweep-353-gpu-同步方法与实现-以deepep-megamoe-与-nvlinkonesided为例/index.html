大纲

大纲（全文已通读；盖茨比，编辑于 2026-11-16；4 赞 / 10 收藏）

  • 同步的四项职责
  • 执行会合：生产者/消费者都到齐
  • release/acquire 发布：写对他人可见，才立起 flag
  • 异步完成可观测：DMA / kernel / RDMA 的完成必须能被观测到
  • 所有权/复用：确认旧用完结，才可覆写 buffer 槽位
  • 两个前提：可达性（CTA / cluster / 远端 rank 寻址）、进展/活性（等待的 CTA 别占满常驻槽位致死锁）
  • 机制总览：按作用域与代价
  • warp barrier、CTA / named barrier、cluster barrier、mbarrier、软件 grid barrier、DeepEP / MegaMoE rank barrier、Fence / Sentinel、NVSHMEM
  • 代价量化：软件 grid barrier 约 B 次 RMW + 轮询；成对 rank barrier P² 次信号
  • 内存序：概念核心
  • release/acquire 必须贴在 flag 访问本身；volatile 只是 relaxed 系统域访问，不绕缓存；cache hint 不是同步
  • fence.acq_rel.sys 不是最强序；sm_70+ 才有 scoped acquire/release；sm_80+ mbarrier；sm_90+ cluster/TMA；Blackwell tcgen05/UMMA
  • 代表线程不能替别人发布；发布 slot n 不等于可覆写 slot n+1
  • 实现巡览：作用域逐级上升
  • warp/CTA：__syncwarp、named barrier 对齐/非对齐、生产者-消费者双 barrier、DeepEP 双写者会合后才发布 tail
  • cluster/mbarrier：mbarrier 对象（到达计数 + tx 计数 + phase）、MegaMoE barrier 清单、TMA 完成 vs proxy 序 vs MMA 完成
  • 单卡跨 CTA：MegaMoE 可复用 grid barrier 的 tag-bit 技巧、大 grid 死锁风险、last-arriver-continues
  • 跨 rank DeepEP：credit/debt 的 barrier_block、ring-buffer 的 tail/payload/head、head 取接收方进度最小值
  • 跨 rank MegaMoE：层内 grid_sync + 逻辑 CTA 0 发 release 信号、4 状态信号复用
  • NVLinkOneSided：Fence 与 Sentinel 对比、Sentinel 五项正确性条件与 reset race
  • 收尾
  • VMM / 对称内存 / 组播 / 传输、kernel/stream/host 同步、代价与场景指导
  • 单生产者单消费者 slot 模板 + 10 点协议检查清单
