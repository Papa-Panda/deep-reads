复盘 SGLang 这一个月：推理框架的瓶颈正在换位置

SGLang 42 天（2026-09-15—10-26）2693 次提交的逐 PR 复盘：缓存统一寻址、PD 状态控制面、投机解码正确性、NVFP4 容量 trade-off，结论是推理框架的瓶颈正在从单点加速换到状态正确性与按负载选策略。值得他看的是它把推理 infra 从 benchmark 数字还原为可复现、可组合的机制与代价，且对每项收益的适用边界都做了标注，正对推理优化主线。

大纲

大纲

  • 立论：瓶颈正在换位置
  • 42 天（2026-09-15—10-26）、2693 次提交、约 498 位作者
  • SGLang 本月在改写缓存寻址、PD 调度与投机解码的组合边界
  • README 回答结果是什么，PR 机制决定结果是否可复现、可组合、能上生产
  • 缓存：系统开始管理地址与生命周期
  • Rust TreeCore 默认：Full / SWA / Mamba 共用树、锁与淘汰接口
  • SeaweedFS L3：KV 页作对象，长前缀 TTFT 降 3.5×–4.7×；25K token 以下重算可能更快
  • Fused draft KV：一槽位同时寻址目标与草稿 KV，Kimi-Linear 单卡显存 127.8→90.8 GiB
  • DSA 跳过未读零长 index-K：GLM-5.2 Prefill KV 容量 +11.6%
  • PD：从部署拓扑变成状态控制面
  • 运行时 P↔D 角色切换：100 次往返零失败，但须等完全空闲、失败即判不健康
  • prefill_complete 准入：吞吐 +26.8%、p95 TTFT −48.9%，但 p99 ITL +92.77%，仅 opt-in
  • Hybrid SWA 状态按 token 与 KV-head 切分传输
  • 投机解码：正确性已成为性能的一部分
  • HiSparse 多步 gather/commit 合并；DCP+MTP 下 GLM-5.3 在 8×B300 上 1041→1876 tok/s
  • 校验窗口按已提交长度重算，修 Mamba 状态恢复错误
  • 被拒 token 是表象，难的是状态提交/回滚与组合拒绝原因
  • 算力利用：专用 kernel、调度与 Graph
  • DeepSeek-V4.1 Hopper 专用路径：8×H200 单卡吞吐 2.1×–2.3×
  • 调度器从排序转向不让流水线停住：最短 prefill 优先、非阻塞 intake、被抢占请求重排队
  • CUDA Graph 从 decode 扩展到 prefill 与 mixed chunk：捕获显存 43→18 GB
  • NVFP4 KV：容量理论 1.778×，但原生 FP4 Prefill 反而慢约 10%——kernel 收益 ≠ 链路收益
  • 服务边界：加载、路由与 API 不再是外围
  • InstantTensor 加载：Qwen3-30B-A3B 加载 57.4→1.77 s
  • 缓存感知路由、Score/Decision API、RL 权重更新会话、请求级 TPOT 直方图
  • Aaronson-Gumbel 文本水印：无额外 token，检测只看 token ID 与密钥
  • 三条主线与使用者判断
  • 统一寻址、状态协议、性能策略化（没有全局默认，只有按负载的策略）
  • 单模型短文本重加载与专用 kernel；长上下文/Agent/MoE/PD 集群再评估 fused draft KV 与动态 PD
  • 验收看 p50/p95/p99 TTFT、TPOT、p99 ITL、任务准确率与缓存命中率，不只看吞吐
  • 展望：下一阶段竞争什么
  • KV 缓存成为可寻址、可迁移的上下文资源
  • 状态正确性成为硬发布门槛；评估从 token 速度转向每完成任务的成本
