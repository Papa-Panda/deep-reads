Meta FAIR 把 Transformer 循环了 32 次：循环哪里、要不要分化、能不能并行

momo 全文解读 Meta FAIR 2026-10 论文《How to Loop Your Transformer》（arXiv:2610.40325）：同一组权重反复跑最多 32 次，不加参数就能加深模型；全栈循环在固定参数预算下质量最强、中段循环在训练算力受限时更划算、每轮加小 LoRA 适配器轮数越多越有用、并行循环要靠“保留当前 token embedding + 分别归一化 + 门控混合”才能保住质量。值得他看的是它把“深度换参数还是换算力”这笔账算清楚了，且数字都给到了可复核的程度（100M 上 BPB 1.115→1.075→L=32 回升超 1.2；1B 上移位 PLT 0.877 胜全栈 0.883），正撞他模型架构与推理效率的主线。全文已通读。

大纲

大纲（全文已通读，momo 2026-11-03）

  • 问题：循环 Transformer——同一组权重反复用，深度换参数
  • 论文：Meta FAIR《How to Loop Your Transformer》（arXiv:2610.40325，2026-10）；作者 Ekbote 等，FAIR at Meta（一作兼 MIT）
  • 背景：标准 Transformer 有 B 个 block；循环是把其中一部分（整网 / 单层 / 中段）反馈回输入跑 L 次，参数共享，看起来像更深的网络
  • 代价：每多一轮，训练 FLOPs 线性增加；生成时每 token 的串行计算随 L 增长
  • 研究问题：循环哪里、循环多少次、每轮要不要分化、推理时能不能并行；此前工作各自用不同模型/数据/预算，结果不可比，本文统一到同一从头训练设定
  • 实验设计：从头训练的 dense decoder-only
  • 规模：70M / 100M / 200M / 300M / 500M / 1B（4–16 层，宽 512–2048）；1B 为 967M 非 embedding 参数
  • 配置：GQA、SwiGLU、RoPE、128256 词 Llama-3 兼容 tokenizer、8192 上下文；AdamW、峰值 lr 3e-4、bf16
  • 预算：10–160 TPP；总量 777M–154.8B token，最高 1.07×10²¹ FLOPs，最多 32 轮（大模型轮数上限更低，1B 只到 4）
  • 指标：DCLM 约 41M token 验证集 BPB 为主；另 C4、WikiText-103、Dolma、RedPajama、代码语料；下游 8 个选择题任务按 NLL 排序计分
  • 七种设计：全栈循环、逐层循环、中段整块循环、中段逐层循环；循环对象：整块 / 仅注意力 / 仅 MLP / 注意力与 MLP 各自循环
  • 发现一：循环哪里、循环几次
  • L≤16 时几乎所有设计都胜过无循环，但边际增益递减，过大 L 会饱和、反转甚至不稳定；TPP 越高，增益越稳
  • 数字：100M、TPP 160，全栈 DCLM BPB 从 L=1 的约 1.115 降到 L=16 的约 1.075，L=32 又跳回 1.2 以上
  • 规模改变排序：100M/200M、L≤2 时逐层与中段可与全栈打平；300M 尤其 500M，全栈与中段最优，TPP 越高全栈越低
  • 按训练 FLOPs 看：小算力预算下中段循环单位 FLOPs 收益最高（只重复中间三分之一）；算力不限时全栈绝对 BPB 最低
  • 1B（TPP 10/40，L=2/4）：全栈、中段、逐层都胜无循环；同 L 下全栈最低，中段额外 FLOPs 最少
  • 反例：注意力与 MLP 各自循环最差，随 L 增大掉得最快；小模型数学/代码实验里 80 个配置中有 11 个不稳定
  • 发现二：要不要分化——每轮加小 LoRA 适配器
  • 动因：后几轮面对的是已被变换多次的表示，完全共享权重会限制收益；完全独立权重又丢掉参数节省
  • 方法：主权重共享，每轮一个 rank-8 低秩修正（三种形式：Loop LoRA、Loop Matrix、Loop Softmax；Loop Matrix 最优，为默认）
  • 效果（300M、全栈、TPP 100）：BPB 改进 L=2 时 0.0001、L=4 时 0.0028、L=8 时 0.0063——越深越有用
  • 成本：300M 上非 embedding 参数只多 1.1–4.3%（对比翻倍深度要 +51.4%）；训练 FLOPs 多 2.1%（L=2）到 9.3%（L=8）
  • 口径：分化省参数、不省算力——同等 FLOPs 下翻倍深度的对照仍更优；算力是瓶颈且能存更多参数时，加层比循环+分化更划算
  • 发现三：并行循环为什么掉分，怎么修
  • 痛点：自回归解码时每轮必须串行，延迟随轮数成比例涨
  • PLT（Wu et al. 2025）：跨相邻 token 传隐藏状态（CLP），第 n 个 token 的各轮输入可成批并行算；原版还共享首轮 KV 缓存 + 滑窗缓存 G-SWA
  • 原版问题：200M、TPP 40/80 下原版 PLT 及其中间变体都追不上全栈；L≤2 时接近无循环基线，裸移位 CLP 随 L 增大更差
  • 根因：当前 token embedding 与上一 token 隐藏状态的 RMS 量级差 10–300 倍（100M、L=8；缓存对比里轴线到 600 倍），直接相加会淹没较小一方，且谁占优随 TPP 与 L 漂移
  • 修复（三件套）：两路分别 RMSNorm 到同一尺度；门控混合 b = g⊙ê + (1−g)⊙ĥ（固定 50/50 已够用，rank-8 线性门略优）；始终保留当前 token embedding
  • 门控成本：跨轮共享，仅 25d 参数，1B 上 51200 参数，不到非 embedding 参数的 0.015%
  • 去掉当前 embedding 的消融：比无循环更差，多次发散——上一 token 状态只是对当前位的“预测”，embedding 把每轮锚回真实 token
  • 最终设计 Normalized Shifted PLT：每轮独立 KV 缓存，不用 KV 共享与 G-SWA；同款归一化+门控也让非移位对照超过全栈
  • 1B 结果（TPP 80）：无循环约 0.898、全栈约 0.883、移位 PLT 约 0.877、非移位对照约 0.875；L=4 时移位 PLT 与全栈大体相当，但与非移位对照的差距拉大
  • 效率账：循环能替数据、也能替算力（在过训练区）
  • 数据效率：1B 上所有循环方法达到同一 BPB 用的 token 都更少；改进版 PLT 省得最多，154.8B token 处增益接近 3 倍
  • 算力效率：100M–1B、TPP 80 的双轮模型，比 TPP 160 的无循环模型用更少 FLOPs 达到同一 BPB，增益 1.06–1.37 倍；L=4 绝对质量更好，但单位 FLOPs 收益弱于 L=2
  • 下游：1B 上 8 个选择题任务平均分随 TPP 上升，三种循环方法都达到或超过无循环；TPP 160 时 6/8 任务胜出，ARC-Challenge 与 HellaSwag 最明显；MMLU 与 MMLU-Pro 在此规模接近随机，单独报告
  • 保留意见
  • 最大 1B、纯 dense，无 MoE 与后训练模型；评估几乎全是似然（BPB）与选择题计分，无自由生成评估
  • 多数设定单随机种子；门控间 0.001 量级的差异只是方向性结果
  • 效率结论基于训练 FLOPs 核算，未实测解码延迟与吞吐；PLT 推理加速仍是理论上的
  • 移位 PLT 在 L=2 最好，L=4 已有差距，更大 L 与更大模型未经验证
  • 对实际使用的启发
  • 参数受限（如端侧）：全栈循环为默认；4 轮以上加 Loop Matrix 式低秩适配器，只多几个百分点参数
  • 训练算力受限：只循环中段、2 轮，性价比最高；能存更多参数时加层更划算
  • 延迟敏感：Normalized Shifted PLT、2 轮，两路分别 RMSNorm、门控混合（固定 50/50 够用）、保留当前 embedding、每轮独立 KV 缓存，显存紧时可换 G-SWA
  • 不要把注意力与 MLP 各自循环；不要指望 32 轮一直变好；数据充足的过训练区，“多一轮、少一半数据”是值得算的 trade-off
