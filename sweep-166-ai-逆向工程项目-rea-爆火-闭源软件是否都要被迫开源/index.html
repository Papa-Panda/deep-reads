AI 逆向工程项目 REA 爆火，闭源软件是否都要被迫开源？

知乎热榜条目（约106万热度，32个回答，关注429，浏览约10.8万）。REA 通过 MCP 把 Ghidra、IDA 等逆向工具接到 Claude Code、Codex 等编程助手上，几天内在 GitHub 揽下近7万星。头部回答中最有分量的是实测：有人用它逆向 Codex 桌面端，梳理出权限检查与自动审查的触发路径，并据此解释某些变慢现象；其余回答的主线是：闭源过去靠的是逆向成本高，AI 把这道成本打下来后，厂商的出路是核心能力上云、卖服务、靠法律与平台数据壁垒。对他正对口 agent 工具链方向：当 AI 能读二进制，软件的分发与防御形态都会变。已读默认排序前3答。

大纲（据默认排序前 3 答整理）

  • 事件本体
  • REA（Reverse Engineer Anything）通过 MCP 把 Ghidra、IDA、Hopper 等逆向工具接到 Claude Code、Codex、Cursor 等编程助手，GitHub 近 7 万星
  • 问题页 32 个回答、429 关注、浏览约 10.8 万，热榜约 106 万热度
  • 实测证据：AI 逆向已经可用（约 161 赞）
  • 回答者用 REA 逆向 Codex 桌面端的安全策略，梳理出权限检查与自动审查的触发路径
  • 据此解释某些模型变慢与严格的自动审查模式有关；重心是演示而非论述开源
  • 机制判断：闭源的护城河是逆向成本（约 35 赞）
  • 逆向成本骤降后，本地软件的逻辑更容易被看清，单纯藏代码不再可靠
  • 厂商出路：核心能力移上云端、法律与平台数据壁垒、转向卖服务、选择性开源或与硬件绑定
  • 商业结论：卖软件副本的模式承压（约 113 赞）
  • 智能体编程时代，开闭源对商业成败的影响在变小，REA 能提高复刻程度但细节仍难完全还原
  • 更可行的形态是卖服务而非卖副本
