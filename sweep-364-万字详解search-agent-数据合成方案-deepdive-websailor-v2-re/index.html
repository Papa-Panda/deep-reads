万字详解Search Agent 数据合成方案（DeepDive、WebSailor-V2、REDSearcher）

余培杰（腾讯混元，2026-02-20，113 赞 / 213 收藏）万字拆解三套 Search Agent 数据合成方案：共用“建图 → 随机游走取子图 → 生成 QA”三步；DeepDive 开源代码逐行讲透（出度过滤 + LLM 选下一跳 + 四测难度过滤）；WebSailor-V2 用 Weisfeiler-Leman 保证子图非同构多样性与三招混淆法；REDSearcher 再加树宽 / 信息分散度与五步 Verifier Pipeline；BrowseComp 15.3 → 35.3 → 42.1，上下文管理再推到 57.4。正撞 Agent 数据合成与后训练主线。

大纲

大纲（全文已通读；余培杰，腾讯混元 Agent，2026-02-20；113 赞 / 213 收藏）

  • 总表：三套方案对照
  • DeepDive：SFT 1016 + RL 2234 = 3250 条，BrowseComp 15.3，清华 & 智谱，2025-09-12
  • WebSailor-V2：30000+ 条，BrowseComp 35.3，阿里通义，2025-09-16，数据集未开源
  • REDSearcher：SFT 10000 + RL 1000，总表称 30000 条，BrowseComp 42.1，上下文管理后 57.4，小红书，2026-02-17
  • 注：REDSearcher 总表中 SFT 与 RL 之和（11000）与总条数（30000）对不上，原文未给剩余数据的拆分
  • 共用三步流水线
  • 构建知识图谱 → 选初始节点随机游走生成子图 → 按子图生成 QA 对
  • 三套方法的差别主要是每一步的优化
  • DeepDive（开源完整，最易懂）
  • 游走约束：节点出度过滤 [dmin, dmax]（太高则答案易猜，太低则走不下去）+ LLM 选与当前路径最相关的下一跳
  • QA 生成：取末节点属性作金答案；LLM 模糊化路径上的实体属性（如具体日期泛化成时间范围）
  • 难度过滤：GPT-4o 测四次，答对一次即丢弃，只留四次全败的题
  • 代码 random_walk_kilt.py：KILT 图上受控游走，路径 ≥5 跳；LLM 只回 1–5 的数字选下一跳；失败回滚到历史节点；每 5 步存一条，100 步或 100 节点封顶
  • 代码 generate_qa.py：提示词模板要求逐节点设线索、至多 15 条、800 字内、全部时间/人名/地名/事件信息模糊化；示例问 Transformer 核心机制，答 self-attention
  • 短板：BrowseComp 仅 15.3，难度与多样性不足，数据量 3000 条偏少
  • WebSailor-V2
  • 建图：从种子实体出发用 Web 工具扩展相关实体，不直接用现成维基图谱
  • 取子图：随机游走 + Weisfeiler-Leman 算法验“非同构”，覆盖链到复杂环、割点/桥等多种拓扑
  • 三招混淆法加难
    • 语义混淆：关键信息不明说或间接描述（如“该成果首次发表的两个重要会议中较早的那个”），逼 Agent 先重建缺失实体再验证
    • 掺假噪声：插入事实错误的干扰项（如同一作者另一篇论文的发表年份），逼多源交叉验证与纠错
    • 结构不确定性：删关键节点/边（割点、桥），逼 Agent 经由替代路径或图冗余重建多跳关系，按 orbit 节点分布不确定性类型
  • 结果：BrowseComp 35.3；但训练集 30000+ 条是 DeepDive 的 10 倍，质量与数量的贡献拆不开
  • REDSearcher
  • 两指标：树宽（图结构复杂度）与信息分散度（覆盖全部关键证据最少需要几个信源；越大越逼多轮检索合成）
  • 子图抽取：按指定树宽 + 分散度构造推理图，LLM Agent 做“拓扑加密”，让依赖图出现环与交错约束
  • QA 生成：模糊化关键实体（如地名换成地图距离约束）
  • 五步 Verifier Pipeline（难、真、可解、答案唯一）
    • 无工具 LLM 预筛：能答对即删
    • 检索可达检查：答案须出现在搜索前 50 条摘要里
    • 幻觉/不一致检查：拿建图证据对问题验矛盾
    • Agent 多轮 rollout 验证：至少一轮答对才保留，通过率作置信度
    • 答案唯一性检查：出现合理解答即丢弃
  • 结果：BrowseComp 42.1（+6.8）；MidTrain 引入教师模型、数据量等多变量，严格比较不易
  • 上下文管理：上下文超阈值时清空工具调用历史、只留原问题与最小任务说明，从新上下文重启 rollout，+15.3 至 57.4；作者认为本质是 Test-Time Scaling
  • 作者总结：复杂拓扑子图 + 实体/属性模糊、噪声注入、删关键节点边 + 信息分散度等监控指标，是当前最优配方
  • 评论区讨论：同 hop 数的子图比链式难得多、也难构造；单跳多约束问题同样难，不必执着多跳
