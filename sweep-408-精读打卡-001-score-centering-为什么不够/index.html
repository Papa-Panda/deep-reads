精读打卡 001：Score Centering 为什么不够

serein（2026-11-20）精读 arXiv:2609.20807《Score Centering Stabilizes Off-policy RL》：讲清异步 RL 里训推不一致如何产生 Drift（策略梯度被采样分布系统性带偏），Score Centering 怎样用公式消掉它、为什么仍不够（Reweighting Error 需 Importance Sampling 补），以及何时 SC 已足够（看 KL 距离、批量与陈旧度）。短而密的后训练 RL 实操精读，直接对上 Jun 的异步 RL 工作。

大纲

1. 背景：异步 RL 与训推不一致

  • 采样器（Sampler）做 rollout，训练器（Trainer）拿旧样本更新参数
  • 训练器不断更新导致采样数据陈旧（Staleness），加上推理量化与数值误差，两者分布不一致
  • 这种训练-推理不一致（TIM）会让训练越来越不稳定，甚至崩溃

2. 核心问题：Drift 是什么

  • 论文指出：在 TIM 下策略梯度会获得一个虚假而持久的更新方向，即 Drift
  • 两 token 例子：a、b 奖励同为 1，训练器认为各 0.5，采样器却以 0.8/0.2 生成
  • 奖励本不该改变偏好，但采样数据让训练器持续被推向 a——它在模仿采样器，而非从奖励中学习

3. 解法一：Score Centering

  • Score 定义为 sθ(y) = ∇θ log pθ(y)，即提升 token y 概率的梯度方向
  • 在训练器自身分布 p 下 E[s] = 0，但在采样分布 q 下 E_q[s] 可能非零
  • 中心化：s̃(y) = s(y) − E_q[s]，使 E_q[s̃] = 0，消掉那股平均推力
  • 数值验算：s(a)=+0.5、s(b)=−0.5 时，E_q=0.3；中心化后平均更新恰为 0

4. 为什么 SC 之后训练仍可能崩

  • SC 只修 Drift，不改变样本来自采样器这一事实，Reweighting Error 仍在
  • 若 a 的奖励高于 b，训练器本应提升 a，但数据中 a 占 80% 而非自身期望的 50%，每个 token 对梯度的贡献被错误加权

5. 解法二：Importance Sampling

  • 权重 w(y) = p(y)/q(y)：a 的权重为 0.5/0.8 = 0.625
  • 加权后 q(a)w(a) = 0.5 = p(a)，在期望上恢复训练器的目标分布

6. SC 何时够用：看 Distance

  • 另一关键词是距离：训练器与采样器的策略距离，用 KL 散度衡量
  • 距离一部分来自随机梯度噪声，一部分来自真实学习（训练器在旧数据上走得太远）

7. 实验对比与调参建议

  • 比较 SC、IS/TIS、KL 惩罚在不同批量、学习率、陈旧度下的表现
  • 批量大、数据新鲜时 SC 往往已足够；批量太小噪声大，陈旧度太高会走偏
  • 降学习率常不亚于再调一个 KL 惩罚系数；KL 惩罚太强则限制学习

流程图
