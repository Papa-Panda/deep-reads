训了一个kernel优化模型后的感想

RL Framework 团队的唐剑以有限经费只训一个模型 KODA（Qwen3.6-35B-A3B），专攻 Kernel 算子优化并支持 RLVR/PRM：SFT 拿了 70–80% 的正确率涨点、RL 抬高上限；多目标奖励必须让正确率做门控，否则 GRPO 下正确率先崩；复读源于数据太难致过渡 token 概率最高，RL 格式惩罚 + 课程学习可解。可直接借鉴的 RLVR 实战手记。

原文链接：https://zhuanlan.zhihu.com/p/2108235534212527828

大纲

1. 为什么训：框架团队要从真实训练拿认知

  • 作者在 RL Framework 团队：只有从真实训练中拿到认知，才能做好框架
  • 经费有限，只训一个模型；目标：Kernel 算子优化上很强，同时支持 RLVR 和 PRM 收益

2. KODA：基座与 Harness

  • 模型名 KODA，基座 Qwen3.6-35B-A3B，只在自家 Harness 上训练
  • 自研 Harness 已在 GitHub 开源，同名 KODA

3. 涨点来源：SFT 拿大头，RL 抬上限

  • SFT 贡献约 70–80% 的正确率涨点、50–60% 的效率（加速比）涨点
  • RL 份额较小，但大幅抬高了上限
  • 经验规则：SFT 超过 4 个 epoch 后，正确率还能涨，效率不再提升，还会伤害后续 RL

4. 多目标奖励设计是关键

  • 初始奖励：正确率只给 1 分，加速最高 10 分
  • GRPO 下正确但不加速的样本优势为负，加速主导奖励、正确率被牺牲：正确率先崩，加速随后也崩
  • 修正：正确率做门控（分值最大），再在正确的基础上算加速奖励

5. 泛化怎么来的：跨任务、跨 GPU

  • 参考 sol-execbench 的任务设计，在 H20 Sandbox 里训练，KernelBench 上仍表现好
  • sm100 系列 GPU 上评估，正确率与加速比与 H20 结果相近
  • 采样轨迹显示：给定 GPU 架构，模型用相似的优化思路，自主切换新指令集尝试

6. 复读问题：成因假说与解法

  • 复读在前沿通用模型也有，小模型更常见
  • 作者假说：训练数据太难，分叉点处各解 logprob 都很低，过渡 token（如 “wait, let me reconsider.”）概率最高而重复
  • 续 RFT、续 OPD 都效果差；起效的是 RL 格式惩罚 + 课程学习
  • RL 格式训练比做题有效得多，稍微调整就能解决

7. 结论：同尺寸 SOTA，已内部使用

  • 同尺寸达到 SOTA，接近前沿通用模型；已内部用于 Kernel 优化
  • Kernel 训练的工程难题多于 SWE 训练：GPU Sandbox、verify 设计、数据分布、训推效率
