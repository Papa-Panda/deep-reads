AI Infra 软核教程（一）为什么我们需要 AI Infra

锦恢为入行 Agentic RL 而写的 AI Infra 原理向开篇：从 2T 参数模型、FP16 权重 4TB、单卡 B200 仅 180GB 的显存账出发，论证 Infra 的价值不在 GPU 数量而在调度效率；系统梳理训练/推理/数据/集群/Agent 五大板块与 slime、dressage、verl 等 RL 训练框架及 Sandbox 等 Agent Infra 组件，并预告后续 DP/PP/SP/CP/EP 与推理中台章节。值得他看的是它把 Infra 还原为“让成百上千张卡像一台机器”的系统问题，且直接对准 Agentic RL 的 infra 需求；本篇偏原理、无代码与实测。

大纲

大纲（全文已通读）

  • 立论：Infra 的价值在调度效率，不在卡数与数据量
  • 主流模型约 2T 参数，FP16 权重约 4TB；单卡 B200 约 180GB，8 卡 DGX 仅 1.44TB，装不下
  • 训练还要约 8 倍模型体积的显存；分布是必然，Infra 的工作由此产生：通信、同步、一致性、调度
  • 目标：让成百上千张 GPU 像一台机器
  • 动因：作者时隔四年重回 Infra、开始做 Agentic RL；系列定位“软核”讲原理，不讲上手部署
  • AI Infra 的五大板块
  • 算力集群：GPU/TPU 节点、NCCL、Slurm/Ray 调度，及机架、组网拓扑、散热、供电、存储
  • 数据与存储：向量库、数据集/benchmark 管理、权重管理、Agent 数据回流
  • 训练：把单机 16 卡能跑的代码，在千卡、万卡集群上跑对、跑快、跑稳；Megatron-LM、DeepSpeed、ColossalAI
  • 推理：高可用、高并发部署，算子融合、自研 CUDA kernel、压低服务成本；vLLM、SGLang
  • Agent：Agent Infra（见下），多数公司尚未成为独立工种
  • 训练 Infra 的工程难点
  • 标准循环：数据、前向、loss、反向、更新参数；PyTorch autograd 与计算图
  • 每卡一个独立进程、内存隔离，跨进程通信不可避免
  • 集合通信 AllReduce vs 点对点 Send/Recv；NCCL（NVIDIA）与 HCCL（华为）
  • 每个进程只持有局部计算图，激活、梯度、参数状态要跨设备传递，显存占用随之上升
  • 核心解法是并行算法：2x2 切分示例（张量并行 + 流水线并行）；DP/PP/SP/CP/EP 留待后文
  • Python 表面之下是 C++、CUDA、NCCL 在跑矩阵运算与设备通信
  • 推理 Infra 的工程难点
  • 自回归生成：一次一个 token，单条查询无法并行；EOS 结束
  • 优化思路（以提问形式引入）：KV Cache（免算共享前缀）、Draft Model/推测解码（一次多猜再验证）、量化、算子融合
  • 工业难题：数百至数千并发下保持 GPU 利用率、按量计费不亏本；批量与调度的平衡留待推理中台章节
  • Agentic RL 与 Agent Infra
  • RL 训练框架：slime（智谱）、dressage（阿里）、verl（字节）；与 Megatron-LM、DeepSpeed 等传统训练后端区分
  • 多数开源 Agentic RL 框架复用现有推理框架作推理后端
  • Agent Infra 组件：高性能沙箱（阿里 OpenSandbox、腾讯 CubeSandbox）、在线 Agent 产品数据回流（字节 Coze）、Agent 框架（LangChain、AgentScope）、评测平台（LangSmith、LangFuse、Coze 罗盘）、公司内 MCP 发现服务
  • 为什么底层知识重要：DeepSeek 的例子
  • DeepSeek 不停留在 CUDA 抽象层；DeepEP 通信库用未公开的 PTX 指令提升 MoE 通信与推理效率
  • R1 在 2025 年初仍有约 30% 利润（作者说法），靠的是底层工程
  • 未回答的问题与后续路线图
  • 第 2 章：NCCL 原语与常见集群（NVIDIA、AWS）
  • 第 3–4 章：训练 Infra——PP、DP、SP、CP、EP
  • 第 5–6 章：推理——部署框架、Draft Model、量化、推理中台（作者坦言推理经验较浅）
  • 第 7 章起：Agent Infra——Sandbox 的技术壁垒、训练/推理/端侧 Sandbox 的差异
  • 悬而未决：单卡何时能到 1TB 显存（带宽、HBM 工艺、良率未知）；并发与利用率如何平衡
