推理 INFRA 方法论（2）：分布式推理：TP、DP、EP、CP 与 PP 的取舍

从权重、KV、激活与通信预算出发，推导分布式推理中 TP、DP、EP、CP、PP 各自的适用边界：GQA 与 MLA 在 TP 下为何不同、MoE 为何要按最差专家定容量、CP 只在长上下文时划算、PP 为何不适合在线解码。值得他看的是它把并行策略变成“先看哪个瓶颈先 binding”的系统设计问题，并给出可算的内存与气泡估算。

大纲

大纲

  • 选型总原则：先定瓶颈
  • 权重、KV、激活、通信四项预算，哪个先 binding 决定策略
  • Attention 与 MoE 的并行决策解耦
  • TP：张量并行
  • 单层权重与计算切分到多卡，通信频繁且细粒度，宜留在节点内
  • GQA：KV 可按 head 切分，TP 同时切 KV
  • MLA：KV 是共享隐向量无法切分，纯 TP 会复制 KV，宜用 TP 2–4 加 DP
  • DP：数据并行
  • 按请求切分，每卡自有 KV，不复制
  • 不减单卡权重，适合扩吞吐；完整态与分片态的转换要付 AllGather 代价
  • EP：专家并行
  • MoE 专家分卡存放，token 经 AllToAll 路由到激活专家
  • 容量按最差专家而非平均定，超容会丢 token 影响质量
  • 负载均衡损失不能消除不均匀，规模越大越要看分布
  • CP：上下文并行
  • 单条长序列的 KV 与注意力切分到多卡
  • 只有单卡装不下或 prefill 太慢时才划算；decode 主要看 KV 容量
  • PP：流水线并行
  • 层按阶段切分，微批次填不满时气泡是主成本
  • 在线解码基本不适用，离线批量与 prefill 才是主场
  • 结论：没有通用最优组合，只有按模型、上下文与 batch 定制的预算组合
