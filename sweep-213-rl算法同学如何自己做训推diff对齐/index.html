RL算法同学如何自己做训推diff对齐

知乎推荐流条目（haotian，编辑于 2026-10-20，35 赞、56 收藏；原文已通读）。作者把 RL 训推 diff 在 Qwen3.5-4B 的 GDN 层上做到了逐位为零：根因是训练侧 chunk 并行内核把 fp32 状态截断成 bf16、而 SGLang 递归 decode 全程 fp32，原生两路逐位一致仅约 38–41%。解法 ISO 是两遍计算——先并行算 64-token 边界的 fp32 状态、再在 chunk 内逐 token 递归——且训练与 rollout 三条路径共用同一套内核；纯 GRPO 实跑 146 步 diff 与 KL 全程为 0，代价是 decode 慢 5.5%、训练前向 +21%，且仅在 4B 单轮上验证、MoE 未做。对他是后训练正确性的一手实作：logprob 对齐可以不靠容差和重要性校正，而靠构造。

大纲

大纲（据原文通读整理，迟到深读已核实）

  • 条目信息
  • 作者 haotian（清华信通硕士），编辑于 2026-10-20 02:05；35 赞、56 收藏；方法源自 vLLM 的 train-inference-consistency skill（diff0），原契约只覆盖 Qwen3 dense，本文补上 GDN 混合线性注意力这块缺口
  • 问题：训推数值差把 on-policy 悄悄变 off-policy
  • rollout（SGLang）与训练（Megatron）对同一批 token 算出的 logprob 不一致；重要性采样/拒绝/校正类补丁只能部分缓解
  • 本文范围声明在前：仅 Qwen3.5-4B、单轮任务，MoE 未做，功能默认关、靠环境变量开启
  • 根因：GDN 层的精度截断
  • 训练侧 chunk 并行 FLA 内核在 64-token chunk 内用 fp32 算状态 h 与 v_new，写出时截断为 bf16；SGLang 递归 decode 全程 fp32
  • 层级实测：原生 decode 对标准训练 prefill，4096 token 逐位一致仅 40.94%（mean diff 5.5e-3），8192 token 仅 37.69%（7.4e-3），且逐层放大；训练侧不切换则对齐卡在约 6.5e-3
  • 方法 ISO：两遍计算、三路同构
  • 第一遍 chunk 并行算出每个 64-token 边界的 fp32 边界态；第二遍在 chunk 内从边界态出发逐 token 递归，全程 fp32
  • 训练 prefill、rollout prefill、rollout decode 共用同一套内核，残差是构造性为零而非容差内；对照 CPR（强行让 decode 走 chunk 内核）同为零但 decode 慢 2.13 倍，ISO 仅慢 1.055 倍
  • 验证：阈值就是逐位零
  • 三组两两 logprob 对比（decode↔prefill、prefill↔训练、decode↔训练）；TP1/TP2、CUDA graph 开关、4k–65,536 token 全部 100% 逐位一致（mean/max diff 均为 0）
  • 防假零：146 步训练 diff 恒为 0 的同时评测分数正常上升；定位靠逐层二分
  • 在线 RL 实跑（纯 GRPO，KL 系数 0）
  • Qwen3.5-4B-Base + dapo-math-17k，8 卡同机；146 步 train_rollout_logprob_abs_diff 与 KL 全程为 0；步时约 499 秒（rollout 170s 为大头）
  • 效果：原始 reward 0.664 → 0.75–0.86；训练内 AIME pass@1 由 step0 的 64.58% 升至 step99 的 71.25%；评测侧 ISO 与原生差异在噪声内
  • 代价与边界
  • decode 端到端 +5.5%；训练纯前向 +21%、前向+反向约 +6%（反向不变摊薄）；每请求槽约 +67MB；prefill 的 GDN 部分约慢 4 倍（长 prompt 多轮场景要留意）
  • 硬限制：不支持推测解码、必须关 radix cache、训练侧必须同步切换（SGLANG_GDN_ISO=1 / DIFF0_GDN_TWO_PASS=1，两侧须共用同一份 SGLang 代码）
