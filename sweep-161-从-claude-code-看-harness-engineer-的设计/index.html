从 Claude Code 看 Harness Engineer 的设计

知乎专栏（初级程序员，1880 赞同、3401 收藏，2026-04 编辑）。主张很明确：agent 的可靠性不该靠把 CLAUDE.md 写得更长——自然语言指令是概率性的，任务和上下文一长就衰减；可靠性要来自模型外面的结构。四个抓手：工具即契约（MCP 接口隐藏实现、干脆删掉危险操作、返回结果先过滤，不污染上下文）；隐性知识显性化（Skill 把团队约定写成版本化、按任务触发加载的文件，加载时还能注入实时状态）；把希望变成强制（Hook 在调用前拦截、声称完成时重跑测试驳回、压缩后重注入约束，安全检查用确定性代码）；受限即设计（Subagent 的价值在隔离——干净上下文、窄工具集、worktree）。对他正中靶心：这就是 harness engineering 的方法论版，与他把结构约束和可观测性用进自己 agent/训练工作的思路同构。注：全篇是概念论述，没有对照实验和失败率数据，对其他框架的类比是高层断言，搭建与维护成本基本没谈——当框架读，别当证据读。

大纲

大纲（据知乎原文结构整理）

  • 问题设定：规则越写越长，错误换个样子重来
  • 用 Claude Code 的人靠给 CLAUDE.md 补规则打补丁，同类错误仍以变体复发
  • 作者的定位：问题不只在 prompt 或模型，而在模型外面的 harness（运行系统）
  • 洞见一：用架构划定能力边界（MCP）
  • 工具接口是与外部世界的契约：隐藏实现细节，只暴露该暴露的动作
  • 最小权限：危险操作干脆不提供，而不是靠叮嘱模型别用
  • 返回结果先过滤，只给相关信息，避免原始输出污染上下文
  • 洞见二：隐性知识必须显性化（Skill）
  • 只活在人脑里的团队约定对 agent 不可见
  • Skill 把约定写成独立文件：版本可控、按任务触发、用到时才加载进上下文
  • 加载时可通过 shell 输出注入实时系统状态
  • 洞见三：把希望变成强制（Hook）
  • 生命周期钩子把口头要求变机械门禁：工具调用前拦截（PreToolUse）、编辑后检查（PostToolUse）、声称完成时把关（Stop）、上下文压缩后处理（PostCompact）
  • 声称完成时自动重跑测试，不过就驳回；压缩后自动重新注入关键约束（状态外置于上下文之外）
  • 安全攸关的检查用确定性代码（如退出码拦截），不再交给另一个 LLM 判断
  • 洞见四：受限即设计（Subagent）
  • 子代理的价值主要在隔离，不在并行
  • 独立干净的上下文加窄工具集（如只读 reviewer；文中以约 5 个工具对比约 50 个工具说明可预测性，属示意数字）
  • 高风险工作可放进独立 worktree 隔离
  • 解空间越小，行为越可预测
  • 四者合流：新增一个后端 API 端点的完整走查
  • 工具契约加任务 Skill 加编辑后 lint/format 钩子加完成时测试门禁加只读 reviewer
  • 用户不必在 prompt 里逐条重复规则，规则由系统结构保证执行
  • 不止 Claude Code
  • 工具使用不确定、领域知识缺失、不会自检、上下文有限，是 agent 框架的共性问题
  • 作者称 LangGraph、AutoGen、CrewAI、OpenAI Agents SDK 里都有对应组件（高层类比，未展开各框架语义差异）
  • 结尾
  • 换模型、写更长的指令文件都不解决可靠性；给 agent 搭工作系统才是可迁移的设计能力
